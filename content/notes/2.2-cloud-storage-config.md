## Why it matters

The bucket configuration sets availability, cost, retention, and exposure. Some settings are permanent: hierarchical namespace and a locked retention policy. The location changes only through bucket relocation. The exam asks which feature meets a requirement with the least effort. Typical pairs are Autoclass or lifecycle rules, soft delete or versioning, retention policies or holds, and signed URLs or public access.

## Key points

- Dual-region and multi-region buckets fail over automatically when a region fails, with an RTO of zero. Replication across regions is asynchronous ([Bucket locations](https://docs.cloud.google.com/storage/docs/locations)).
- Turbo replication targets an RPO of 15 minutes for all new objects. It works only for dual-region buckets ([Data availability and durability](https://docs.cloud.google.com/storage/docs/availability-durability)).
- Nearline, Coldline, and Archive have minimum storage durations of 30, 90, and 365 days, and retrieval fees ([Storage classes](https://docs.cloud.google.com/storage/docs/storage-classes)).
- Autoclass fits data with varied or unknown access patterns. It is not recommended when most data fits known storage classes ([Autoclass](https://docs.cloud.google.com/storage/docs/autoclass)).
- Soft delete is on by default with a 7-day retention duration. Google recommends soft delete instead of Object Versioning to protect against accidental or malicious deletion ([Soft delete overview](https://docs.cloud.google.com/storage/docs/soft-delete), [Object Versioning](https://docs.cloud.google.com/storage/docs/object-versioning)).
- A locked retention policy cannot be removed or reduced. Locking is irreversible ([Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock)).
- Uniform bucket-level access disables ACLs, so only IAM grants access. You cannot disable it after 90 consecutive days ([Uniform bucket-level access](https://docs.cloud.google.com/storage/docs/uniform-bucket-level-access)).
- Public access prevention blocks `allUsers` and `allAuthenticatedUsers`. It does not block signed URLs ([Public access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention)).
- A CMEK key ring must be in the same location as the bucket ([Customer-managed encryption keys](https://docs.cloud.google.com/storage/docs/encryption/customer-managed-keys)).
- Below about 1,000 writes or 5,000 reads per second, no ramp-up is needed. Above that, at most double the request rate every 20 minutes ([Request rate and access distribution guidelines](https://docs.cloud.google.com/storage/docs/request-rate)).

## Location and replication

You set the location when you create the bucket.

| Location type | Redundancy | Outage behavior | Cost | Fits |
|---|---|---|---|---|
| Zone (Rapid Bucket) | One zone | A zone outage can affect availability | Highest storage price of all location types | AI, ML, HPC |
| Region | Across zones, synchronous | Automatic failover for a zone failure | Lowest storage price; no replication charges | Analytics, backup, and archive |
| Dual-region | Two regions, asynchronous; optional turbo replication | Automatic failover for a region failure | Higher storage price than multi-region; replication charges on write | Disaster recovery, analytics |
| Multi-region | Several regions, asynchronous | Automatic failover for a region failure | Replication charges on write; outbound charges on reads | Content serving |

Sources: [Bucket locations](https://docs.cloud.google.com/storage/docs/locations).

- **Default replication** copies 99.9% of new objects to the second region within one hour, and 100% within 12 hours ([Data availability and durability](https://docs.cloud.google.com/storage/docs/availability-durability)).
- **Turbo replication** is a premium feature. Enable it when you need a short and predictable RPO ([Bucket locations](https://docs.cloud.google.com/storage/docs/locations)).
- **Short-lived data** belongs in regions, to avoid replication charges ([Bucket locations](https://docs.cloud.google.com/storage/docs/locations)).
- **Dual-region names.** A predefined dual-region has its own code. For example, `NAM4` is `US-CENTRAL1` plus `US-EAST1` ([Bucket locations](https://docs.cloud.google.com/storage/docs/locations)).
- **Cross-bucket replication** copies new and updated objects to an independent bucket with its own location, encryption, and class. It uses Storage Transfer Service and Pub/Sub. It has no RPO, it does not replicate deletions, and it does not support hierarchical namespace or zonal buckets ([Data availability and durability](https://docs.cloud.google.com/storage/docs/availability-durability)).
- **Bucket relocation** moves a bucket to another location with the same name. Reads have no downtime and writes have minimal downtime. It needs Storage Intelligence ([Bucket relocation](https://docs.cloud.google.com/storage/docs/bucket-relocation/overview)).

Cloud Storage gives strong global consistency for object read-after-write and for listing, also in dual-regions and multi-regions. Grants and revocations of access are eventually consistent and typically take about a minute ([Cloud Storage consistency](https://docs.cloud.google.com/storage/docs/consistency)).

## Storage classes

| Class | Minimum storage duration | Retrieval fee | Typical monthly availability |
|---|---|---|---|
| Standard | None | None | 99.99% in regions; above 99.99% in dual-regions and multi-regions |
| Nearline | 30 days | Yes | 99.9% in regions; 99.95% in dual-regions and multi-regions |
| Coldline | 90 days | Yes | Same as Nearline |
| Archive | 365 days | Yes | Same as Nearline |
| Rapid | None | None | Above 99.95% in zones; zonal buckets only |

Sources: [Storage classes](https://docs.cloud.google.com/storage/docs/storage-classes).

- Archive data is available within milliseconds, not hours or days ([Storage classes](https://docs.cloud.google.com/storage/docs/storage-classes)).
- A new bucket uses Standard unless you set another default. A change of the bucket default class does not change existing objects ([Storage classes](https://docs.cloud.google.com/storage/docs/storage-classes)).
- If you delete, replace, or move an object before its minimum duration, you pay as if it stayed for the full duration. A rewrite to change the class also causes early deletion charges. A lifecycle class change and Autoclass do not ([Storage pricing](https://cloud.google.com/storage/pricing)).

## Autoclass or lifecycle rules

| Criterion | Autoclass | Object Lifecycle Management |
|---|---|---|
| Use it when | Access frequency varies or is unknown | You know the pattern by age, prefix, or version |
| Class changes | Colder after 30, 90, and 365 days without access; back to Standard when read | Colder only, with `SetStorageClass` |
| Other actions | None | `Delete`, and `AbortIncompleteMultipartUpload` |
| Fees | Management fee and enablement charge; no retrieval or early deletion fees | A Class A operation for each class change; no retrieval or early deletion fee for the change |
| Small objects | Objects under 128 KiB stay in Standard | Use `sizeAboveBytes` so the operation cost does not exceed the savings |
| Limits | Default terminal class is Nearline; you can set Archive. Not recommended if other services read the bucket regularly | Configuration changes take up to 24 hours; actions run asynchronously |

Sources: [Autoclass](https://docs.cloud.google.com/storage/docs/autoclass), [Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle).

- A bucket cannot have Autoclass together with a lifecycle `SetStorageClass` rule ([Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle)).
- `Delete` takes precedence over `SetStorageClass`. `Delete` waits until holds are released and retention is met ([Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle)).
- With `SetStorageClass`, the time in the old class counts toward the minimum duration of the new class ([Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle)).
- Useful conditions include `age`, `matchesPrefix`, `isLive`, `numNewerVersions`, and `daysSinceNoncurrentTime`. The last two limit noncurrent versions ([Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle)).

## Protect objects: soft delete, versioning, retention, and holds

| Feature | Protects against | Behavior to know |
|---|---|---|
| Soft delete | Accidental or malicious deletion or overwrite of objects and buckets | On by default; 7 to 90 days, or 0 to disable. Soft-deleted objects cannot be read, and they keep storage charges. A restore writes a new live copy in Standard. |
| Object Versioning | Overwrites when you must keep older versions | Keeps noncurrent versions until you remove them. It does not protect against bucket deletion. |
| Retention policy (Bucket Lock) | Deletion or replacement before a set age | Applies to existing and new objects. An unlocked policy can change. A locked policy can only increase, and the project gets a lien. |
| Object Retention Lock | Deletion before a per-object retain-until time | `Unlocked` or `Locked` mode. After you enable it on a bucket, you cannot disable it. |
| Event-based hold | Deletion until an event, then a retention period | In a bucket with a retention policy, release resets the object's retention clock. |
| Temporary hold | Deletion during an investigation | Release does not change the retention period. |

Sources: [Soft delete overview](https://docs.cloud.google.com/storage/docs/soft-delete), [Object Versioning](https://docs.cloud.google.com/storage/docs/object-versioning), [Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock), [Object Retention Lock](https://docs.cloud.google.com/storage/docs/object-lock), [Object holds](https://docs.cloud.google.com/storage/docs/object-holds).

- For buckets of short-lived temporary data, Google recommends buckets without soft delete, because soft delete can increase storage costs a lot ([Soft delete overview](https://docs.cloud.google.com/storage/docs/soft-delete)).
- If you restore a soft-deleted bucket with the gcloud CLI, you get the empty bucket. You restore its objects in a separate operation ([Soft delete overview](https://docs.cloud.google.com/storage/docs/soft-delete)).
- Bucket Lock with Detailed audit logging mode can help with FINRA, SEC, and CFTC requirements. The maximum retention period is 100 years ([Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock)).
- You cannot delete a bucket with a locked policy until every object meets the retention period ([Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock)).

Recovery times for each mechanism are on the [Data protection](note:2.2-data-protection) page. Compliance design is on the [Designing for compliance](note:3.2-compliance) page.

## Access control and encryption

- **Uniform bucket-level access (UBLA).** Google generally recommends it. It is required for hierarchical namespace, managed folders, and IAM conditions on the bucket ([Uniform bucket-level access](https://docs.cloud.google.com/storage/docs/uniform-bucket-level-access)).
- **Public access prevention (PAP).** Set it on the bucket, or enforce it with the organization policy constraint `storage.publicAccessPrevention`. Requests authorized by `allUsers` or `allAuthenticatedUsers` then fail with `401` or `403` ([Public access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention)).
- **Signed URLs.** They give time-limited access to one resource. Anyone with the URL can use it, with or without an account. The longest expiration is 7 days. In most cases, a service account signs the URL ([Signed URLs](https://docs.cloud.google.com/storage/docs/access-control/signed-urls)). The `gcloud storage sign-url` command can impersonate the service account, so you need no key file. The caller needs the Service Account Token Creator role ([V4 signing process with Cloud Storage tools](https://docs.cloud.google.com/storage/docs/access-control/signing-urls-with-helpers)).
- **CMEK.** For a configurable dual-region, the key ring uses the location code, for example `US`. For the predefined dual-region `NAM4`, the key ring must be in `NAM4`. Cloud KMS Autokey can create key rings and keys on demand ([Customer-managed encryption keys](https://docs.cloud.google.com/storage/docs/encryption/customer-managed-keys)). Key design is on the [Encryption, Cloud KMS, and secrets](note:3.1-data-protection-kms) page.

## Performance, transfer, and growth

Cloud Storage has no capacity limit ([Design an optimal storage strategy for your cloud workload](https://docs.cloud.google.com/architecture/storage-advisor)). Growth planning is about request rates, object names, and cost.

- **Object names.** Sequential names, such as timestamps, slow down auto-scaling. Add a hash prefix, for example the first 6 characters of an MD5 hash of the name ([Request rate and access distribution guidelines](https://docs.cloud.google.com/storage/docs/request-rate)).
- **Hierarchical namespace (HNS).** It adds folders and atomic folder operations for AI, ML, and analytics. HNS buckets have up to 8 times higher initial QPS. You enable HNS only when you create the bucket ([Hierarchical namespace](https://docs.cloud.google.com/storage/docs/hns-overview)).
- **Parallel composite uploads.** A file is split into up to 32 chunks that upload in parallel. The final object has a crc32c hash but no MD5 hash ([Parallel composite uploads](https://docs.cloud.google.com/storage/docs/parallel-composite-uploads)). Do not use them with a retention policy, because the temporary parts cannot be deleted before they meet it ([Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock)).
- **Rapid Cache.** For a multi-region workload with strict performance needs, enable Rapid Cache (formerly Anywhere Cache) ([Bucket locations](https://docs.cloud.google.com/storage/docs/locations)).
- **Storage Transfer Service.** It is optimized for transfers of more than 1 TiB ([Storage Transfer Service](https://docs.cloud.google.com/storage-transfer/docs/overview)). Transfer options are on the [Migration tooling](note:5.1-migration-tooling) page.

## AWS mapping

| AWS | Google Cloud | Difference that matters |
|---|---|---|
| S3 Intelligent-Tiering | Autoclass | Read access moves an object back to Standard. There are no retrieval or early deletion fees. |
| S3 Lifecycle | Object Lifecycle Management | `SetStorageClass` moves objects only to colder classes. |
| S3 Object Lock | Bucket Lock and Object Retention Lock | A locked bucket policy is irreversible and adds a project lien. |
| S3 Versioning | Object Versioning and soft delete | Google recommends soft delete for deletion protection. Soft delete also protects buckets. |
| S3 Block Public Access | Public access prevention | An organization policy constraint can enforce it. |
| S3 presigned URLs | Signed URLs | The maximum expiration is 7 days. |
| S3 Cross-Region Replication | Dual-region bucket, or cross-bucket replication | A dual-region is one bucket with automatic failover. Turbo replication targets a 15-minute RPO. |
| S3 Glacier Deep Archive | Archive storage class | Data is available within milliseconds. |

Sources: [Autoclass](https://docs.cloud.google.com/storage/docs/autoclass), [Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle), [Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock), [Object Versioning](https://docs.cloud.google.com/storage/docs/object-versioning), [Public access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention), [Signed URLs](https://docs.cloud.google.com/storage/docs/access-control/signed-urls), [Data availability and durability](https://docs.cloud.google.com/storage/docs/availability-durability), [Storage classes](https://docs.cloud.google.com/storage/docs/storage-classes).

## Exam traps

- **A lifecycle rule that moves data back to Standard when users read it.** `SetStorageClass` only moves objects to colder classes. Autoclass moves read objects back to Standard ([Object Lifecycle Management](https://docs.cloud.google.com/storage/docs/lifecycle), [Autoclass](https://docs.cloud.google.com/storage/docs/autoclass)).
- **Autoclass on a bucket that Sensitive Data Protection scans regularly.** Regular reads by other services make Autoclass a poor fit ([Autoclass](https://docs.cloud.google.com/storage/docs/autoclass)).
- **Object Versioning to recover from a deleted bucket.** Only soft delete can recover objects from a deleted bucket ([Object Versioning](https://docs.cloud.google.com/storage/docs/object-versioning)).
- **Lock the retention policy while you test it.** Locking is irreversible. Test with an unlocked policy ([Bucket Lock](https://docs.cloud.google.com/storage/docs/bucket-lock)).
- **Turbo replication on a multi-region bucket.** It works only for dual-regions ([Data availability and durability](https://docs.cloud.google.com/storage/docs/availability-durability)).
- **Cross-bucket replication for a guaranteed RPO.** It offers no RPO and does not replicate deletions ([Data availability and durability](https://docs.cloud.google.com/storage/docs/availability-durability)).
- **Public objects so that customers without Google accounts can download a file.** Use a signed URL. Public access prevention does not block signed URLs ([Public access prevention](https://docs.cloud.google.com/storage/docs/public-access-prevention), [Signed URLs](https://docs.cloud.google.com/storage/docs/access-control/signed-urls)).
- **A change of the bucket default class to move old objects.** Existing objects keep their class ([Storage classes](https://docs.cloud.google.com/storage/docs/storage-classes)).
- **Timestamp object names at a high request rate.** Add a hash prefix ([Request rate and access distribution guidelines](https://docs.cloud.google.com/storage/docs/request-rate)).
