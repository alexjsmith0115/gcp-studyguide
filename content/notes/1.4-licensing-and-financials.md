## Why it matters

Licenses can decide the target platform, the tenancy, and sometimes whether a workload can move at all. The exam gives a license fact, such as "Windows Server 2019 licenses without Software Assurance", and asks for the compliant and cost-effective design. It also tests what belongs in a migration TCO: rightsizing, commitments, network costs, and the cost of running two environments.

## Key points

- Premium images include an on-demand license for RHEL, SLES, Ubuntu Pro, Windows Server, and SQL Server. Their charges are in addition to the machine type charges ([Disk and image pricing](https://cloud.google.com/compute/disks-image-pricing)).
- With your own license (BYOL), you pay Google only for the infrastructure that you use ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing)).
- Licenses with dedicated hardware requirements, per physical core or per processor, need your own media and hardware such as sole-tenant nodes ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses)).
- License Mobility covers server applications such as SQL Server and SharePoint Server ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing)). It does not cover Windows Server ([Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)).
- BYOL for Windows Server needs a version released before October 1, 2019, and sole-tenant nodes ([Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)).
- Linux BYOS for RHEL or SLES does not need sole-tenant nodes ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses)).
- For most Oracle deployments, Google positions Oracle Database@Google Cloud as more integrated than Bare Metal Solution ([Oracle partnership offerings](https://docs.cloud.google.com/bare-metal/docs/explore-oracle-partnership-offerings)).
- Migration Center TCO reports compare preference sets for tenancy, OS license type, pricing track, and sizing strategy ([Migration preferences for servers](https://docs.cloud.google.com/migration-center/docs/server-preferences)).
- Network use is a commonly overlooked cost in cloud migrations ([Assess and discover](https://docs.cloud.google.com/architecture/migration-to-gcp-assessing-and-discovering-your-workloads)).
- Define criteria to retire the source environment, so that you do not pay for two environments indefinitely ([Validating a migration plan](https://docs.cloud.google.com/architecture/migration-to-google-cloud-best-practices)).

## License models on Compute Engine

Google gives two license models. On-demand licenses come with prebuilt premium images, and you pay an hourly fee with the compute cost. With BYOL, you bring licenses that you already own and you stay responsible for compliance ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing)).

| Software | On-demand license from Google | Bring your own license | Tenancy for BYOL |
|---|---|---|---|
| Windows Server | Premium image, or attach an on-demand license during image import. User CALs are included. | Only through Outsourcing Software Management Rights: version released before October 1, 2019, and license acquired under an enrollment effective before that date. | Sole-tenant nodes |
| SQL Server | Premium image. One core license per vCPU, with a minimum of four. | License Mobility through Software Assurance. | Multi-tenant is allowed with License Mobility on an on-demand Windows Server image. |
| RHEL | Premium image | BYOS, through Red Hat Cloud Access | Sole-tenant nodes not required |
| SLES | Premium image | BYOS | Sole-tenant nodes not required |

Sources: [Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq), [Operating system details](https://docs.cloud.google.com/compute/docs/images/os-details), [Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses).

On-demand licenses are simple. Google handles the license reporting and compliance, and you need no upfront purchase ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing), [Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)). BYOL can cost less for long-term, stable workloads with active Software Assurance. If the licenses require sole-tenant nodes, add that cost to the comparison ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing)).

## Microsoft licensing in detail

Microsoft BYOL on Google Cloud has two paths ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing)):

| Path | Covers | Conditions |
|---|---|---|
| Software Assurance with License Mobility | Server applications, such as SQL Server and SharePoint Server | Active Software Assurance with License Mobility, and CALs with Software Assurance. After you deploy a license in a region, you cannot move it to another region for 90 days. |
| Outsourcing Software Management Rights | Products not covered by License Mobility, such as Windows Server 2019 | Product released before October 1, 2019, and license acquired under an enrollment effective before that date. Dedicated hardware, such as sole-tenant nodes. |

Source: [Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing).

The Windows Server license decides the tenancy for SQL Server:

| Windows Server license | SQL Server license | Tenancy |
|---|---|---|
| On-demand | On-demand, or BYOL with License Mobility | Multi-tenant or sole-tenant. No version limits. |
| On-demand | BYOL without License Mobility | Sole-tenant nodes. SQL Server 2017 or earlier. |
| BYOL | Any | Sole-tenant nodes. Windows Server 2019 or earlier. SQL Server 2017 or earlier without License Mobility. |

Source: [Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq).

Two cost facts follow from per-vCPU licensing:

- Google charges on-demand Windows Server and SQL Server licenses for each vCPU. If you disable simultaneous multithreading (SMT) or disable cores, you pay for fewer licenses. SQL Server always charges at least four core licenses ([Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)).
- By default, Compute Engine runs two vCPUs on each physical core. Migration Center can model SMT as enabled, disabled, or disabled with compensation, to balance license cost and performance ([Migration preferences for servers](https://docs.cloud.google.com/migration-center/docs/server-preferences)).

If you upgrade a BYOL Windows Server to a version released after October 1, 2019, the new license might not be eligible for BYOL ([Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)).

### Microsoft licenses on VMware Engine

Google Cloud VMware Engine has its own rules. Windows Server VMs in a private cloud are not licensed by default. You can bring Windows Server licenses bought before October 1, 2019, but then you must license all physical cores of the nodes. You can also buy on-demand licenses from Google. Google recommends one licensing option per private cloud ([VMware Engine: Microsoft licensing](https://docs.cloud.google.com/vmware-engine/docs/vmware-ecosystem/microsoft-licensing)).

For the VMware software itself, Migration Center models two VMware Engine service types. "Fully licensed" sells the VMware Cloud Foundation software as a service. "Portable License" lets you use VMware Cloud Foundation subscriptions that you buy from Broadcom ([Migration preferences for servers](https://docs.cloud.google.com/migration-center/docs/server-preferences)).

## Sole-tenant nodes for BYOL

Sole-tenant nodes are physical servers that host VMs for only your project ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses)). They help with BYOL licenses per core or per processor. Compute Engine reports the physical server ID of each VM, and Cloud Logging keeps the history for license reports ([Sole-tenancy overview](https://docs.cloud.google.com/compute/docs/nodes/sole-tenant-nodes)).

The host maintenance policy controls how many physical servers your VMs use:

| Policy | Behavior during host events | Use it for |
|---|---|---|
| Default | VMs live migrate to any new sole-tenant node. | Per-user or per-device licenses, and workloads without license needs |
| Restart in place | VMs stop and restart on the same physical server. | Fault-tolerant workloads that accept about one hour of downtime, with per-core or per-processor licenses |
| Migrate within node group | VMs live migrate within a fixed group of physical servers. Google reserves 1 holdback node for every 20 nodes. | Highly available workloads with per-core or per-processor licenses |

Source: [Sole-tenancy overview](https://docs.cloud.google.com/compute/docs/nodes/sole-tenant-nodes).

More BYOL rules:

- You must bring your own media. Images based on a premium image are not eligible for BYOL ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses)).
- You import the virtual disk (VMDK or VHD) and choose your own license key during the import ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses)).
- CPU overcommit is available on N1, N2, N2D, and N4 sole-tenant nodes ([Sole-tenancy overview](https://docs.cloud.google.com/compute/docs/nodes/sole-tenant-nodes)).
- You might be able to classify sole-tenant node costs as capital expenditure ([Cost optimization pillar](https://docs.cloud.google.com/architecture/framework/cost-optimization)).

## Linux subscriptions

RHEL and SLES images are premium images with extra fees. To use an existing RHEL subscription, use the Red Hat Cloud Access feature ([Operating system details](https://docs.cloud.google.com/compute/docs/images/os-details)). The price of a premium image depends on the machine type. Spot VMs do not reduce premium image costs ([Disk and image pricing](https://cloud.google.com/compute/disks-image-pricing)). You can buy a 1-year commitment for RHEL images, which costs less than the on-demand image price ([Disk and image pricing](https://cloud.google.com/compute/disks-image-pricing)).

Many Linux images have no license fee, for example Debian, Rocky Linux, and AlmaLinux ([Operating system details](https://docs.cloud.google.com/compute/docs/images/os-details)).

## Oracle

| | Oracle Database@Google Cloud | Bare Metal Solution |
|---|---|---|
| What it is | Oracle Cloud Infrastructure (OCI) database services, such as Exadata Database Service and Autonomous AI Database, on OCI Exadata hardware in Google Cloud data centers | Dedicated bare-metal servers in regional extensions, with a managed low-latency connection to Google Cloud |
| License | License included (bought with the Cloud Marketplace order) or BYOL | BYOL |
| Your tasks | You link an OCI account. Google Cloud provides the infrastructure, network, security, and hardware monitoring. | You manage the OS, the database, patches, backups, and licenses. |
| Billing | Cloud Marketplace: public pay-as-you-go offer or a negotiated private offer, on the Google Cloud invoice | Google Cloud billing for the servers |
| Google's positioning | More integrated for most Oracle deployments | Third-party virtualization software and applications that need low-level server access |

Sources: [Oracle Database@Google Cloud overview](https://docs.cloud.google.com/oracle/database/docs/overview), [Create Exadata VM Cluster](https://docs.cloud.google.com/oracle/database/docs/create-clusters), [Purchase and billing](https://docs.cloud.google.com/oracle/database/docs/purchase-and-billing), [Bare Metal Solution overview](https://docs.cloud.google.com/bare-metal/docs/bms-overview), [Oracle partnership offerings](https://docs.cloud.google.com/bare-metal/docs/explore-oracle-partnership-offerings).

## Financial modeling

A migration TCO compares the full cost of the source environment with the cost on Google Cloud. Include these items:

| Area | Items to include |
|---|---|
| Source environment | Hardware and software, plus data center costs such as power, cooling, and maintenance. |
| Target environment | Compute, storage, licenses, and network use. Egress and cross-region traffic are charged. Ingress is free for most services. |
| Migration project | Egress from another cloud provider, extra bandwidth, a Transfer Appliance, and staff time. |
| Transition | Both environments run in parallel until the retirement criteria are met. |
| Savings levers | Rightsizing during the migration, autoscaling, and committed use discounts. |

Sources: [Assess and discover](https://docs.cloud.google.com/architecture/migration-to-gcp-assessing-and-discovering-your-workloads), [Build your foundation](https://docs.cloud.google.com/architecture/migration-to-google-cloud-building-your-foundation), [Transfer your large datasets](https://docs.cloud.google.com/architecture/migration-to-google-cloud-transferring-your-large-datasets), [Validating a migration plan](https://docs.cloud.google.com/architecture/migration-to-google-cloud-best-practices), [Minimize costs](https://docs.cloud.google.com/architecture/migration-to-google-cloud-minimize-costs).

The cost model also changes type. On premises, network hardware is a fixed, upfront capital expense. In the cloud, you are billed for data transfer ([Build your foundation](https://docs.cloud.google.com/architecture/migration-to-google-cloud-building-your-foundation)). CapEx, OpEx, and discount details are in [Cost optimization](note:4.2-cost-optimization).

### Migration Center preferences that change the TCO

| Preference | Options |
|---|---|
| Tenancy | Multi-tenant supports only pay-as-you-go Windows Server licenses. Sole-tenant supports BYOL and pay-as-you-go. |
| OS license | Windows Server, RHEL, and SLES: BYOL or pay-as-you-go. BYOL removes the license charge from the report. |
| Pricing track | On demand, 1-year or 3-year resource-based CUD, or 1-year or 3-year flexible CUD. "No preference" means a 3-year resource-based CUD. |
| Sizing strategy | No rightsizing, moderate (the default), aggressive, or custom. |
| Data transfer out | The percentage of traffic that leaves Google Cloud. The default is 5%. |

Source: [Migration preferences for servers](https://docs.cloud.google.com/migration-center/docs/server-preferences).

Create several preference sets and compare them in one TCO report ([Create and manage migration preferences](https://docs.cloud.google.com/migration-center/docs/migration-preferences)). The TCO report exports to Google Slides for executives. The detailed pricing report exports to Google Sheets, CSV, or Excel with the cost of each asset ([Generate TCO reports](https://docs.cloud.google.com/migration-center/docs/generate-tco-report)). For software that needs a Microsoft license, Migration Center also generates a license report ([Available reports](https://docs.cloud.google.com/migration-center/docs/migration-center-reports)).

Google also runs the Rapid Migration and Modernization Program (RaMP). It offers a migration methodology, partner funding, and migration incentives ([RaMP](https://cloud.google.com/solutions/cloud-migration-program)).

## Exam traps

- **License Mobility for Windows Server.** License Mobility covers server applications, not the operating system ([Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)).
- **Windows Server 2022 BYOL.** Versions released after October 1, 2019 are not eligible. Use on-demand Windows Server licenses ([Microsoft licensing on Google Cloud](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing)).
- **Sole-tenant nodes for every BYOL case.** RHEL or SLES BYOS does not need them. SQL Server with License Mobility on an on-demand Windows image does not need them either ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses), [Microsoft licensing FAQ](https://docs.cloud.google.com/compute/docs/instances/windows/ms-licensing-faq)).
- **BYOL on a Google premium image.** Images based on premium images already carry a pay-as-you-go license. Import your own media ([Bringing your own licenses](https://docs.cloud.google.com/compute/docs/nodes/bringing-your-own-licenses)).
- **The default host maintenance policy for per-core licenses.** It lets VMs move to any server. Use restart in place or migrate within node group ([Sole-tenancy overview](https://docs.cloud.google.com/compute/docs/nodes/sole-tenant-nodes)).
- **Spot VMs to cut Windows license costs.** Spot VMs do not reduce premium image charges ([Disk and image pricing](https://cloud.google.com/compute/disks-image-pricing)).
- **A TCO with only hardware and licenses.** Include network use, data transfer, and the dual-running period ([Assess and discover](https://docs.cloud.google.com/architecture/migration-to-gcp-assessing-and-discovering-your-workloads), [Validating a migration plan](https://docs.cloud.google.com/architecture/migration-to-google-cloud-best-practices)).
- **Reading the default TCO as on-demand cost.** "No preference" for the pricing track means a 3-year resource-based CUD ([Migration preferences for servers](https://docs.cloud.google.com/migration-center/docs/server-preferences)).
