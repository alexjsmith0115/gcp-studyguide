## Why it matters

A model in a notebook is not a production system. The architect designs how data reaches training and how training repeats. The architect also designs how models are versioned and served, and how the system detects a weaker model. The exam tests the managed Agent Platform (formerly Vertex AI) tool for each stage. It also tests trade-offs, such as Agent Platform Pipelines compared with Managed Service for Apache Airflow (formerly Cloud Composer), and online compared with batch inference.

## Key points

- Agent Platform Pipelines (formerly Vertex AI Pipelines) runs ML workflows in a serverless manner. You do not manage a cluster ([Introduction to Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/introduction)).
- Use the Kubeflow Pipelines (KFP) SDK for most pipelines. Use TFX only when you process terabytes of structured or text data with TensorFlow Extended ([Interfaces for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/interfaces)).
- Each pipeline run stores its parameters and artifact metadata in ML Metadata. This gives you lineage for audits and debugging ([Introduction to Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/introduction), [MLOps on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/start/introduction-mlops)).
- Pipelines has no gcloud commands. Use the console, the SDK, or the REST API ([Interfaces for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/interfaces)).
- Run pipelines as a dedicated service account with granular permissions. Without one, runs use the Compute Engine default service account ([Configure your project for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-project)).
- Store structured data in BigQuery. Store images, video, and audio in Cloud Storage in large sharded files ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)).
- In the current Feature Store, your BigQuery tables form the offline store. Bigtable online serving is the online serving type that is not deprecated ([About Feature Store](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/featurestore/latest/overview), [Online serving types](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/featurestore/latest/online-serving-types)).
- Serverless training provisions compute for a job and releases it after. Training clusters reserve dedicated accelerators and use Slurm ([Choose a training method](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/start/training-methods), [Gemini Enterprise Agent Platform training clusters overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/training-clusters/overview)).
- Use online inference when an application waits for the answer. Use batch inference for accumulated data that needs no immediate response ([Overview of getting inferences](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions)).
- Dedicated public endpoints are the recommended public endpoint. Private Service Connect endpoints are recommended for private production traffic ([Choose an endpoint type](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/choose-endpoint-type)).
- Model Monitoring detects training-serving skew and inference drift for tabular models ([Introduction to Model Monitoring](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-monitoring/overview)).
- A Cloud Run function (formerly Cloud Functions) can start a pipeline run or a training job when an event arrives. Examples are a Pub/Sub message or a new file ([Trigger a pipeline run with Pub/Sub](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/trigger-pubsub), [Generative AI security best practices](https://docs.cloud.google.com/docs/security/genai-security-bps)).

## The MLOps lifecycle on Agent Platform

Each MLOps need has a managed tool. The tools are modular, so you can add them to an existing system one at a time ([MLOps on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/start/introduction-mlops)).

| Need | Google Cloud tool |
|---|---|
| Orchestrate and repeat workflows | Agent Platform Pipelines |
| Run training | Serverless training, or training clusters for reserved capacity |
| Track parameters, artifacts, and metrics | ML Metadata, Experiments, and TensorBoard |
| Version models and deploy them | Model Registry |
| Share and serve features | Feature Store |
| Watch model quality in production | Model Monitoring |
| Scale Python and AI code | Ray on Agent Platform |
| Build, test, and deploy ML code (CI/CD) | Cloud Build |

Sources: [MLOps on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/start/introduction-mlops), [AI and ML perspective: Operational excellence](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/operational-excellence).

Google's MLOps guide defines three maturity levels. Use them to describe a company's current state and its next step.

| Level | What is automated | What you deploy |
|---|---|---|
| 0: Manual | Nothing. Every step is manual and script-driven. | A trained model |
| 1: ML pipeline automation | The training pipeline, so the model retrains itself (continuous training). The pipeline validates data and models. | The whole training pipeline |
| 2: CI/CD pipeline automation | Also the build, test, and deployment of the pipeline code | The pipeline, through CI/CD |

Source: [MLOps: Continuous delivery and automation pipelines in machine learning](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning).

Continuous training needs a trigger. The guide lists five triggers. One is a manual run on demand. The other four are a schedule, the arrival of new training data, a drop in model performance, and a significant change in the data distribution ([MLOps: Continuous delivery and automation pipelines in machine learning](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning)).

## Agent Platform Pipelines

A pipeline is a graph of steps. Each step is a component that runs in a container. Use the predefined Google Cloud Pipeline Components to call Agent Platform features such as AutoML. A step can also hand its work to BigQuery, Dataflow, or Managed Service for Apache Spark (formerly Dataproc) ([Introduction to Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/introduction)).

### Choose the orchestrator

| Option | Use it when | Do not use it when |
|---|---|---|
| Agent Platform Pipelines | The workflow is container-based and runs inside the Agent Platform ecosystem. You want no cluster to operate. | The flow spans many unrelated systems. |
| Managed Service for Apache Airflow (formerly Cloud Composer) | The flow spans heterogeneous systems: ELT, training, and external business tools. It integrates BigQuery, Dataflow, Agent Platform, and third-party tools. | The workflow is container-based and stays inside Agent Platform. |
| Self-managed Kubeflow on GKE | You need full control, or you run Kubeflow on-premises too. | You do not want to operate Kubernetes. |

Sources: [Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices), [What is Kubeflow?](https://cloud.google.com/discover/what-is-kubeflow), [Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/docs/deprecations).

Legacy AI Platform Pipelines is shut down. Its migration path is Agent Platform Pipelines ([Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/docs/deprecations)).

### Features that the exam tests

- **Execution caching.** If ML Metadata has a matching execution, the step reuses its outputs and is skipped ([Configure execution caching](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-caching)). Caching is on unless you turn it off ([Run a pipeline](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/run-pipeline)).
- **Lineage.** ML Metadata records what each run consumed and produced. You can also send lineage to Knowledge Catalog (formerly Dataplex). You opt in per project when you enable the Data Lineage API ([Track the lineage of pipeline artifacts](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/lineage)).
- **Experiments.** You can attach a run to an experiment to compare runs ([Introduction to Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/introduction)).
- **Templates.** A template is a reusable pipeline definition. Artifact Registry stores templates and container images ([Configure your project for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-project)).
- **Schedules.** The scheduler API creates one-time or recurring runs, which implements continuous training ([Schedule a pipeline run](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/schedule-pipeline-run)).
- **Cost.** Each run has an execution fee. You also pay for the resources the run creates. Pipelines labels those resources with the run's billing ID, so a billing export to BigQuery shows the cost of each run ([Gemini Enterprise Agent Platform pricing](https://cloud.google.com/products/gemini-enterprise-agent-platform/pricing), [Understand pipeline run costs](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/understand-pipeline-cost-labels)).

### Security for pipeline runs

- Create a dedicated service account for runs. For least privilege, grant a custom role instead of `roles/aiplatform.user` ([Configure your project for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-project)).
- The person who submits the run needs `roles/iam.serviceAccountUser` on that service account ([Configure your project for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-project)).
- For private connectivity, Google recommends a Private Service Connect interface. It reduces IP exhaustion and supports transitive peering ([Configure Private Service Connect interface for a pipeline](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-private-service-connect)).
- Inside a VPC Service Controls perimeter, components cannot install packages from public PyPI. Build custom containers or use Artifact Registry ([VPC Service Controls with Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/general/vpc-service-controls)).

## Data integration: prepare the data

Keep the data where it fits, and let training read it in place.

| Data | Store it in | How training reads it |
|---|---|---|
| Structured and semi-structured | BigQuery | Training code reads BigQuery directly, or a managed dataset points to it. |
| Images, video, audio | Cloud Storage, as large sharded files (TFRecord or Avro) | Cloud Storage FUSE mounts buckets at `/gcs/` on each training node and streams large files. |
| Files that need POSIX behavior | An existing NFS share | Mount the share over private connectivity. A Private Service Connect interface (Preview for NFS mounts) is recommended. |

Sources: [Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices), [Data preparation overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/data-preparation-overview), [Prepare training code](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/code-requirements), [Mount a Network File System share](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/train-nfs-share).

**Managed datasets.** AutoML requires a managed dataset. Custom training can use one or skip it ([Overview of managed datasets](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/datasets/overview)). Skip it if you want to control data splits in code, or if lineage between data and model is not critical ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)).

**Transformation.** Use BigQuery SQL when a SQL process fits. It can be the most cost-effective method for a custom model. Use Dataflow for large volumes, and Managed Service for Apache Spark when the team already has Spark code and skills ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)).

**Feature Store.** Use one feature store as the source for experimentation, continuous training, and online serving. This avoids training-serving skew ([MLOps: Continuous delivery and automation pipelines](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning)). In the current Feature Store, the BigQuery tables or views that hold features form the offline store ([About Feature Store](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/featurestore/latest/overview)). Bigtable online serving syncs from BigQuery on a schedule or continuously. Optimized online serving and Feature Store (Legacy) are deprecated. For embeddings, use Vector Search instead ([Online serving types](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/featurestore/latest/online-serving-types), [Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/docs/deprecations)).

**Labeling.** The Vertex AI Data Labeling Service shut down on October 3, 2024. Add labels in the console, or use a partner labeling solution from Cloud Marketplace ([Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/docs/deprecations)).

**BigQuery ML.** You can register BigQuery ML models in Model Registry without an export ([Introduction to Model Registry](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-registry/introduction)). A pipeline can also run BigQuery and BigQuery ML jobs as steps ([Agent Platform for BigQuery users](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/beginner/bqml)).

## Training options

| Option | Use it when | Know this |
|---|---|---|
| BigQuery ML | All data is in BigQuery, and the team knows SQL. | Batch predictions only. Deploy through Model Registry for online use. |
| AutoML | The problem fits AutoML with little code. | Image and tabular data only. AutoML Text and AutoML Video are shut down. |
| Serverless training (a `CustomJob`) | Experiments and production jobs that do not need assured capacity | Prebuilt containers for supported Python frameworks. Custom containers for other languages or private dependencies. |
| Training clusters | Large, critical, long-running jobs that need reserved accelerators and no queue | Slurm interface. Google manages the cluster. Access through your sales team. |
| Ray on Agent Platform | You already have Ray code. | The Ray cluster runs until you delete it. |
| Hyperparameter tuning | You search for the best hyperparameters. | Vizier uses Bayesian optimization by default. |

Sources: [Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices), [Agent Platform for BigQuery users](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/beginner/bqml), [Train and use your own models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training-overview), [Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/docs/deprecations), [Serverless training overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/overview), [Choose a training method](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/start/training-methods), [Gemini Enterprise Agent Platform training clusters overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/training-clusters/overview), [Ray on Agent Platform overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/open-source/ray), [Agent Platform Vizier overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/vizier/overview).

Google recommends managed training for production even on small datasets, when training runs on a schedule or on new data ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)). Do not leave production retraining in a notebook.

Serverless training supports other capacity options. Spot VMs suit fault-tolerant jobs, reservations give assured capacity, and Dynamic Workload Scheduler suits GPU jobs that can wait ([Use Spot VMs with training](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/use-spot-vms), [Use reservations with training](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/use-reservations), [Schedule training jobs based on resource availability](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training/schedule-jobs-dws)). The details are in [AI Hypercomputer: accelerators and consumption models](note:2.4-ai-hypercomputer).

## Model Registry and evaluation

Model Registry is the central list of models and versions. From the registry, you evaluate a version, deploy it to an endpoint, or run batch inference ([MLOps on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/start/introduction-mlops)). An alias is a movable name for one version. The first version gets the `default` alias, and you can add your own aliases. You can deploy by alias ([How to use model version aliases](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-registry/model-alias), [Introduction to Model Registry](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-registry/introduction)). AutoML models go into the registry automatically, and custom models need an import ([Overview of getting inferences](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions)).

Model evaluation needs a trained model, batch inference output, and a ground truth dataset. If production metrics drop, retrain. Google calls this continuous evaluation ([Model evaluation in Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/evaluation/introduction)).

## Serving: online, batch, and endpoints

| | Online inference | Batch inference |
|---|---|---|
| Use it when | An application waits for the answer. | You process accumulated data and need no immediate response. |
| Needs an endpoint | Yes | No. The model does not need to be deployed. |
| Input and output | Request and response | Cloud Storage or BigQuery |
| Scaling | Autoscaling replicas | No autoscaling. The job splits the data across replicas at start. |

Sources: [Overview of getting inferences](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions), [Get batch inferences](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/get-batch-predictions).

### Endpoint types

| Endpoint type | Use it for | Limits to know |
|---|---|---|
| Dedicated public endpoint | Recommended for public access. Production isolation, larger payloads, longer timeouts. | No VPC Service Controls support |
| Private Service Connect endpoint | Recommended for private production traffic and on-premises access | Needs network setup |
| Shared public endpoint | Only when a model needs it. Tuned Gemini models deploy only here. | Smaller payloads and shorter timeouts |
| Private services access endpoint (VPC Network Peering) | Private access, also from on-premises | No traffic splitting, no request-response logging, and no SSL/TLS. Access logging is off, and you must contact Google to turn it on. |

Sources: [Choose an endpoint type](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/choose-endpoint-type), [Use private services access endpoints](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/using-private-endpoints).

### Scaling and rollout

- The minimum replica count is at least 1, so a normal deployment never scales to zero ([Scale inference nodes by using autoscaling](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/autoscaling)).
- Scale To Zero (Preview) removes all replicas when there is no traffic. The first request to a scaled-down model gets an HTTP 429 response ([Scale inference nodes by using autoscaling](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/autoscaling)).
- For a high-availability SLA, autoscale with a minimum of two nodes ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)).
- For a canary release, deploy the new model to the same endpoint with a small traffic share. Then increase its share to 100% ([Deploy a model to an endpoint](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/general/deployment)).
- Co-hosting puts many low-traffic models on shared nodes in a deployment resource pool. All models must use the same prebuilt TensorFlow or PyTorch (Preview) container ([Share resources across deployments](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/model-co-hosting)).

### Monitoring

Model Monitoring runs on a schedule or on demand to track the quality of tabular models ([Introduction to Model Monitoring](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-monitoring/overview)). Choose the detection type from the data you have:

- If you have the original training data, enable skew detection (training-serving skew).
- If you do not have it, enable drift detection. It compares the input data over time.

Model Monitoring v1 is GA and works on endpoints. Model Monitoring v2 is in Preview and works on model versions, even for models served outside Agent Platform ([Introduction to Model Monitoring](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-monitoring/overview)). Vertex Explainable AI is deprecated, so do not design new solutions around it ([Introduction to Vertex Explainable AI](https://docs.cloud.google.com/vertex-ai/docs/explainable-ai/overview)).

## Where Cloud Run functions fit

The exam guide names Cloud Run functions (formerly Cloud Functions) in this objective. Use them as small, event-driven glue, not as the place to train:

- **Start a pipeline run from Pub/Sub.** A function subscribes to a topic and submits the run with the Agent Platform SDK ([Trigger a pipeline run with Pub/Sub](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/trigger-pubsub)). Publishers can be Cloud Scheduler or a Cloud Logging filter on new data or on Model Monitoring alerts ([Architecture for MLOps using TFX, Agent Platform Pipelines, and Cloud Build](https://docs.cloud.google.com/architecture/architecture-for-mlops-using-tfx-kubeflow-pipelines-and-cloud-build)).
- **Retrain when new data lands.** A function with an Eventarc trigger can run the pipeline when new rows arrive in a BigQuery table ([Build a pipeline for continuous model training](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/continuous-training-tutorial)). A function triggered by a Cloud Storage upload can start a training job on the new file ([Generative AI security best practices](https://docs.cloud.google.com/docs/security/genai-security-bps)).
- **Light preprocessing.** A function can preprocess data before it goes to a model for training or prediction ([Generative AI security best practices](https://docs.cloud.google.com/docs/security/genai-security-bps)).

Choose the trigger from the data pattern. Data that arrives on a regular schedule fits the scheduler API. Data that arrives at irregular times fits an event trigger ([MLOps: Continuous delivery and automation pipelines](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning)).

## Exam traps

- **Managed Service for Apache Airflow for an ML-only workflow.** If the workflow is container-based and stays inside Agent Platform, Google recommends Agent Platform Pipelines ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)).
- **TFX by default.** Use KFP unless you process terabytes of structured or text data with TensorFlow Extended ([Interfaces for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/interfaces)).
- **The default service account.** It works, but the recommended answer is a dedicated service account with granular permissions ([Configure your project for Agent Platform Pipelines](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/pipelines/configure-project)).
- **Online endpoints for nightly scoring.** Batch inference needs no endpoint and reads from and writes to BigQuery or Cloud Storage ([Overview of getting inferences](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions), [Get batch inferences](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/get-batch-predictions)).
- **A dedicated public endpoint inside a VPC Service Controls perimeter.** It does not support VPC Service Controls. Use a Private Service Connect endpoint ([Choose an endpoint type](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/choose-endpoint-type)).
- **Traffic splitting on a private services access endpoint.** It is not supported ([Use private services access endpoints](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/using-private-endpoints)).
- **Drift detection when training data exists.** Skew detection is the direct check when you have the training data ([Introduction to Model Monitoring](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/model-monitoring/overview)).
- **Deprecated tools.** Do not choose AI Platform Pipelines, Data Labeling Service, AutoML Text or Video, managed notebooks, Feature Store (Legacy), or Explainable AI ([Vertex AI deprecations](https://docs.cloud.google.com/vertex-ai/docs/deprecations)).
- **Scale To Zero for a latency-critical endpoint.** It is Preview, and the first request after idle gets HTTP 429 ([Scale inference nodes by using autoscaling](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/predictions/autoscaling)).
