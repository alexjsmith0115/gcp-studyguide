## Why it matters

AI workloads add new attack paths: prompts, model responses, training data, model artifacts, and agents that call tools. The exam guide names Model Armor, Sensitive Data Protection (includes Cloud DLP), and secure model deployment. Exam scenarios ask where to screen prompts, how to keep personal data out of training data and responses, and how to keep a model private.

## Key points

- Model Armor screens LLM prompts and responses. It works for AI in Google Cloud and in other cloud providers ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- A Model Armor template sets the filters and confidence levels. Google recommends separate templates for prompts and for responses ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- "Inspect only" logs a violation but does not stop it. "Inspect and block" gives a block verdict, and the calling service does the blocking ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- Floor settings set minimum filters at the organization, folder, or project level. You cannot create a template that is less strict than the floor settings ([Configure floor settings](https://docs.cloud.google.com/model-armor/configure-floor-settings)).
- The Gemini Enterprise Agent Platform (formerly Vertex AI) integration skips the Model Armor check when Model Armor is unavailable or has an error. The request then continues without screening ([Integrate Model Armor with Gemini Enterprise Agent Platform](https://docs.cloud.google.com/model-armor/model-armor-vertex-integration)).
- Sensitive Data Protection de-identifies data by redaction, replacement, masking, tokenization, bucketing, date shifting, and time extraction ([Transformation reference](https://docs.cloud.google.com/sensitive-data-protection/docs/transformations-reference)).
- Tokens from AES-SIV or format-preserving encryption are reversible with the key. Cryptographic hashing is one-way ([Pseudonymization](https://docs.cloud.google.com/sensitive-data-protection/docs/pseudonymization)).
- Google does not use your data to train or fine-tune AI/ML models without your permission or instruction ([Gemini Enterprise Agent Platform and zero data retention](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention)).
- Run training jobs and deployed models as a dedicated service account. By default, training containers run as the Agent Platform Custom Code Service Agent ([Use a custom service account](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/general/custom-service-account)).
- The organization policy constraint `vertexai.allowedModels` limits which Model Garden models users can use, tune, or deploy ([Control access to Model Garden models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/control-model-access)).
- AI Protection in Security Command Center finds AI assets, their vulnerabilities, and threats to them. It works with organization-level and project-level activations ([AI Protection overview](https://docs.cloud.google.com/security-command-center/docs/ai-protection-overview)).
- Agent Identity gives each agent its own identity. Unlike a service account, an agent identity can't be impersonated and has no long-lived keys ([Agent Identity overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview)).

## Threats and controls

Google's Secure AI Framework (SAIF) is a guide for secure and responsible AI systems. The AI and ML perspective of the Well-Architected Framework gives six security principles. One of them, "Verify and protect inputs", says to treat all inputs as untrusted ([AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security)).

| Threat | What happens | Main Google Cloud controls |
|---|---|---|
| Prompt injection and jailbreak | Crafted input makes the model ignore its instructions, leak data, or produce harmful content. | Model Armor prompt injection and jailbreak filter. Input validation in the application. |
| Sensitive data leakage | Personal data goes into prompts, responses, logs, or training data. | Sensitive Data Protection. The Model Armor Sensitive Data Protection filter. |
| Data poisoning | An attacker adds malicious data to the training data. | Data validation, data quality checks, anomaly detection, and pipeline monitoring. |
| Exfiltration of models or data | An attacker copies model weights or training data. | VPC Service Controls, IAM least privilege, CMEK, and private endpoints. |
| Harmful or malicious output | The model returns harmful content or a phishing URL. | Model Armor responsible AI and malicious URL filters. |
| Tampered pipelines or artifacts | A changed model or container reaches production. | SLSA practices, signing, Model Registry, and Binary Authorization. |
| Query floods | A spike of queries tries denial of service or model theft. | Rate limiting in Apigee, and alerts on unusual query patterns. |

Sources: [AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security), [Model Armor overview](https://docs.cloud.google.com/model-armor/overview).

Build and deploy controls for containers are in [Software supply chain security](note:3.1-supply-chain).

## Model Armor

Model Armor is model-agnostic. Google recommends it as a mandatory protection layer for LLMs ([AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security)). It checks the prompt before the model gets it, and it checks the response before the user gets it.

### Filters

| Filter | What it detects | Notes |
|---|---|---|
| Responsible AI | Hate speech, harassment, sexually explicit content, and dangerous content | You set a confidence level for each category. The CSAM filter is always on. |
| Prompt injection and jailbreak | Commands in the prompt that try to trick the model | Inputs of fewer than three words return `NO_MATCH_FOUND`. |
| Sensitive Data Protection, basic | Credit card numbers, US SSNs, financial account numbers, US ITINs, and Google Cloud credentials and API keys | Inspection only. No templates. |
| Sensitive Data Protection, advanced | The infoTypes (sensitive data types) in your Sensitive Data Protection inspect template | Can also de-identify with a de-identify template. |
| Malicious URLs | Phishing and malware links | Scans only the first 256 URLs. |

Sources: [Model Armor overview](https://docs.cloud.google.com/model-armor/overview).

Confidence levels are `High`, `Medium and above`, and `Low and above`. `Low and above` catches more attacks but blocks more harmless content. Google suggests `High` or `Medium and above` as a start ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).

With the advanced filter and both templates, Model Armor returns the de-identified text in `deidentifyResult.data.text` ([Create and manage templates](https://docs.cloud.google.com/model-armor/manage-templates)).

### Enforcement and floor settings

- **Start with "Inspect only".** Look at the logs, tune the template, and then change to "Inspect and block". Without Cloud Logging, "Inspect only" gives no useful information ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- **Floor settings give a baseline.** An organization floor setting applies to the whole organization. When floor settings conflict, the lower level in the hierarchy wins ([Configure floor settings](https://docs.cloud.google.com/model-armor/configure-floor-settings)).
- **The console sets only project floor settings.** Use the API for organization and folder floor settings ([Configure floor settings](https://docs.cloud.google.com/model-armor/configure-floor-settings)).
- **Violations become findings.** A template that breaks a floor setting creates a high-severity finding in Security Command Center Premium or Enterprise (deprecated) ([Configure floor settings](https://docs.cloud.google.com/model-armor/configure-floor-settings), [Security Command Center service tiers](https://docs.cloud.google.com/security-command-center/docs/service-tiers)).
- **Precedence on Agent Platform.** A template in the request comes first, then floor settings, then the built-in Agent Platform safety filters ([Integrate Model Armor with Gemini Enterprise Agent Platform](https://docs.cloud.google.com/model-armor/model-armor-vertex-integration)).

### Where to put Model Armor

| Integration | What it screens | Design notes |
|---|---|---|
| REST API from your code | Any model in any cloud. Text, documents, and images. | Your application acts on the verdict. Image screening is Preview. |
| Agent Platform | `generateContent` calls to Gemini models, by template or floor settings | Skips screening on a Model Armor error. Does not return de-identified text. |
| Apigee | Prompts and responses that pass through API proxies | You add Model Armor policies to the proxies. |
| Service Extensions | Traffic on Application Load Balancers and GKE Inference Gateway | Screens all AI traffic that passes through the load balancer. |
| Agent Gateway | Traffic to and from agents | Inspects ingress and egress with no code change. |
| Gemini Enterprise | Prompts and responses between users, agents, and LLMs | Also screens documents. Blocks instead of de-identifying. |
| Google Cloud MCP (Model Context Protocol) servers | MCP tool calls and responses | Uses floor settings, not templates. The floor settings page marks it Preview. |

Sources: [Model Armor integrations](https://docs.cloud.google.com/model-armor/integrations), [Integrate Model Armor with Gemini Enterprise Agent Platform](https://docs.cloud.google.com/model-armor/model-armor-vertex-integration), [Model Armor overview](https://docs.cloud.google.com/model-armor/overview), [Configure floor settings](https://docs.cloud.google.com/model-armor/configure-floor-settings).

For the Agent Platform integration, grant the Model Armor User role to the Agent Platform service agent ([Integrate Model Armor with Gemini Enterprise Agent Platform](https://docs.cloud.google.com/model-armor/model-armor-vertex-integration)).

### Limits, data, and cost

- Model Armor checks each prompt and response as a single turn. It does not decode Base64 or other encodings, and it does not support audio or video ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- Model Armor does not store prompts or responses. Content is kept only if you turn on Cloud Logging ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- Some regions have limited filter support to keep strict data residency. You can turn off data residency enforcement in a template to get all filters there ([Data residency and endpoints](https://docs.cloud.google.com/model-armor/data-residency)).
- The first 2 million tokens each month are free. Then each 1 million tokens costs $0.10. A Security Command Center Premium subscription includes 3 billion tokens each month ([Model Armor](https://cloud.google.com/security/products/model-armor)).

## Sensitive Data Protection for AI data

Sensitive Data Protection finds and protects personal data before it reaches a model, a log, or a person.

- **Discover.** The discovery service profiles data in an organization, folder, or project. For Agent Platform training data, it profiles the Cloud Storage or BigQuery data ([Overview of sensitive data discovery](https://docs.cloud.google.com/sensitive-data-protection/docs/data-profiles)).
- **Minimize.** Do not collect data that you do not need. Where possible, train on synthetic or fully anonymized data ([AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security)).
- **De-identify.** Transform the data before training, before logging, and in model responses ([AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security)).

### Choose a de-identification method

| Method | Reversible | Keeps joins | Use when |
|---|---|---|---|
| Redaction, replacement, or masking | No | No | Nobody needs the value. Masking can hide only part of it. |
| Cryptographic hash (HMAC-SHA-256) | No | Yes | Analysts must join or count records, and nobody may see the original. |
| Deterministic encryption (AES-SIV) | Yes, with the key | Yes | A trusted service must re-identify values. It has no input limits and is fast. |
| Format-preserving encryption (FPE-FFX) | Yes, with the key | Yes | A system checks the length and character set. Use it only then. |
| Bucketing | No | No | Ranges are enough, for example age groups. |
| Date shifting | No | Keeps order and intervals | Dates must keep their sequence and duration. |

Sources: [Transformation reference](https://docs.cloud.google.com/sensitive-data-protection/docs/transformations-reference), [Pseudonymization](https://docs.cloud.google.com/sensitive-data-protection/docs/pseudonymization).

The key decides what you can do later ([Pseudonymization](https://docs.cloud.google.com/sensitive-data-protection/docs/pseudonymization)):

- **Key wrapped with Cloud KMS.** Google calls this the preferred method. Keep the key in Cloud KMS so that only authorized services can re-identify.
- **Transient key.** Sensitive Data Protection creates it and then discards it. It keeps integrity only within one request, so you cannot re-identify or join later.
- **Raw key in the request.** Not recommended.

Tokens can narrow the PCI DSS or HIPAA scope of downstream systems. See [Designing for compliance](note:3.2-compliance). For key management, see [Encryption, Cloud KMS, and secrets](note:3.1-data-protection-kms).

## Secure model deployment

| Area | Control | Detail |
|---|---|---|
| Identity | A dedicated, least-privilege service account for each job, pipeline, and deployed model | The default account of a prediction container can read model artifacts. Do not rely on other permissions. You can't change them. |
| Network | Private Service Connect endpoints inside a VPC Service Controls perimeter | Google recommends Private Service Connect for online prediction. |
| Encryption | CMEK in Cloud KMS | You control the key location, rotation, and access. |
| Approved models | The `vertexai.allowedModels` constraint | Allows or denies `predict`, `deploy`, and `tune` for each model. |
| Artifacts | Model Registry, signing, and Binary Authorization | For containerized models, Binary Authorization verifies signatures. |
| Data in use | Confidential Computing | Confidential VMs with GPUs, or Confidential GKE Nodes. |
| Model APIs | Apigee or API Gateway | Authentication, authorization, and rate limiting. |
| Audit | Cloud Audit Logs for Agent Platform | Records endpoint creation, model deployment, and configuration changes. |
| Data residency | A regional or US or EU multi-region endpoint | Requests to the global endpoint can run in any location. |

Sources: [Use a custom service account](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/general/custom-service-account), [AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security), [Customer-managed encryption keys (CMEK)](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/general/cmek), [Control access to Model Garden models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/control-model-access), [Data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency).

Endpoint types, pipeline service accounts, and VPC Service Controls limits are in [End-to-end ML workflows on Agent Platform](note:2.4-ml-workflows). Gemini endpoints and data location are in [Choosing AI and ML solutions](note:1.3-ai-solutions).

### Data that Google keeps

These features keep customer data unless you act:

| Feature | What Google keeps | To get zero data retention |
|---|---|---|
| In-memory caching | Inputs, outputs, and derived data, in memory only, isolated by project, for up to 24 hours | Google states that this caching does not violate zero data retention. You can disable it at the project level. |
| Abuse monitoring | Prompts that safety classifiers flag, for up to 90 days | Request an exception. |
| Grounding with Google Search | Queries for up to 3 days. You cannot turn this off. | Use Web Grounding for Enterprise. |
| Grounding with Google Maps | Prompts, context, and generated output for 30 days. You cannot turn this off. | Do not use this feature. |
| Request-response logging | Requests and responses in your BigQuery table. Off by default. | Do not turn it on. |
| Session resumption (Gemini Live API) | Cached prompts and outputs, including audio and video, for up to 24 hours. Off by default. | Do not turn it on. |
| Interactions API | Prompts, responses, and conversation state, because `store` defaults to `true` | Set `store = false`. |

Sources: [Gemini Enterprise Agent Platform and zero data retention](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention), [Abuse monitoring](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/abuse-monitoring).

## Governing agents

Agent Platform has components that control what agents can call:

| Component | Question it answers | What it does |
|---|---|---|
| Agent Identity | Who made the request? | An identity for each agent that follows the SPIFFE standard, with an X.509 certificate. Access tokens are bound to the certificate. |
| Agent Registry | What destinations are approved? | A catalog of approved agents, tools, MCP servers, and endpoints. |
| Policies | What actions are permitted? | IAM allow and deny policies, Model Armor, semantic governance policies, and custom authorization engines. |
| Agent Gateway | Where are policies enforced? | The entry and exit point for agent traffic. It handles mTLS, translates protocols, and checks policies. |

Sources: [Agent Gateway overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview), [Agent Identity overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview).

- Agent Gateway blocks all connections unless an IAM policy grants access ([Agent Gateway overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview)).
- Semantic governance policies are rules in natural language. They check that tool calls match the user's intent and your business rules. The policies feature does not support VPC Service Controls ([Policies overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/policies/overview)).
- Agent Identity works with Agent Runtime (formerly Vertex AI Agent Engine), Gemini Enterprise, and Cloud Run ([Agent Identity overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview)).

## Exam traps

- **"Inspect only" does not protect.** It only logs. Use "Inspect and block" after you tune the template ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- **A verdict is not a block.** With the REST API, your application must stop the prompt or response ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview)).
- **The Agent Platform integration can skip screening.** On a Model Armor error or outage, the request continues unscreened ([Integrate Model Armor with Gemini Enterprise Agent Platform](https://docs.cloud.google.com/model-armor/model-armor-vertex-integration)).
- **No masked text from the Agent Platform integration.** In "Inspect and block" mode, it blocks instead. To get masked text, call the REST API with a de-identify template ([Integrate Model Armor with Gemini Enterprise Agent Platform](https://docs.cloud.google.com/model-armor/model-armor-vertex-integration), [Create and manage templates](https://docs.cloud.google.com/model-armor/manage-templates)).
- **Model Armor is one layer.** It sees one turn at a time and does not decode Base64. Also validate inputs in code ([Model Armor overview](https://docs.cloud.google.com/model-armor/overview), [AI and ML perspective: Security](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/security)).
- **Hashes and transient keys cannot be reversed.** To re-identify later, use AES-SIV or FPE with a KMS-wrapped key ([Pseudonymization](https://docs.cloud.google.com/sensitive-data-protection/docs/pseudonymization)).
- **FPE is not the default token.** Use it only when the format must stay the same ([Transformation reference](https://docs.cloud.google.com/sensitive-data-protection/docs/transformations-reference)).
- **The Model Garden policy does not cover Model Registry.** It applies only to Model Garden models ([Control access to Model Garden models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/control-model-access)).
- **Grounding with Google Search keeps data.** For zero data retention, use Web Grounding for Enterprise ([Gemini Enterprise Agent Platform and zero data retention](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention)).
