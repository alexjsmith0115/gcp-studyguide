## Why it matters

A data processing question describes the data source, the latency need, the team skills, and the existing code. You choose the services for ingestion, processing, and orchestration. The exam prefers the managed option with the least operational overhead that still meets every requirement. Google renamed several data products in 2026, so a question can use the old name or the new name.

## Key points

- Google recommends the ELT approach for most customers: load the data into BigQuery, then transform it with SQL ([Introduction to loading, transforming, and exporting data](https://docs.cloud.google.com/bigquery/docs/load-transform-export-intro)).
- A Pub/Sub BigQuery subscription writes messages to a BigQuery table with no subscriber client. Use Dataflow when you must window or aggregate across messages ([BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/bigquery)).
- Pub/Sub gives at-least-once delivery by default. Exactly-once delivery works only for pull subscriptions, with subscribers in the same region ([Subscription overview](https://docs.cloud.google.com/pubsub/docs/subscription-overview), [Exactly-once delivery](https://docs.cloud.google.com/pubsub/docs/exactly-once-delivery)).
- Dataflow runs Apache Beam pipelines for batch and streaming data. It gives exactly-once processing by default ([Dataflow overview](https://docs.cloud.google.com/dataflow/docs/overview)).
- Managed Service for Apache Spark (formerly Dataproc) has cluster and serverless deployments. Choose clusters to migrate Hadoop or Spark workloads. Choose serverless for ease of use and intermittent jobs ([Compare Managed Service for Apache Spark serverless and cluster deployments](https://docs.cloud.google.com/managed-spark/docs/concepts/serverless-spark-compare)).
- Datastream is a serverless change data capture (CDC) service. It replicates changes from MySQL, Oracle, SQL Server, PostgreSQL, and other databases ([Datastream overview](https://docs.cloud.google.com/datastream/docs/overview), [Sources](https://docs.cloud.google.com/datastream/docs/sources)).
- For new streaming workloads, Google recommends Pub/Sub. For existing Kafka workloads, it recommends Managed Service for Apache Kafka ([Choose Pub/Sub or Cloud Managed Service for Apache Kafka](https://docs.cloud.google.com/pubsub/docs/choose-pubsub-kafka)).
- Pub/Sub Lite is deprecated. Google turns it down on January 31, 2027 ([Pub/Sub Lite documentation](https://docs.cloud.google.com/pubsub/lite/docs)).
- Managed Service for Apache Airflow (formerly Cloud Composer) orchestrates batch ETL and ELT workflows. Workflows orchestrates HTTP-based services and is serverless ([Choose Workflows or Managed Airflow for service orchestration](https://docs.cloud.google.com/workflows/docs/choose-orchestration), [Knowledge Catalog release notes](https://docs.cloud.google.com/knowledge-catalog/docs/release-notes)).

## Ingest

### Pub/Sub behavior that shapes the design

| Property | Behavior |
|---|---|
| Delivery | At-least-once, with no ordering guarantee. Subscribers must be idempotent. |
| Exactly-once | Pull subscriptions only, with subscribers in the same region. Publish-side duplicates can still occur. |
| Ordering | Set the same ordering key on related messages and publish them in the same region. Enable message ordering on the subscription. |
| Retention | A subscription keeps unacknowledged messages for 7 days by default (10 minutes to 31 days). A topic can keep messages for up to 31 days. |
| Replay | Seek to a past time needs topic retention or retained acknowledged messages. A snapshot lives at most 7 days. |
| Failed messages | A dead-letter topic receives messages after a set number of delivery attempts. |
| Light transforms | Single Message Transforms (SMTs) change one message at a time inside Pub/Sub. |
| Export | BigQuery, Cloud Storage, and Bigtable (Preview) subscriptions write messages directly. |

Sources: [Subscription overview](https://docs.cloud.google.com/pubsub/docs/subscription-overview), [Exactly-once delivery](https://docs.cloud.google.com/pubsub/docs/exactly-once-delivery), [Order messages](https://docs.cloud.google.com/pubsub/docs/ordering), [Subscription properties](https://docs.cloud.google.com/pubsub/docs/subscription-properties), [Create a topic](https://docs.cloud.google.com/pubsub/docs/create-topic), [Replay and purge messages with seek](https://docs.cloud.google.com/pubsub/docs/replay-overview), [Dead-letter topics](https://docs.cloud.google.com/pubsub/docs/dead-letter-topics), [Single Message Transforms (SMTs) overview](https://docs.cloud.google.com/pubsub/docs/smts/smts-overview).

Pub/Sub compared with Cloud Tasks and Eventarc is on the [Integration patterns](note:1.1-integration-and-data-movement) page.

### Pub/Sub or Managed Service for Apache Kafka

- Choose Pub/Sub for new workloads, for minimal configuration, and for data movement between regions ([Choose Pub/Sub or Cloud Managed Service for Apache Kafka](https://docs.cloud.google.com/pubsub/docs/choose-pubsub-kafka)).
- Choose Managed Service for Apache Kafka when you already use Kafka. You must manage the cluster size and the number of partitions for each topic ([Choose Pub/Sub or Cloud Managed Service for Apache Kafka](https://docs.cloud.google.com/pubsub/docs/choose-pubsub-kafka)).
- Migrate Pub/Sub Lite workloads to Pub/Sub or Managed Service for Apache Kafka ([Pub/Sub Lite documentation](https://docs.cloud.google.com/pubsub/lite/docs)).

### Database changes: Datastream

Datastream reads changes from MySQL, Oracle, SQL Server, PostgreSQL, AlloyDB, Cloud SQL, and Amazon RDS. It also supports Spanner, MongoDB, and Salesforce sources ([Sources](https://docs.cloud.google.com/datastream/docs/sources)). It writes to BigQuery, Cloud Storage, or Apache Iceberg tables ([Configure Apache Iceberg tables in BigQuery](https://docs.cloud.google.com/datastream/docs/destination-blmt), [Datastream overview](https://docs.cloud.google.com/datastream/docs/overview)).

- A stream can backfill historical data and stream ongoing changes at the same time ([Key concepts and features](https://docs.cloud.google.com/datastream/docs/behavior-overview)).
- Delivery is at least once. Event metadata lets you remove duplicates in the destination ([Key concepts and features](https://docs.cloud.google.com/datastream/docs/behavior-overview)).
- To move a database to a new primary in Cloud SQL or AlloyDB for PostgreSQL, use Database Migration Service instead ([Database Migration Service overview](https://docs.cloud.google.com/database-migration/docs/overview), [Migration tooling](note:5.1-migration-tooling)).

### Files and SaaS data

- If the source data changes rarely, load jobs can cost less than streaming ([Introduction to loading data](https://docs.cloud.google.com/bigquery/docs/loading-data)).
- BigQuery Data Transfer Service automates scheduled loads into BigQuery. Sources include Cloud Storage, Amazon S3, Azure Blob Storage, and SaaS applications ([Introduction to the BigQuery Data Transfer Service](https://docs.cloud.google.com/bigquery/docs/dts-introduction)).
- For new streaming code, use the Storage Write API (gRPC). It has lower pricing and exactly-once semantics compared with the Storage Write API (REST) ([Use the Storage Write API (REST)](https://docs.cloud.google.com/bigquery/docs/write-api-rest)).

## Process

| Service | Use it when | Do not use it when |
|---|---|---|
| BigQuery SQL (ELT) | The data lands in BigQuery and the team writes SQL. | You must reduce resource use in BigQuery, or you already have an ETL process. |
| Dataflow | You build new batch or streaming pipelines, with windows, aggregations, or custom sources. | You must move existing Spark or Hadoop jobs with few changes. |
| Managed Spark clusters | You migrate Hadoop or Spark jobs, need maximum control, or need Hive, Flink, Trino, or Kafka on the cluster. | Jobs are intermittent and you do not want to manage clusters. |
| Managed Spark serverless | You run Spark batch jobs or interactive sessions with no cluster to manage. | You need a framework other than Spark. |
| Cloud Data Fusion | Teams want code-free, visual ETL and ELT pipelines with prebuilt connectors. | A simple copy fits a BigQuery subscription or a transfer service. |
| Pub/Sub BigQuery subscription | Messages go to BigQuery as they arrive, with no transformation or a light SMT. | You must window, aggregate, or deduplicate exactly. |

Sources: [Introduction to loading, transforming, and exporting data](https://docs.cloud.google.com/bigquery/docs/load-transform-export-intro), [Dataflow overview](https://docs.cloud.google.com/dataflow/docs/overview), [Introduction to loading data](https://docs.cloud.google.com/bigquery/docs/loading-data), [Compare Managed Service for Apache Spark serverless and cluster deployments](https://docs.cloud.google.com/managed-spark/docs/concepts/serverless-spark-compare), [Cloud Data Fusion](https://cloud.google.com/data-fusion), [BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/bigquery).

### Dataflow

- Dataflow uses one programming model for batch and streaming. You can later run the same Beam code on Apache Flink or Apache Spark ([Dataflow overview](https://docs.cloud.google.com/dataflow/docs/overview)).
- Exactly-once mode is the default. At-least-once mode reduces cost and latency when the workload tolerates duplicates ([Set the pipeline streaming mode](https://docs.cloud.google.com/dataflow/docs/guides/streaming-modes)).
- Streaming Engine moves pipeline execution from the worker VMs into the Dataflow service backend ([Use Streaming Engine for streaming jobs](https://docs.cloud.google.com/dataflow/docs/streaming-engine)). Horizontal Autoscaling is on by default for Streaming Engine jobs ([Horizontal Autoscaling](https://docs.cloud.google.com/dataflow/docs/horizontal-autoscaling)).
- For a new template, Google recommends a Flex template. Since August 4, 2025, Google-managed templates run on Dataflow Prime by default ([Dataflow templates](https://docs.cloud.google.com/dataflow/docs/concepts/dataflow-templates)).

### Managed Service for Apache Spark

- The cluster deployment bills for cluster uptime. The serverless deployment bills for job runtime ([Compare Managed Service for Apache Spark serverless and cluster deployments](https://docs.cloud.google.com/managed-spark/docs/concepts/serverless-spark-compare)).
- With the ephemeral cluster model, you create a cluster for each job and delete it after the job. Keep the input and output data in Cloud Storage or BigQuery ([Spark job tuning tips](https://docs.cloud.google.com/managed-spark/docs/support/spark-job-tuning)).
- Do not use autoscaling to shrink an idle cluster. Delete the idle cluster and create a new one later ([Autoscale clusters](https://docs.cloud.google.com/managed-spark/docs/concepts/configuring-clusters/autoscaling)).
- Secondary workers do not store data, so they add compute without storage. They can be Spot VMs ([Managed Service for Apache Spark secondary workers](https://docs.cloud.google.com/managed-spark/docs/concepts/compute/secondary-vms)).

### SQL in BigQuery: Dataform, pipelines, and continuous queries

- Dataform lets analysts develop, test, version, and schedule SQL workflows in BigQuery. You write SQLX files and can link a Git repository ([Dataform overview](https://docs.cloud.google.com/dataform/docs/overview)).
- For smaller scheduled workflows of SQL, notebooks, or data preparations, use BigQuery pipelines ([Introduction to loading, transforming, and exporting data](https://docs.cloud.google.com/bigquery/docs/load-transform-export-intro)).
- Continuous queries run SQL on incoming data in real time. They need an Enterprise or Enterprise Plus reservation with a `CONTINUOUS` assignment, not on-demand billing ([Introduction to continuous queries](https://docs.cloud.google.com/bigquery/docs/continuous-queries-introduction)).

### Cloud Data Fusion

Data Fusion is based on the open source project CDAP. At run time, it creates an ephemeral Managed Service for Apache Spark cluster and runs the pipeline on it ([Cloud Data Fusion overview](https://docs.cloud.google.com/data-fusion/docs/concepts/overview)). The editions are Developer, Basic, and Enterprise. Enterprise is the edition for production ([Cloud Data Fusion pricing](https://cloud.google.com/data-fusion/pricing)).

## Streaming into BigQuery: choose the path

| Path | Fits | Delivery |
|---|---|---|
| Pub/Sub BigQuery subscription | Messages are already in Pub/Sub, with no transformation or a light SMT | At least once |
| Dataflow, for example the Pub/Sub to BigQuery template | Windows, aggregations, enrichment, and a dead-letter table | Exactly once by default |
| Storage Write API (gRPC) from the application | The application writes rows directly | Exactly once with stream offsets; the default stream is at least once |
| Datastream | Changes from an operational database | At least once, with metadata for deduplication |

Sources: [BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/bigquery), [Pub/Sub to BigQuery template](https://docs.cloud.google.com/dataflow/docs/guides/templates/provided/pubsub-to-bigquery), [Introduction to the Storage Write API (gRPC)](https://docs.cloud.google.com/bigquery/docs/write-api-grpc), [Key concepts and features](https://docs.cloud.google.com/datastream/docs/behavior-overview), [Dataflow overview](https://docs.cloud.google.com/dataflow/docs/overview).

The Dataflow template docs say it directly: before you run the template, consider whether a BigQuery subscription with a UDF meets your requirements ([Pub/Sub to BigQuery template](https://docs.cloud.google.com/dataflow/docs/guides/templates/provided/pubsub-to-bigquery)). A BigQuery subscription needs the BigQuery Data Editor role for its service account ([Create BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/create-bigquery-subscription)). If a message cannot be written, add a dead-letter topic to the subscription ([BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/bigquery)).

## Orchestrate

| Criterion | Managed Airflow | Workflows |
|---|---|---|
| Designed for | Data-driven workflows, particularly ETL and ELT | Chains of HTTP-based services and microservices |
| Definition | Python DAG files | YAML or JSON |
| Latency between steps | Seconds | Milliseconds |
| Scaling and billing | Provisioned; billed for capacity | Serverless; billed per step |
| Data features | Backfills and DAG re-runs | None |

Sources: [Choose Workflows or Managed Airflow for service orchestration](https://docs.cloud.google.com/workflows/docs/choose-orchestration).

- Do not run CPU-heavy or memory-heavy tasks on the Airflow nodes. Use `KubernetesPodOperator` or `GKEStartPodOperator` instead ([Write Airflow DAGs](https://docs.cloud.google.com/composer/docs/composer-3/write-dags)).
- Managed Airflow Legacy Gen 1 environments reached end of life on September 15, 2026. Google recommends Gen 3 ([Managed Service for Apache Airflow versioning overview](https://docs.cloud.google.com/composer/docs/composer-versioning-overview)).
- For SQL-only transformations in BigQuery, Dataform or BigQuery pipelines can schedule the work without an Airflow environment ([Introduction to loading, transforming, and exporting data](https://docs.cloud.google.com/bigquery/docs/load-transform-export-intro)).

## Govern, share, and use open formats

- **Knowledge Catalog (formerly Dataplex Universal Catalog).** It keeps data discovery, data lineage, data quality scans, and business glossaries ([Transition from Dataplex Universal Catalog to Knowledge Catalog](https://docs.cloud.google.com/knowledge-catalog/docs/transition-dataplex-universal-catalog)). Data Catalog began a phased shutdown on June 1, 2026 ([Knowledge Catalog release notes](https://docs.cloud.google.com/knowledge-catalog/docs/release-notes)).
- **Lakehouse (formerly BigLake).** For most open lakehouse workloads, Google recommends Apache Iceberg tables in the Lakehouse runtime catalog, served through the Iceberg REST catalog endpoint ([Compare table types](https://docs.cloud.google.com/lakehouse/docs/lakehouse-tables), [Lakehouse release notes](https://docs.cloud.google.com/lakehouse/docs/release-notes)).
- **BigLake tables.** They query data in external stores with access delegation, so users do not need access to the underlying store ([Introduction to BigLake tables](https://docs.cloud.google.com/bigquery/docs/biglake-intro)).
- **BigQuery sharing (formerly Analytics Hub).** It shares data across organizations without copies ([Introduction to BigQuery sharing](https://docs.cloud.google.com/bigquery/docs/analytics-hub-introduction)).
- **BigQuery Omni.** It runs BigQuery analytics on data in Amazon S3 or Azure Blob Storage ([Introduction to BigQuery Omni](https://docs.cloud.google.com/bigquery/docs/omni-introduction)).

## Exam traps

- **A Dataflow job to copy Pub/Sub messages into BigQuery unchanged.** A BigQuery subscription does this with less overhead ([BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/bigquery), [Pub/Sub to BigQuery template](https://docs.cloud.google.com/dataflow/docs/guides/templates/provided/pubsub-to-bigquery)).
- **A BigQuery subscription for windowed aggregates.** Use Dataflow for windows and aggregation across messages ([BigQuery subscriptions](https://docs.cloud.google.com/pubsub/docs/bigquery)).
- **Exactly-once delivery on a push or export subscription.** Only pull subscriptions support it ([Exactly-once delivery](https://docs.cloud.google.com/pubsub/docs/exactly-once-delivery)).
- **Rewrite Spark jobs in Apache Beam for a fast migration.** Move them to Managed Service for Apache Spark clusters ([Compare Managed Service for Apache Spark serverless and cluster deployments](https://docs.cloud.google.com/managed-spark/docs/concepts/serverless-spark-compare)).
- **Autoscale an idle Spark cluster down to save money.** Delete idle clusters and use ephemeral clusters ([Autoscale clusters](https://docs.cloud.google.com/managed-spark/docs/concepts/configuring-clusters/autoscaling)).
- **Pub/Sub Lite in a new design.** It is deprecated ([Pub/Sub Lite documentation](https://docs.cloud.google.com/pubsub/lite/docs)).
- **Managed Airflow to chain low-latency HTTP calls.** Workflows fits, with millisecond latency and per-step billing ([Choose Workflows or Managed Airflow for service orchestration](https://docs.cloud.google.com/workflows/docs/choose-orchestration)).
- **Continuous queries with on-demand billing.** They need an Enterprise or Enterprise Plus reservation ([Introduction to continuous queries](https://docs.cloud.google.com/bigquery/docs/continuous-queries-introduction)).
- **Datastream to move a database to a new primary.** Datastream feeds analytics. Database Migration Service moves databases into Cloud SQL or AlloyDB for PostgreSQL ([Datastream overview](https://docs.cloud.google.com/datastream/docs/overview), [Database Migration Service overview](https://docs.cloud.google.com/database-migration/docs/overview), [Migration tooling](note:5.1-migration-tooling)).
