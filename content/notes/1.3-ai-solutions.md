## Why it matters

The architect decides how much of an AI solution to build and how much to buy. The exam gives a business need and constraints such as time to market, data location, team skills, and cost. You then pick the right layer: a pre-trained API, a Gemini model with prompts and grounding, a tuned model, or a custom-trained model. The exam guide v6.1 uses the new Gemini Enterprise Agent Platform names. You must also map the old Vertex AI names to the new ones.

## Key points

- Google renamed Vertex AI to Gemini Enterprise Agent Platform (short form: Agent Platform) in April 2026. The API is still `aiplatform.googleapis.com` ([Agent Platform name changes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/vertex-ai-name-changes), [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes), [Agent Platform API reference](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/rest)).
- Agent Platform is one platform to build, deploy, govern, and optimize agents and model-based solutions. It gives access to more than 200 foundation models ([Agent Platform overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/overview)).
- "Agent Builder" is now part of Agent Platform. Its Agent Engine is now Agent Runtime ([Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)).
- Google recommends that you start with prompting and fine-tune only if required ([Introduction to tuning](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/tuning)).
- Grounding connects model output to verifiable sources, such as Google Search, Agent Search (formerly Vertex AI Search), RAG Engine, or your own search API ([Grounding overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/overview)).
- Gemini comes in tiers. Pro is for complex reasoning, Flash balances quality and speed, and Flash-Lite is for low-cost, high-volume traffic ([Google models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/google-models)).
- Stable Gemini models stay available for at least 12 months after release. Retirement dates can move later, but never earlier ([Model versions and lifecycle](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-versions)).
- The global endpoint gives no data residency guarantee. Use a regional or multi-region endpoint when data must stay in a jurisdiction ([Data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency)).
- Model Garden has Google models, partner models (for example Anthropic Claude), and open models (for example Llama). Partner models run as a managed API ([Overview of models on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models), [Partner models for MaaS](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/use-partner-models)).
- BigQuery ML creates and runs models with SQL. It can also call Agent Platform models from SQL, so you do not need to move data out of the warehouse ([Introduction to ML in BigQuery](https://docs.cloud.google.com/bigquery/docs/bqml-introduction)).
- AI Hypercomputer is an integrated system of accelerators, open software, and consumption options for AI workloads ([AI Hypercomputer overview](https://docs.cloud.google.com/ai-hypercomputer/docs/overview)).
- Gemini Enterprise (formerly Google Agentspace) is an intranet search, AI assistant, and agentic platform for employees ([What is Gemini Enterprise?](https://docs.cloud.google.com/gemini/enterprise/docs), [Gemini Enterprise release notes](https://docs.cloud.google.com/gemini/enterprise/docs/release-notes)).

## What "Agent Builder" means now

The exam guide names "Agent Builder". The docs described Vertex AI Agent Builder as a suite of products to build, scale, and govern AI agents in production ([Vertex AI Agent Builder documentation](https://docs.cloud.google.com/agent-builder)). In April 2026, Google moved Agent Builder into Agent Platform ([Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)). The console still has an Agent Builder section in the Agent Platform menu ([Agent Garden](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/agent-garden)).

Map an exam requirement to the current component:

| Requirement | Component | What to know |
|---|---|---|
| Prototype prompts and simple agents without code | Agent Studio (formerly Vertex AI Studio) | Low-code workspace. It compares prompts and models and adds grounding with Google Search, RAG Engine, or Agent Search. |
| Write multi-agent systems in code | Agent Development Kit (ADK) | Open-source, model-agnostic framework in Python, TypeScript, Go, and Java. Agents run on Agent Runtime, Cloud Run, or GKE. |
| Start from a sample agent | Agent Garden (Preview) | Library of prebuilt agent samples, such as RAG templates. |
| Run agents in production | Agent Runtime (formerly Agent Engine) | Fully managed runtime. It deploys any framework that runs in a container. Sessions keep one conversation; Memory Bank keeps memory across sessions. |
| Answer from enterprise data | Agent Search, RAG Engine, Vector Search | See the grounding and RAG section below. |
| Govern agents | Agent Registry, Agent Identity, Agent Gateway | A catalog of agents and tools, one identity for each agent, and one point for policy enforcement. See [Securing AI workloads](note:3.1-securing-ai). |
| Give agents to employees | Gemini Enterprise app | Employees find and run agents in one place. See [Pre-trained AI APIs, Gemini Enterprise, and Model Garden](note:2.5-ai-apis-and-gemini-enterprise). |

Sources: [Agents overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/agents), [Agent Platform overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/overview), [Agent Studio overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/agent-studio), [Agent Development Kit](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/adk), [Agent Runtime](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/runtime), [Agent Garden](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/agent-garden).

A trap: the Agent Search docs list "Agent Builder" among the former names of Agent Search itself ([Agent Search](https://docs.cloud.google.com/generative-ai-app-builder/docs)). So an older question that says "Agent Builder" can mean the search and conversation product. Read the scenario: search over company content points to Agent Search, and custom agent logic points to ADK and Agent Runtime.

## The build-versus-buy ladder

Google tells you to take an incremental approach to model selection and development, and to use managed services and pre-trained models to control cost ([AI and ML perspective: Cost optimization](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/cost-optimization)). Climb only as high as the requirement needs.

| Step | Use it when | Products | Build effort |
|---|---|---|---|
| 1. Pre-trained task API | The task is common and narrow: OCR, labels, speech, translation, entity extraction. | Cloud Vision, Speech-to-Text, Cloud Translation, Natural Language, Document AI | Lowest |
| 2. Foundation model with a prompt | The task needs reasoning, generation, or several modalities in one request. | Gemini on Agent Platform, Agent Studio | Low |
| 3. Prompt plus grounding or RAG | Answers must use current or private data and show sources. | Grounding with Google Search, Agent Search, RAG Engine, Vector Search | Medium |
| 4. Tuning | Prompting is not enough, and you have labeled examples (about 100 or more). | Supervised fine-tuning of Gemini, LoRA for open models | Medium |
| 5. Predictive ML on your data | You predict from your own tabular or image data. | BigQuery ML (data in BigQuery, SQL skills), AutoML (tabular and image only) | Medium |
| 6. Custom training | No managed option fits, or you need full control of the model. | Agent Platform serverless training, training clusters, GKE | Highest |

Sources: [AI and ML perspective: Cost optimization](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/cost-optimization), [Introduction to tuning](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/tuning), [Train and use your own models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/training-overview), [Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices), [Vertex AI APIs for building search and RAG experiences](https://docs.cloud.google.com/generative-ai-app-builder/docs/builder-apis).

Two rules decide most ladder questions:

- **Tuning teaches a skill. Grounding adds facts.** Supervised fine-tuning teaches the model a new skill, such as classification or entity extraction ([Introduction to tuning](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/tuning)). Grounding ties answers to your data sources and reduces hallucinations ([Grounding overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/overview)). Data that changes every day belongs in retrieval, not in model weights.
- **Skills and economics count.** The Well-Architected Framework asks you to weigh the value of buying a solution against the cost of building and maintaining it. It also asks whether the team has the skills for custom model development ([AI and ML perspective: Performance optimization](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/performance-optimization)).

## Choose a Gemini model

Pick the tier first. Version numbers change every few months, but the tiers stay.

| Tier | Examples (September 2026) | Use it for |
|---|---|---|
| Pro | Gemini 2.5 Pro (GA, retires October 20, 2026) | Complex reasoning and coding with a 1 million token context |
| Flash | Gemini 3.5 Flash (stable), Gemini 3.8 Flash (short-term) | Most production work. Google describes 3.5 Flash as near-Pro intelligence at Flash-tier cost and speed. |
| Flash-Lite | Gemini 3.5 Flash-Lite, Gemini 3.1 Flash-Lite | Low latency, high volume, and the lowest cost |
| Live | Gemini 3.8 Live | Real-time voice and video through the Gemini Live API |
| Image | Gemini 3.1 Flash Image (Nano Banana 2), Gemini 3 Pro Image | Image generation and conversational editing |
| Open weights | Gemma 4 | Models that you deploy and control yourself |

Sources: [Google models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/google-models), [Model versions and lifecycle](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-versions), [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes), [Gemini Live API overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/live-api).

**Lifecycle.** Stable models stay available for at least 12 months after release. Short-term models stay active until Google announces a retirement date, with at least 45 days to migrate ([Model versions and lifecycle](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-versions)). For production, pin a model version, track its retirement date, and test the replacement before you switch.

**Endpoints and data location.** The global endpoint gives higher availability than a single region ([Deployments and endpoints](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/locations)). But requests to the global endpoint can run in any Google Cloud location, so it gives no data residency guarantee. US and EU multi-region endpoints keep ML processing in that jurisdiction ([Data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency)). The `constraints/gcp.restrictEndpointUsage` organization policy constraint can block requests to the global endpoint ([Partner models for MaaS](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/use-partner-models)).

**Consumption options.** Match the option to the traffic pattern:

| Option | Ideal for | Pricing |
|---|---|---|
| Provisioned Throughput | Critical, steady, always-on workloads that need an SLA | Commitment (1 week to 1 year) |
| Standard PayGo | Everyday use with variable traffic | Per token, standard rate |
| Priority PayGo | Important workloads that need higher reliability than Standard PayGo | Per token, premium rate |
| Flex PayGo | Work that can wait longer and accept more throttling | Per token, discounted rate |
| Batch inference | Large, asynchronous jobs | Per token, discounted rate |

Source: [Consumption options](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/consumption-options).

Google recommends that you cover baseline traffic with Provisioned Throughput and let spillover go to Standard or Priority PayGo. For a large backlog, such as millions of documents to summarize, batch is the most cost-effective option ([Consumption options](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/consumption-options)).

## Model Garden: which model, and who runs it

Model Garden is a library to discover, test, customize, and deploy models from Google and partners ([Overview of Model Garden](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-garden/explore-models)). It has three groups of models: Google models (Gemini, Gemma, Veo, Lyria), partner models (Anthropic Claude, Grok, Mistral AI), and open-weight models (DeepSeek, Llama, Qwen) ([Overview of models on Agent Platform](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models)).

The key decision is who runs the model:

| | Model as a Service (MaaS) | Self-deployed model |
|---|---|---|
| Infrastructure | Serverless. You provision nothing. | Runs on an endpoint in your project and VPC network. |
| Billing | Per token (or Provisioned Throughput) | For the compute of the endpoint. Partner models also bill model usage. |
| Use it when | Prototypes, bursty traffic, a team that wants no infrastructure work | Custom or fine-tuned weights, predictable high volume, rules that forbid a multi-tenant service, a specific region or accelerator |

Sources: [Use open models using MaaS](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/open-models/use-maas), [Partner models for MaaS](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/use-partner-models), [Consumption options](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/consumption-options), [Open models overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/open-models/choose-serving-option), [Overview of self-deployed models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-garden/self-deployed-models).

Governance matters for partner models. A Model Garden organization policy controls which models people can use ([Overview of Model Garden](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/model-garden/explore-models)). Google does not share prompts and responses with the partner ([Partner models for MaaS](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/use-partner-models)). The 2.5 page covers enablement, tuning, and serving in detail.

## Grounding and RAG: choose the retrieval layer

Retrieval-augmented generation (RAG) has two stages: retrieve the relevant facts, then let the model generate an answer from them ([Vertex AI APIs for building search and RAG experiences](https://docs.cloud.google.com/generative-ai-app-builder/docs/builder-apis)). The exam tests which retrieval layer fits.

| Option | What it gives you | Use it when |
|---|---|---|
| Grounding with Google Search | Answers grounded in the public web. No retrieval infrastructure. | The answer needs fresh public information. |
| Web Grounding for Enterprise | A curated web index. No logging of customer data. Supports VPC Service Controls. | A regulated company (finance, healthcare, public sector) needs web grounding with compliance controls. |
| Agent Search (formerly Vertex AI Search) | An out-of-the-box semantic and keyword search engine for RAG, with connectors to BigQuery and third-party systems | You want Google-quality search over your content with the least build work. |
| RAG Engine | A managed RAG framework: ingest, chunk, embed, index (a corpus), and retrieve | You want to control the RAG pipeline but not operate each part. |
| Vector Search | An approximate nearest neighbor (ANN) engine that scales to billions of vectors | You build your own retrieval with your own embeddings, or you build semantic search and recommendations. |
| Agent Retrieval (formerly Vector Search 2.0) | A fully managed, self-tuning store of data objects with built-in embeddings | You want vector search without managing indexes, VMs, or replicas. |
| Grounding with your search API or Elasticsearch | Your existing search engine as the retriever | You already run a search engine. |

Sources: [Grounding overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/overview), [Web Grounding for Enterprise](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/web-grounding-enterprise), [Vertex AI APIs for building search and RAG experiences](https://docs.cloud.google.com/generative-ai-app-builder/docs/builder-apis), [RAG Engine overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview), [Vector Search](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search/overview), [Agent Retrieval](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview).

Check the security controls before you choose. RAG Engine supports VPC Service Controls and CMEK, but not data residency or Access Transparency ([RAG Engine overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview)). Grounding with Google Search keeps reliability logs for up to 3 days. Web Grounding for Enterprise does not store customer data ([Web Grounding for Enterprise](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/web-grounding-enterprise)).

## BigQuery ML: ML where the data lives

BigQuery ML lets SQL users build models and get results from LLMs and Cloud AI APIs with SQL. It removes the need to move data out of the warehouse ([Introduction to ML in BigQuery](https://docs.cloud.google.com/bigquery/docs/bqml-introduction)). Remote models call models deployed on Agent Platform, and those calls also bill Agent Platform charges ([Introduction to ML in BigQuery](https://docs.cloud.google.com/bigquery/docs/bqml-introduction)).

Choose BigQuery ML when all the data is in BigQuery, the team is comfortable with SQL, and a BigQuery ML model type fits the problem ([Best practices for implementing machine learning on Google Cloud](https://docs.cloud.google.com/architecture/ml-on-gcp-best-practices)). BigQuery ML supports only batch predictions. For online predictions, register the model in Model Registry and deploy it to an Agent Platform endpoint ([Agent Platform for BigQuery users](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/beginner/bqml)). For more on BigQuery, see [Choosing data processing solutions](note:1.3-data-processing).

## AI Hypercomputer and Gemini Enterprise in brief

**AI Hypercomputer** combines three parts. The first is performance-optimized infrastructure: NVIDIA GPUs, Cloud TPUs, networking, and storage. The second is open software, such as PyTorch, JAX, and TensorFlow, plus orchestration. The third is flexible consumption options ([AI Hypercomputer overview](https://docs.cloud.google.com/ai-hypercomputer/docs/overview)). Choose it when you train or serve your own large models. You do not need it when you call Gemini as a managed API. See [AI Hypercomputer: accelerators and consumption models](note:2.4-ai-hypercomputer).

**Gemini Enterprise** is an intranet search, AI assistant, and agentic platform for knowledge workers. It gives employees one search interface with permissions-aware access to company data, and it has prebuilt connectors for Confluence, Jira, Microsoft SharePoint, and ServiceNow. It can also host custom agents, and developers can use its APIs to add search and assistant features ([What is Gemini Enterprise?](https://docs.cloud.google.com/gemini/enterprise/docs)). Gemini Enterprise is also the parent product of Gemini Notebook Enterprise ([What is Gemini Notebook Enterprise?](https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/overview)). Developers build agents on Agent Platform, and employees use them in the Gemini Enterprise app ([Introducing Gemini Enterprise Agent Platform](https://cloud.google.com/blog/products/ai-machine-learning/introducing-gemini-enterprise-agent-platform)).

## Responsible AI

Agent Platform generative AI APIs follow Google's AI Principles. They have built-in content filtering and safety attribute scoring, and you set the thresholds for your use case ([Responsible AI](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/responsible-ai)). The customer still owns testing. Google recommends four steps: assess security risks, run safety tests for your use case, configure safety filters, and collect user feedback while you monitor content ([Responsible AI](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/responsible-ai)).

Two points often decide exam answers:

- For specialized use cases that can affect individual rights, Google says that meaningful human supervision must exist ([Responsible AI](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/responsible-ai)). A human-in-the-loop review step satisfies this.
- If an application renders model output as HTML or Markdown, sanitize the output and use Content Security Policy headers. These steps help protect users from indirect prompt injection and data exfiltration ([Responsible AI](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/responsible-ai)).

Model Armor, Sensitive Data Protection, and secure model deployment are in [Securing AI workloads](note:3.1-securing-ai).

## Case study angles

- [Cymbal Retail](case:cymbal) wants gen AI to derive product attributes from supplier titles, descriptions, and images, with a human review step. A Gemini multimodal prompt with structured output fits step 2 of the ladder. A batch job fits a large backlog of products ([Consumption options](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/consumption-options)). For image variations, use Gemini image models: Gemini supports improved image editing and multi-turn editing ([Edit images with Gemini](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/gemini-edit-images)).
- [Altostrat Media](case:altostrat) wants summaries and metadata from audio and video, plus chatbots. Gemini understands video content in a request ([Video understanding](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/video-understanding)). A chatbot that must answer from the media library needs grounding, for example with Agent Search.
- [KnightMotives Automotive](case:knightmotives) says that its current AI infrastructure is obsolete. Its autonomous driving work needs cutting-edge AI and ML and a simulation environment. That is custom training at scale, so the answer is AI Hypercomputer, not a pre-trained API.

## Exam traps

- **Custom training for a common task.** If a pre-trained API or a Gemini prompt meets the need, custom training is the over-engineered answer. Google recommends managed services and pre-trained models to control cost ([AI and ML perspective: Cost optimization](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/cost-optimization)).
- **Tuning to add changing facts.** Tuning teaches skills. For facts that change, ground the model with RAG or search ([Introduction to tuning](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/tuning), [Grounding overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/overview), [Grounding with Google Search](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-google-search)).
- **The global endpoint for a data residency requirement.** The global endpoint gives no residency guarantee. Use a regional or US/EU multi-region endpoint ([Data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency)).
- **Provisioned Throughput for bursty traffic.** If traffic has spikes, it can leave reserved capacity unused. Cover only the steady baseline with it ([Consumption options](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/consumption-options)).
- **Pro tier for simple, high-volume work.** Flash-Lite is the most cost-efficient tier for high-volume, cost-sensitive traffic ([Google models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/google-models)).
- **RAG Engine when data residency is mandatory.** RAG Engine does not support data residency controls ([RAG Engine overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview)).
- **"Agent Builder" read too literally.** The name covered both the agent tools and the search product. Map the requirement, not the name ([Agent Search](https://docs.cloud.google.com/generative-ai-app-builder/docs)).
- **Gemini Enterprise to build, deploy, and govern custom agents.** Use Agent Platform for that. Technical teams build agents on Agent Platform and deliver them to employees through the Gemini Enterprise app ([Agent Platform overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/overview), [Introducing Gemini Enterprise Agent Platform](https://cloud.google.com/blog/products/ai-machine-learning/introducing-gemini-enterprise-agent-platform)).
