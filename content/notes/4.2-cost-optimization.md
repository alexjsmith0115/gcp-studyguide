## Why it matters

An architect chooses the pricing model, the discount, and the guardrails for each workload. The exam gives a spend pattern and a risk, and asks which cost lever fits. Wrong answers often use a real tool for the wrong job. Examples are a budget as a spending cap, or a resource-based commitment for a fleet that changes.

## Key points

- On premises, you buy assets (CapEx) and depreciate them. In the cloud, most resource costs are OpEx: you pay when you consume ([Cost optimization pillar](https://docs.cloud.google.com/architecture/framework/cost-optimization)).
- Compute Engine applies sustained use discounts (SUDs) automatically, but only to some machine series: N1, N2, N2D, C2, M1, M2, and sole-tenant nodes. Only self-serve Cloud Billing accounts get SUDs ([Sustained use discounts](https://docs.cloud.google.com/compute/docs/sustained-use-discounts)).
- Committed use discounts (CUDs) give a lower price for a 1-year or 3-year commitment. Resource-based CUDs commit to Compute Engine resources in one region. Compute flexible CUDs commit to an hourly spend across Compute Engine, GKE, and Cloud Run ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
- You can't cancel a resource-based commitment. A commitment doesn't reserve capacity; a reservation does ([Resource-based CUDs](https://docs.cloud.google.com/compute/docs/instances/signing-up-committed-use-discounts)).
- Spot VMs cost much less than standard VMs. Compute Engine can preempt them at any time, and no SLA covers them ([Spot VMs](https://docs.cloud.google.com/compute/docs/instances/spot)).
- An alerts-only budget doesn't cap spend. Spend cap budgets (Preview) pause usage only for a few API-based services ([Budgets and budget alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets), [Spend cap budgets](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps)).
- Labels flow into billing data, so you can report cost by team or environment ([Labels overview](https://docs.cloud.google.com/resource-manager/docs/labels-overview)).
- Active Assist recommenders find idle and oversized resources. The FinOps hub shows savings and opportunities on one dashboard ([FinOps hub](https://docs.cloud.google.com/billing/docs/how-to/finops-hub)).
- Quotas limit consumption, but API request caps are not a project-wide spending cap ([Capping API usage](https://docs.cloud.google.com/apis/docs/capping-api-usage)).
- BigQuery bills queries per TiB scanned (on-demand) or per slot-hour (capacity pricing with editions) ([BigQuery pricing](https://cloud.google.com/bigquery/pricing)).

## CapEx, OpEx, and the cost pillar

Cloud cost follows consumption, so cost control moves from purchase approval to design and daily operations. The cost pillar says that on-premises costs include CapEx and OpEx, and that most cloud resource costs are OpEx. Some services, such as Compute Engine sole-tenant nodes, can be classified as CapEx ([Cost optimization pillar](https://docs.cloud.google.com/architecture/framework/cost-optimization)).

A commitment changes this picture. You pay a monthly commitment fee for the full term, whether you use the resources or not ([Committed use discounts](https://docs.cloud.google.com/docs/cuds)). A CUD trades flexibility for a lower unit price. Commit only to the part of the load that you are sure of.

The cost pillar has four principles. Use them to explain an answer in business terms.

| Principle | What it means for a design |
|---|---|
| Align cloud spending with business value | Prefer managed and serverless services. Measure unit cost (for example, cost per customer or per transaction) and TCO, not only upfront cost. |
| Foster a culture of cost awareness | Give teams cost data: a standard label set, shared cost reports, and cost estimates in architecture blueprints. |
| Optimize resource usage | Match resources to the environment and the workload. Use autoscaling with maximum limits, Spot VMs for non-critical work, organization policies that limit locations and products, and budgets and quotas as boundaries. |
| Optimize continuously | Watch business metrics (user experience, business outcomes, DORA, SRE error budgets) and adjust resources as needs change. |

Sources: [Align spending with business value](https://docs.cloud.google.com/architecture/framework/cost-optimization/align-cloud-spending-business-value), [Foster a culture of cost awareness](https://docs.cloud.google.com/architecture/framework/cost-optimization/foster-culture-cost-awareness), [Optimize resource usage](https://docs.cloud.google.com/architecture/framework/cost-optimization/optimize-resource-usage), [Optimize continuously](https://docs.cloud.google.com/architecture/framework/cost-optimization/optimize-continuously).

For the other pillars, see [The Well-Architected Framework](note:1.2-well-architected-framework). For migration TCO and license costs, see [Licensing and financial impact of a migration](note:1.4-licensing-and-financials).

## Pricing levers for compute

| Lever | How you get it | Use it when | Watch out |
|---|---|---|---|
| On-demand | Default. You pay for what you use. | Load is new, short, or unpredictable. | Highest unit price. |
| Sustained use discounts | Automatic when a resource runs more than 25% of a billing month. | Steady VMs in an eligible series. | Only N1, N2, N2D, C2, M1, M2, and sole-tenant nodes. Not on usage that a CUD covers. Only for self-serve billing accounts. |
| Resource-based CUD | Commit to vCPUs, memory, GPUs, Local SSD, or licenses in one region, for 1 or 3 years. | Steady usage of a known machine series and region. | You can't cancel it. It doesn't reserve capacity. |
| Compute flexible CUD | Commit to an hourly spend on the billing account, for 1 or 3 years. | Steady total spend that moves across regions, machine series, GKE, and Cloud Run. | Doesn't apply to Spot VMs. Memory-optimized VMs get a discount only on the 3-year term. |
| Spot VMs | Create VMs with the Spot provisioning model. | Fault-tolerant work such as batch jobs. | Preemption at any time. No SLA. |

Sources: [Sustained use discounts](https://docs.cloud.google.com/compute/docs/sustained-use-discounts), [CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview), [Resource-based CUDs](https://docs.cloud.google.com/compute/docs/instances/signing-up-committed-use-discounts), [Spot VMs](https://docs.cloud.google.com/compute/docs/instances/spot).

How the discounts combine:

1. A resource gets only one kind of discount at a time. Discounts don't stack ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
2. Each hour, Google Cloud applies resource-based commitments first, then compute flexible commitments. The rest is charged at on-demand rates, and that usage can still earn SUDs ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
3. Use resource-based CUDs for stable usage in a known project, region, and machine configuration. Use compute flexible CUDs for usage that isn't tied to one region, project, or machine configuration ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
4. With CUD sharing on, a resource-based CUD covers eligible usage in all projects of the billing account. New billing accounts created on or after June 16, 2026 have sharing on by default ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
5. If you need guaranteed capacity in a zone, create a reservation and attach it to the commitment. GPU commitments require attached reservations ([Resource-based CUDs](https://docs.cloud.google.com/compute/docs/instances/signing-up-committed-use-discounts)).

Size a commitment from data. The CUD recommender analyzes the previous 30 days of usage. It has a "stable usage" model and an "optimal savings" model. Google's example: with a 30% discount, an instance must run more than 70% of the month to break even ([CUD recommendations](https://docs.cloud.google.com/docs/cuds-recommender)).

Many managed services have their own spend-based CUDs, for example Cloud SQL, Spanner, Bigtable, BigQuery, and Memorystore. A service-specific commitment covers spend only inside that service ([Committed use discounts](https://docs.cloud.google.com/docs/cuds)).

For Spot VM configuration and machine family choice, see [Choosing compute resources](note:1.3-compute-resources).

## Resource optimization before discounts

A discount on an idle resource still wastes money. Remove waste first, then commit to what remains. Built-in options include Compute Engine autoscaling and custom machine types, GKE Autopilot bin packing, and Cloud Storage Object Lifecycle Management and Autoclass ([Optimize resource usage](https://docs.cloud.google.com/architecture/framework/cost-optimization/optimize-resource-usage)). Instance schedules start and stop VMs on a timetable, for example only during working hours ([Instance schedules](https://docs.cloud.google.com/compute/docs/instances/schedule-instance-start-stop)).

### Active Assist recommenders

| Recommender | What it looks at | Limits to know |
|---|---|---|
| VM machine type (rightsizing) | CPU and memory use over the previous 8 days | Less suited to workloads that spike rarely, such as monthly peaks. Not shown when the saving is very small. |
| Idle VM | CPU and network use over 1 to 14 days (default 14) | Not for VMs with GPUs, TPUs, or Local SSD, or for GKE and Dataflow VMs. |
| Idle disk, IP address, and image; Cloud SQL idle and overprovisioned instance | Unused or oversized resources | Back up a disk before you delete it. |
| Unattended project | Project use over the last 30 days | Review, delete, or reclaim the project. |
| CUD (resource-based and spend-based) | Usage and spend over the previous 30 days | Recommends commitment amounts. |

Sources: [Machine type recommendations](https://docs.cloud.google.com/compute/docs/instances/apply-machine-type-recommendations-for-instances), [Idle VM recommendations](https://docs.cloud.google.com/compute/docs/instances/idle-vm-recommendations-overview), [Recommenders](https://docs.cloud.google.com/recommender/docs/recommenders), [Unattended project recommender](https://docs.cloud.google.com/recommender/docs/unattended-project-recommender), [CUD recommendations](https://docs.cloud.google.com/docs/cuds-recommender).

Google warns that a reviewer must assess the impact before anyone applies a recommendation. If you apply recommendations without human review, set up a rollback process first ([Active Assist](https://docs.cloud.google.com/recommender/docs/whatis-activeassist)).

### FinOps hub

The FinOps hub puts active savings and optimization opportunities on one dashboard. It uses data from Cloud Billing and Recommender ([FinOps hub](https://docs.cloud.google.com/billing/docs/how-to/finops-hub)). It shows:

- A FinOps score for practices such as labels, budgets, CUD purchases, and billing export.
- Potential savings per month, and the top 10 recommendations.
- Potential wasted usage (Preview).
- Insights from [Gemini Cloud Assist](note:1.2-gemini-cloud-assist).

For the full FinOps hub, you need Billing Account Viewer or Billing Account Administrator on the billing account ([FinOps hub](https://docs.cloud.google.com/billing/docs/how-to/finops-hub)).

## Budgets, alerts, and automated responses

A budget tracks actual spend against planned spend. Threshold rules send email when actual or forecasted cost passes a percentage of the budget ([Budgets and budget alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets)). The key facts:

- An alerts-only budget doesn't prevent the use or billing of services. Cost data arrives with a delay, so Google recommends a budget amount below your available funds. Budgets with a custom time range can't alert on forecasted cost ([Budgets and budget alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets)).
- Pub/Sub notifications arrive multiple times per day with the current budget status. Delivery is at-least-once, so your handler must accept duplicates and out-of-order messages ([Programmatic notifications](https://docs.cloud.google.com/billing/docs/how-to/budgets-programmatic-notifications)).

Choose the control by the need:

| Need | Use | Behavior |
|---|---|---|
| Warn owners early | Alerts-only budget with actual and forecasted threshold rules | Sends email. Doesn't stop anything. |
| Run code when spend is high (chat message, stop VMs) | Budget with a Pub/Sub topic and a Cloud Run function (formerly Cloud Functions) | Your code decides the action. You can stop some resources and keep data. |
| Hard stop for a sandbox project | Budget notification that disables billing on the project | Stops all services, including Free Tier. Resources might be deleted and can't always be recovered. |
| Stop a runaway Gemini API, Agent Platform (formerly Vertex AI), Cloud Run, or Cloud Run functions service | Spend cap budget (Preview) | One project and one service. Pauses new usage until you lift the cap. Doesn't pause persistent resources. |
| Limit how much of a resource or API a project uses | Quota (set a lower value) | Limits usage, not money. Enforcement has some latency. |
| Daily limit on BigQuery on-demand bytes | Custom query quotas | Proactive: a query that exceeds the quota doesn't run. The quota is approximate. |
| Find unusual spikes | Cost anomaly detection | Compares spend with historical patterns. |

Sources: [Control resource usage with notifications](https://docs.cloud.google.com/billing/docs/how-to/control-usage), [Disable billing usage with notifications](https://docs.cloud.google.com/billing/docs/how-to/disable-billing-with-notifications), [Spend cap budgets](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps), [Capping API usage](https://docs.cloud.google.com/apis/docs/capping-api-usage), [Custom query quotas](https://docs.cloud.google.com/bigquery/docs/custom-quotas), [Cost anomalies](https://docs.cloud.google.com/billing/docs/how-to/manage-anomalies).

The cost pillar recommends quotas together with budgets and monitoring as a layered control. It also recommends maximum limits on autoscaling, so that costs stay inside budgets ([Optimize resource usage](https://docs.cloud.google.com/architecture/framework/cost-optimization/optimize-resource-usage)).

## Cost allocation: labels, projects, and billing export

Chargeback needs three things: a unit of ownership, a label standard, and raw cost data.

1. **Projects and budget scope.** A budget can apply to a whole billing account, or to organizations, folders, projects, services, or resources with one label. Label scope is available only for billing-account-level budgets ([Budgets and budget alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets)).
2. **Labels.** A label is a key-value pair on a resource. Cloud Billing receives the label, so you can break down charges by label. A resource can have up to 64 labels ([Labels overview](https://docs.cloud.google.com/resource-manager/docs/labels-overview)). Use keys such as `costcenter`, `service`, and `environment`. Enforce them with automation such as Terraform ([Foster a culture of cost awareness](https://docs.cloud.google.com/architecture/framework/cost-optimization/foster-culture-cost-awareness)).
3. **Billing export to BigQuery.** The export writes usage, cost, and pricing data to a dataset throughout the day ([Export Cloud Billing data](https://docs.cloud.google.com/billing/docs/how-to/export-data-bigquery)).

| Export type | Contents | Use it for |
|---|---|---|
| Standard usage cost | Account, services, SKUs, projects, labels, locations, cost, credits | Broad cost trends |
| Detailed usage cost | Standard data plus resource-level cost | Find the resources that drive cost |
| Pricing data | Your SKU prices and tiers | Join with usage to explain charges |
| FOCUS usage cost (Preview) | Detailed data in the FinOps Open Cost and Usage Specification | Cost data in an open, standard format |

Source: [Export Cloud Billing data](https://docs.cloud.google.com/billing/docs/how-to/export-data-bigquery).

Timing matters for labels and exports:

- A billing report shows cost for a label only from the time you add the label to the resource ([Billing reports](https://docs.cloud.google.com/billing/docs/how-to/reports)).
- A multi-region (US or EU) export dataset gets data back to the start of the previous month. A regional dataset gets data only from the day you enable the export. Enable the export early ([Export Cloud Billing data](https://docs.cloud.google.com/billing/docs/how-to/export-data-bigquery), [Set up billing export](https://docs.cloud.google.com/billing/docs/how-to/export-data-bigquery-setup)).
- Put the export dataset and billing Pub/Sub topics in a dedicated FinOps administration project ([Set up billing export](https://docs.cloud.google.com/billing/docs/how-to/export-data-bigquery-setup), [Programmatic notifications](https://docs.cloud.google.com/billing/docs/how-to/budgets-programmatic-notifications)).

Labels are not tags: only tags can be conditions in policies ([Labels overview](https://docs.cloud.google.com/resource-manager/docs/labels-overview)).

## Cloud Billing IAM

Billing roles live on the Cloud Billing account (or the organization), not only on projects. Grant the smallest role that does the job ([Cloud Billing access control](https://docs.cloud.google.com/billing/docs/how-to/billing-access)).

| Role | Typical holder | Can do |
|---|---|---|
| Billing Account Administrator (`roles/billing.admin`) | Billing owners | Manage the account, payment, exports, users, and project links. Purchase spend-based CUDs. |
| Billing Account Costs Manager (`roles/billing.costsManager`) | FinOps team | Manage budgets. View and export cost data, but not pricing data. Can't link projects. |
| Billing Account Viewer (`roles/billing.viewer`) | Finance team | Read cost and payment information. |
| Billing Account User (`roles/billing.user`) | Project creators | Link projects to the account, together with Project Creator or Project Billing Manager. |
| Project Billing Manager (`roles/billing.projectManager`) | Project owners | Link or unlink a project. Gives no rights over resources. |
| Project Billing Costs Manager (`roles/billing.projectCostsManager`) | Project teams | See reports, budgets, and FinOps hub scoped to projects where they have cost view access. |
| Billing Account Creator (`roles/billing.creator`) | Very few people | Create self-serve billing accounts. |

Sources: [Cloud Billing access control](https://docs.cloud.google.com/billing/docs/how-to/billing-access), [Spend-based CUDs](https://docs.cloud.google.com/docs/cuds-spend-based).

## BigQuery pricing in brief

| | On-demand | Capacity (editions) |
|---|---|---|
| Unit | TiB scanned | Slot-hours |
| Capacity | Up to 2,000 slots per project | Reservations of dedicated or autoscaling slots |
| Cost control | Project-level or user-level daily query quotas (hard cap) | Maximum slots per reservation |
| Discounts | Pay-as-you-go only | 1-year or 3-year slot commitments (Enterprise and Enterprise Plus only). Spend-based BigQuery CUDs on pay-as-you-go slots in any edition. |
| Predictability | Variable | Predictable through baselines and commitments |

Sources: [Reservations introduction](https://docs.cloud.google.com/bigquery/docs/reservations-intro), [BigQuery pricing](https://cloud.google.com/bigquery/pricing), [BigQuery CUDs](https://docs.cloud.google.com/bigquery/docs/bigquery-cud).

The three editions are Standard, Enterprise, and Enterprise Plus. You can use editions and on-demand at the same time, per project ([BigQuery editions](https://docs.cloud.google.com/bigquery/docs/editions-intro)). Custom query quotas apply only to the on-demand model ([Custom query quotas](https://docs.cloud.google.com/bigquery/docs/custom-quotas)). For partitioning, clustering, and query design, see [Choosing data processing solutions](note:1.3-data-processing).

## Exam traps

- **"Set a budget so that spend stops at the limit."** An alerts-only budget only notifies ([Budgets and budget alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets)).
- **"Disable billing when the budget is exceeded" for a production project.** This stops all services, and resources might be deleted. Stop selected resources instead ([Disable billing usage with notifications](https://docs.cloud.google.com/billing/docs/how-to/disable-billing-with-notifications)).
- **"Buy a resource-based CUD to guarantee capacity."** A commitment doesn't reserve capacity. Combine it with a reservation ([Resource-based CUDs](https://docs.cloud.google.com/compute/docs/instances/signing-up-committed-use-discounts)).
- **"Buy resource-based CUDs" for a fleet that changes region or machine series, or moves to Cloud Run.** Compute flexible CUDs follow the spend ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
- **"Cover the Spot VM fleet with a flexible CUD."** Flexible commitments don't apply to Spot VMs ([CUDs for Compute Engine](https://docs.cloud.google.com/compute/docs/instances/committed-use-discounts-overview)).
- **"The E2 fleet runs all month, so it gets SUDs."** SUDs apply only to the listed series ([Sustained use discounts](https://docs.cloud.google.com/compute/docs/sustained-use-discounts)).
- **"Rightsize from recommendations" for a workload with a monthly peak.** 8 days of data can miss the peak ([Machine type recommendations](https://docs.cloud.google.com/compute/docs/instances/apply-machine-type-recommendations-for-instances)).
- **"Add team labels now to report last quarter's cost by team."** Reports show label cost only from the time you add the label ([Billing reports](https://docs.cloud.google.com/billing/docs/how-to/reports)).
- **"Use API quotas as the project spending cap."** Request caps are not designed for that ([Capping API usage](https://docs.cloud.google.com/apis/docs/capping-api-usage)).
- **"Give finance Billing Account Administrator to see costs."** Billing Account Viewer is enough ([Cloud Billing access control](https://docs.cloud.google.com/billing/docs/how-to/billing-access)).
