## Why it matters

Before code can call a Google Cloud API, the API must be enabled in the right project and the code needs credentials. A developer chooses the client: a Cloud Client Library, REST, gRPC, or the Google APIs Explorer (the exam guide says API Explorer) for tests. The developer also chooses the identity: an attached service account, impersonation, or user credentials for local work. The exam tests the recommended choices and the errors that follow from a wrong project, a disabled service, or a missing quota project.

## Key points

- You must enable most Google APIs in a Google Cloud project before you use them. Some APIs are enabled by default in a new project ([Service Usage overview](https://docs.cloud.google.com/service-usage/docs/overview)).
- `gcloud services enable SERVICE` enables a service in the current project. You need the Service Usage Admin role ([Enable and disable services](https://docs.cloud.google.com/service-usage/docs/enable-disable)).
- A call to a disabled service fails with the `ErrorInfo` reason `SERVICE_DISABLED`. The metadata names the consumer project and the service ([Enum ErrorReason](https://docs.cloud.google.com/java/docs/reference/proto-google-common-protos/latest/com.google.api.ErrorReason)).
- The project that is checked for API activation is the same project that is checked for rate quota ([Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)).
- Cloud Client Libraries are the recommended way to call Google Cloud APIs from code. The older Google API Client Libraries support only REST ([Client libraries and Cloud APIs explained](https://docs.cloud.google.com/apis/docs/client-libraries-explained)).
- Every Google Cloud API has a JSON/REST interface. A gRPC-enabled API also has an RPC interface ([Client libraries and Cloud APIs explained](https://docs.cloud.google.com/apis/docs/client-libraries-explained)).
- Client libraries find credentials automatically with Application Default Credentials (ADC) ([Authenticate with client libraries](https://docs.cloud.google.com/docs/authentication/client-libraries)).
- In production on Google Cloud, attach a service account to the resource. ADC gets its credentials from the metadata server ([How Application Default Credentials works](https://docs.cloud.google.com/docs/authentication/application-default-credentials)).
- Service account impersonation is more secure than a service account key. The caller needs the Service Account Token Creator role on the service account ([Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation)).
- A resource-based API uses the project of the resource for quota. A client-based API uses a quota project that you can set ([Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)).
- The APIs Explorer calls real API methods from the reference docs, with its own credentials and JSON only ([APIs Explorer overview](https://developers.google.com/explorer-help)).
- A regional endpoint (`SERVICE.REGION.rep.googleapis.com`) processes and ends TLS for the request in one region ([Google Cloud API endpoint overview](https://docs.cloud.google.com/docs/security/compliance/endpoints)).

## Enable services

Service Usage is the API that lists, enables, and disables services. You can use it from the console, the gcloud CLI, or the Service Usage API ([Service Usage overview](https://docs.cloud.google.com/service-usage/docs/overview)).

```bash
gcloud services enable bigquery.googleapis.com pubsub.googleapis.com

curl -X POST \
    -H "Authorization: Bearer $(gcloud auth print-access-token)" \
    -H "Content-Type: application/json; charset=utf-8" \
    -d "" \
    "https://serviceusage.googleapis.com/v1/projects/PROJECT_ID/services/SERVICE:enable"
```

Source: [Enable and disable services](https://docs.cloud.google.com/service-usage/docs/enable-disable).

One `gcloud services enable` command can enable several services. The `services.batchEnable` method enables up to 20 services in one operation. Some APIs ask you to accept terms of service first ([Enable and disable services](https://docs.cloud.google.com/service-usage/docs/enable-disable)). Enabling services at other levels of the resource hierarchy is in Preview ([Service Usage overview](https://docs.cloud.google.com/service-usage/docs/overview)).

### Disable services with care

| Service that you disable | What happens |
|---|---|
| Cloud Storage, BigQuery | The data stays, and you continue to pay for storage. Delete the data first to stop charges |
| Cloud Run | Cloud Run deletes the resources of the service |
| Kubernetes Engine | Running clusters are suspended. Google deletes them after 30 days |
| A service that other enabled services depend on | The request fails, unless you set `disableDependentServices` to `true` |

Source: [Enable and disable services](https://docs.cloud.google.com/service-usage/docs/enable-disable).

### The SERVICE_DISABLED error

To call a Google API, you need a project, the service enabled in that project, and an API key or OAuth access token for that project ([Troubleshoot issues (Service Usage)](https://docs.cloud.google.com/service-usage/docs/troubleshooting)). If the service is disabled, the error has this `ErrorInfo` ([Enum ErrorReason](https://docs.cloud.google.com/java/docs/reference/proto-google-common-protos/latest/com.google.api.ErrorReason)):

```json
{ "reason": "SERVICE_DISABLED",
  "domain": "googleapis.com",
  "metadata": { "consumer": "projects/123", "service": "pubsub.googleapis.com" } }
```

Source: [Enum ErrorReason](https://docs.cloud.google.com/java/docs/reference/proto-google-common-protos/latest/com.google.api.ErrorReason).

Enable the service in the project that the `consumer` field names. That project is not always the project of the resource. For example, a service account from project A reads data in project B, and neither project has the API enabled. The error names the project that is checked for activation ([Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)). The next section on the quota project explains which project that is.

## Choose how to call the API

| Option | Use it when | Know this |
|---|---|---|
| Cloud Client Libraries | You write application code. This is the default choice | Idiomatic code, built-in authentication, and gRPC for some APIs |
| Google API Client Libraries | No Cloud Client Library exists for your language or API, or the project already uses them | REST only. No gRPC |
| REST with an HTTP client | The client libraries do not meet your needs, or you write a quick script or test | Send an OAuth 2.0 access token in the `Authorization: Bearer` header |
| gRPC with your own generated client | The API is gRPC-enabled and the client libraries do not fit your needs | Generate the client from the API's protocol buffer definitions |
| APIs Explorer | You want to try one method from its reference page | Acts on real data. Uses its own credentials. JSON only |

Sources: [Client libraries and Cloud APIs explained](https://docs.cloud.google.com/apis/docs/client-libraries-explained), [Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest), [APIs Explorer overview](https://developers.google.com/explorer-help).

Cloud Client Libraries for some gRPC-enabled APIs use gRPC internally. Accessing an API with gRPC can increase throughput per CPU by as much as a factor of 10 compared to the JSON REST API ([Client libraries and Cloud APIs explained](https://docs.cloud.google.com/apis/docs/client-libraries-explained)).

### Cloud Client Libraries with ADC

The code does not contain credentials. The library finds them with ADC:

```python
from google.cloud import storage

# Credentials are not specified, so the client library uses ADC.
storage_client = storage.Client(project=project_id)
buckets = storage_client.list_buckets()
for bucket in buckets:
    print(bucket.name)
```

Source: [Authenticate with client libraries](https://docs.cloud.google.com/docs/authentication/client-libraries).

### REST with an access token

For local work, use the token of your gcloud CLI user credentials. In production, ADC is the preferred source. On Cloud Run, GKE, Compute Engine, App Engine, Cloud Run functions, and Cloud Build, code can also ask the metadata server for a token ([Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest)).

```bash
curl -X GET \
    -H "Authorization: Bearer $(gcloud auth print-access-token)" \
    "https://cloudresourcemanager.googleapis.com/v3/projects/PROJECT_ID"

# Inside Cloud Run, GKE, or Compute Engine:
curl "http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token" \
    -H "Metadata-Flavor: Google"
```

Source: [Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest).

The metadata server returns JSON with `access_token`, `expires_in`, and `token_type` ([Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest)). [Efficient and resilient API calls](note:4.2-efficient-api-calls) covers field selection, pagination, batching, and retries for these calls.

## Credentials for API calls

ADC looks for credentials in this order. The order does not say which source is best ([How Application Default Credentials works](https://docs.cloud.google.com/docs/authentication/application-default-credentials)):

1. The file that the `GOOGLE_APPLICATION_CREDENTIALS` environment variable points to.
2. The local file that `gcloud auth application-default login` creates.
3. The attached service account, from the metadata server.

| Where the code runs | Recommended credential | How to set it up |
|---|---|---|
| Cloud Run, GKE, Compute Engine, and other Google Cloud runtimes | The attached service account | Attach a service account to the resource that runs the code |
| Your workstation | Your user credentials, or an impersonated service account | `gcloud auth application-default login`, optionally with `--impersonate-service-account` |
| Anywhere | Not a service account key | A leaked key works for anyone. Use impersonation or the attached service account |

Sources: [How Application Default Credentials works](https://docs.cloud.google.com/docs/authentication/application-default-credentials), [Authenticate with client libraries](https://docs.cloud.google.com/docs/authentication/client-libraries), [Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation).

Tokens from a local ADC file with user credentials have the `cloud-platform` scope by default ([How Application Default Credentials works](https://docs.cloud.google.com/docs/authentication/application-default-credentials)).

### Service account impersonation

Impersonation needs an authenticated identity first, and the credentials that it makes do not persist. A service account key needs no prior authentication and is a high-risk credential if someone gets it ([Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation)).

1. Enable the Service Account Credentials API in your project.
2. Get the Service Account Token Creator role (`roles/iam.serviceAccountTokenCreator`) on the service account. A user needs it even with the Owner role.
3. Use impersonation for one gcloud command, or for ADC.

Sources: [Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation), [Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest).

```bash
gcloud storage buckets list --impersonate-service-account=SERVICE_ACCT_EMAIL
gcloud auth application-default login --impersonate-service-account SERVICE_ACCT_EMAIL
curl -X GET \
    -H "Authorization: Bearer $(gcloud auth print-access-token --impersonate-service-account=PRIV_SA)" \
    "https://cloudresourcemanager.googleapis.com/v3/projects/PROJECT_ID"
```

Sources: [Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation), [Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest).

ADC with impersonation works in the client libraries for C#, Go, Java, Node.js, and Python ([Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation)). [Authenticating code to Google Cloud](note:1.2-authenticating-to-google-cloud) covers Workload Identity Federation and tokens. [Service accounts, IAM roles, and least privilege](note:1.2-service-accounts-least-privilege) covers the roles to grant.

## The quota project

Every request counts against a quota, and quotas are enforced per project. So every request needs a quota project ([Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)).

| API type | Quota project | Can you change it? |
|---|---|---|
| Resource-based (for example Compute Engine) | The project that contains the resource | No |
| Client-based (for example Cloud Translation) | The first one found: the project in the request, the API key's project, sometimes the gcloud CLI shared project, the service account's project, or the workforce pool user project | Yes |

Source: [Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project).

If no quota project is found for a client-based API, the request fails ([Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)). Set it in one of these ways. The first one in the list wins ([Set the quota project](https://docs.cloud.google.com/docs/quotas/set-quota-project)):

1. In code, with the client options of the client library.
2. With the `GOOGLE_CLOUD_QUOTA_PROJECT` environment variable (C#, Go, Java, Node.js, PHP, and Python).
3. From the credentials: the service account's project, the quota project in the local ADC file, or the API key's project.

For the gcloud CLI, use the `billing/quota_project` property or the `--billing-project` flag. For REST, send the `x-goog-user-project` header. For the local ADC file, run `gcloud auth application-default set-quota-project` ([Set the quota project](https://docs.cloud.google.com/docs/quotas/set-quota-project)). The caller needs the `serviceusage.services.use` permission on the quota project, for example in the Service Usage Consumer role ([Set the quota project](https://docs.cloud.google.com/docs/quotas/set-quota-project)).

A missing or wrong quota project gives errors such as `User credentials not supported by this API`, `API not enabled in the project`, or `No quota project set` ([Troubleshoot quota errors](https://docs.cloud.google.com/docs/quotas/troubleshoot)).

## API keys for Google APIs

Not all Google Cloud APIs accept API keys. Check the documentation of the API first ([Use API keys to access APIs](https://docs.cloud.google.com/docs/authentication/api-keys-use)). Send the key in the `x-goog-api-key` header. The `key` query parameter puts the key in the URL, where URL scans can steal it ([Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest)).

A standard API key associates the request with a project for billing and quota, but it does not identify a principal. An authorization key is bound to a service account and acts like a long-lived access token. Do not use authorization keys in production for APIs that create or manage resources. A default organization policy constraint blocks them ([Manage API keys](https://docs.cloud.google.com/docs/authentication/api-keys)).

In a Cloud Client Library, pass the key in the client options, for example `client_options={"api_key": api_key_string}` in Python ([Authenticate with client libraries](https://docs.cloud.google.com/docs/authentication/client-libraries)). [Calling generative AI APIs](note:4.2-generative-ai-apis) covers keys for the Gemini API.

## API endpoints

| Endpoint type | Format | Use it when |
|---|---|---|
| Global | `SERVICE.googleapis.com` | You want low latency for clients in many places. No data residency |
| Regional | `SERVICE.REGION.rep.googleapis.com` | Requests must be processed in one region. TLS ends in that region |
| Multi-regional | `SERVICE.MULTI_REGION.rep.googleapis.com` | Requests must stay in a jurisdiction, such as `eu` or `us` |
| Private regional | `SERVICE.REGION.p.rep.googleapis.com` | Private Service Connect access |
| Locational | `LOCATION-SERVICE.googleapis.com` | Older format. Regional endpoints are replacing it |

Source: [Google Cloud API endpoint overview](https://docs.cloud.google.com/docs/security/compliance/endpoints).

A regional endpoint works only with resources in its region. For example, a Cloud Storage regional endpoint rejects a read of a bucket in another location. To use it with the gcloud CLI, set `gcloud config set api_endpoint_overrides/storage https://storage.LOCATION.rep.googleapis.com/` ([Regional endpoints (Cloud Storage)](https://docs.cloud.google.com/storage/docs/regional-endpoints)). Pub/Sub always routes a request to a regional endpoint to that region. The global endpoint routes a request from Google Cloud to the region where the request starts, and a request from outside Google Cloud to a nearby region ([Pub/Sub APIs overview](https://docs.cloud.google.com/pubsub/docs/reference/service_apis_overview)).

## AWS mapping

| AWS | Google Cloud | Difference that matters |
|---|---|---|
| AWS SDKs | Cloud Client Libraries (Google Cloud SDK) | You must enable each API in the project before the first call |
| AWS CLI | Google Cloud CLI (Google Cloud SDK) | `--impersonate-service-account` runs one command as a service account |
| Amazon Identity and Access Management | Identity and Access Management (IAM) | A user with the Owner role still needs the Service Account Token Creator role to impersonate a service account |

Sources: [Compare AWS and Azure services to Google Cloud](https://docs.cloud.google.com/docs/get-started/aws-azure-gcp-service-comparison), [Service Usage overview](https://docs.cloud.google.com/service-usage/docs/overview), [Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation), [Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest).

## Exam traps

- **The Google API Client Libraries for new code.** Use the Cloud Client Libraries. The older libraries do not support gRPC ([Client libraries and Cloud APIs explained](https://docs.cloud.google.com/apis/docs/client-libraries-explained)).
- **A service account key file in production on Google Cloud.** Attach a service account and let ADC use the metadata server ([How Application Default Credentials works](https://docs.cloud.google.com/docs/authentication/application-default-credentials)).
- **A key file for local tests as a service account.** Use `gcloud auth application-default login --impersonate-service-account` ([Use service account impersonation](https://docs.cloud.google.com/docs/authentication/use-service-account-impersonation)).
- **Owner role, so impersonation works.** A user still needs `iam.serviceAccounts.getAccessToken`, which is in the Service Account Token Creator role ([Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest)).
- **`SERVICE_DISABLED` fixed in the resource project.** Enable the API in the project that the error's `consumer` field names ([Enum ErrorReason](https://docs.cloud.google.com/java/docs/reference/proto-google-common-protos/latest/com.google.api.ErrorReason), [Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)).
- **`No quota project set` with user credentials.** Set a quota project, for example with `x-goog-user-project` or `gcloud auth application-default set-quota-project` ([Troubleshoot quota errors](https://docs.cloud.google.com/docs/quotas/troubleshoot), [Set the quota project](https://docs.cloud.google.com/docs/quotas/set-quota-project)).
- **A changed quota project for Compute Engine calls.** A resource-based API always uses the resource's project ([Quota project overview](https://docs.cloud.google.com/docs/quotas/quota-project)).
- **Disabling the Cloud Run API to stop charges for a test.** It deletes the Cloud Run resources ([Enable and disable services](https://docs.cloud.google.com/service-usage/docs/enable-disable)).
- **The APIs Explorer with your service account credentials.** The APIs Explorer uses its own credentials only ([APIs Explorer overview](https://developers.google.com/explorer-help)).
- **An API key in the `key` query parameter.** Use the `x-goog-api-key` header ([Authenticate with REST](https://docs.cloud.google.com/docs/authentication/rest)).
