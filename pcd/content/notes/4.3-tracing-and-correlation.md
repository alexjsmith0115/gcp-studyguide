## Why it matters

One user request can pass through a load balancer, several Cloud Run or GKE services, and a Pub/Sub topic. A trace ID connects the spans from each service into one trace, and it connects log entries to that trace. The exam tests how the trace context moves between services, and who decides to sample a trace. It also tests which log fields link a log entry to a trace.

## Key points

- A trace is the set of spans that share one trace ID. Each span has its own span ID and the ID of its parent span. The root span has no parent ([Traces and spans](https://docs.cloud.google.com/trace/docs/traces-and-spans)).
- Context propagation sends the trace ID, the parent span ID, and the sampling decision to the next service in request headers or gRPC metadata ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).
- Use the W3C `traceparent` header when possible. Google Cloud services that propagate context typically also accept the legacy `X-Cloud-Trace-Context` header ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).
- Cloud Trace does not propagate context. The Google Cloud services and the applications that send data to Cloud Trace do it ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).
- Cloud Run creates traces for incoming requests and populates `traceparent` automatically. Requests are sampled "at a maximum rate of 0.1 requests per second for each instance (or one request every 10 seconds)". Cloud Run does not support configuration of this sample rate ([Using distributed tracing](https://docs.cloud.google.com/run/docs/trace)).
- Application Load Balancers do not export traces or spans. The global external and classic Application Load Balancers add `X-Cloud-Trace-Context` when it is missing ([External Application Load Balancer overview](https://docs.cloud.google.com/load-balancing/docs/https)).
- Each component makes its own sampling decision. The `sampled` flag in the header passes the parent's decision as a hint ([Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup)).
- Cloud Trace does not support tail-based sampling ([Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling)).
- To link a log entry to a trace, set the `trace`, `spanId`, and `traceSampled` fields. The preferred `trace` format is the trace ID alone ([Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration)).
- The Pub/Sub client libraries can trace each message from publish to acknowledgment. The trace context travels in a message attribute with the `googclient_` prefix ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).

## Traces, spans, and their IDs

| Field | Format | Notes |
|---|---|---|
| Trace ID | 32 hexadecimal characters (a 128-bit number) | The same value in every span of the request |
| Span ID | 16 hexadecimal characters in `traceparent` and in `LogEntry.spanId`. A decimal number in `X-Cloud-Trace-Context` | Each operation gets its own span ID. A repeated operation gets a new span ID each time |
| Parent span ID | The span ID of the caller | `null` for the root span |
| Sampled flag | `01` in `traceparent`. `o=1` in `X-Cloud-Trace-Context` | The sampling decision of the parent |

Sources: [Trace context](https://docs.cloud.google.com/trace/docs/trace-context), [Traces and spans](https://docs.cloud.google.com/trace/docs/traces-and-spans), [LogEntry](https://docs.cloud.google.com/logging/docs/reference/v2/rest/v2/LogEntry).

A span also has a name, a kind, a status, and a start and end time. The status is `Unset` by default, and `Unset` does not mean an error. Attributes are key-value pairs. Google recommends the OpenTelemetry semantic conventions for attribute names ([Traces and spans](https://docs.cloud.google.com/trace/docs/traces-and-spans)).

## Trace context headers

```text
traceparent: VERSION-TRACE_ID-PARENT_SPAN_ID-TRACE_FLAGS
X-Cloud-Trace-Context: TRACE_ID/SPAN_ID;o=OPTIONS
```

Source: [Trace context](https://docs.cloud.google.com/trace/docs/trace-context).

| | `traceparent` (W3C) | `X-Cloud-Trace-Context` (legacy) |
|---|---|---|
| Separators | Hyphens (`-`) | Forward slash (`/`) and semicolon (`;`) |
| Span ID | Hexadecimal | Decimal |
| Sampled | `TRACE_FLAGS` is `01` | `OPTIONS` is `1` |
| Use it | When possible | Only as a fallback. Update an application that supports only this header |

Source: [Trace context](https://docs.cloud.google.com/trace/docs/trace-context).

- **`tracestate`.** This optional W3C header carries vendor-specific data. `traceparent` carries the identifiers ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).
- **gRPC.** gRPC sends the context in metadata, as `traceparent` or as the `grpc-trace-bin` key. For components that you own, Google recommends `traceparent` ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).
- **OpenTelemetry defaults.** The OpenTelemetry Python SDK uses the W3C Trace Context format by default ([Python instrumentation sample](https://docs.cloud.google.com/stackdriver/docs/instrumentation/setup/python)). In Go, call `SetTextMapPropagator` to use the `traceparent` format ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).

## Where traces start, and who samples them

| Component | Trace header | Spans sent to Cloud Trace | Sampling |
|---|---|---|---|
| Cloud Run | Populates `traceparent` for incoming requests | Yes, automatically, without charge | A maximum rate of 0.1 requests per second for each instance (or one request every 10 seconds). You can also force a particular request to be traced, up to a separate maximum rate. You cannot configure the sample rate |
| Global external and classic Application Load Balancer | Adds `X-Cloud-Trace-Context` if it is not present | No | Not applicable |
| Regional external Application Load Balancer | Does not add the header. An existing header passes through unmodified | No | Not applicable |
| Internal Application Load Balancer | Does not support Cloud Trace | No | Not applicable |
| Your code with OpenTelemetry | The SDK propagates the context | Yes, through OTLP. Your own spans are charged | You configure the sampler |

Sources: [Using distributed tracing](https://docs.cloud.google.com/run/docs/trace), [External Application Load Balancer overview](https://docs.cloud.google.com/load-balancing/docs/https), [Internal Application Load Balancer overview](https://docs.cloud.google.com/load-balancing/docs/l7-internal), [Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup), [Trace context](https://docs.cloud.google.com/trace/docs/trace-context).

The automatic Cloud Run traces need no instrumentation. Add instrumentation when you need custom spans, for example for a database query. Also add it to propagate the context, so that Cloud Trace shows the flow across several services as one request ([Using distributed tracing](https://docs.cloud.google.com/run/docs/trace)).

### Sampling decisions

- **Head-based sampling.** The component decides when it receives the request ([Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling)).
- **Tail-based sampling.** The decision waits until the full trace is available. Cloud Trace does not support it, so the components that send data must make the decision. Use an OpenTelemetry Collector with the Tail Sampling Processor, and send all spans of one trace ID to the same collector ([Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling)).
- **No forced sampling.** You cannot force spans to be sampled, because each component decides independently. A `sampled` flag set to `true` is a hint to the child components. Google Cloud services accept the hint but enforce their own rate limits ([Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup)).
- **`ParentBased` sampler.** In OpenTelemetry, the `ParentBased` sampler makes your code respect the parent's flag ([Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup)). When every component follows the parent, the root span decides for the whole trace, and a sampled trace is complete ([Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling)).
- **Incomplete traces are normal.** Probabilistic sampling, an exceeded quota, or a component that does not sample can remove spans from a trace ([Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling)).

| Goal | Do this |
|---|---|
| Complete traces across your services | Use `ParentBased` in every service that you own, and propagate `traceparent` |
| Decide to keep a trace after you see all of its spans | Tail sampling in an OpenTelemetry Collector, not in Cloud Trace |
| Lower the cost and quota use of traces | Lower the sampling ratio of the SDK |
| Change the sample rate of Cloud Run request traces | Not possible. Cloud Run does not support configuration of its sample rate |

Sources: [Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup), [Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling), [Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing), [Using distributed tracing](https://docs.cloud.google.com/run/docs/trace).

## Propagate context in your code

- **Use a library.** OpenTelemetry propagates a context object that holds the trace data. When no suitable library exists, your code must pass the trace context to child operations itself ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).
- **Spans at RPC boundaries.** OpenTelemetry and the client libraries create spans at RPC boundaries automatically, so you often do not need manual spans ([Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup)).
- **Threads.** The libraries keep the current span in a global context. A multi-threaded application must pass that context to each thread ([Instrument for Cloud Trace](https://docs.cloud.google.com/trace/docs/setup)).
- **Google Cloud services.** Apigee, App Engine, Cloud Endpoints, Cloud Run functions, Cloud Load Balancing, Cloud Run, Cloud Scheduler, Cloud Tasks, and Pub/Sub take part in request processing. Support for starting and propagating a trace is different for each service ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context)).

For publishers, subscribers, and delivery options, see [Publishing and consuming messages with Pub/Sub](note:4.1-messaging).

### Pub/Sub messages

The Pub/Sub client library creates a new trace for each published message. The trace covers the message from publish to acknowledgment ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).

```python
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.cloud_trace import CloudTraceSpanExporter
from opentelemetry.sdk.trace.sampling import TraceIdRatioBased, ParentBased

from google.cloud.pubsub_v1 import PublisherClient
from google.cloud.pubsub_v1.types import PublisherOptions

sampler = ParentBased(root=TraceIdRatioBased(1))
trace.set_tracer_provider(TracerProvider(sampler=sampler))

# Export to Google Trace.
cloud_trace_exporter = CloudTraceSpanExporter(project_id=trace_project_id)
trace.get_tracer_provider().add_span_processor(
    BatchSpanProcessor(cloud_trace_exporter)
)

publisher = PublisherClient(
    publisher_options=PublisherOptions(enable_open_telemetry_tracing=True),
)
topic_path = publisher.topic_path(topic_project_id, topic_id)
future = publisher.publish(topic_path, data)
```

Source: [Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing).

- **Turn it on at both ends.** The subscriber uses `SubscriberOptions(enable_open_telemetry_tracing=True)`. The propagation attribute exists only when tracing is on ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).
- **Role.** The service account that exports the traces needs the Cloud Trace Agent role (`roles/cloudtrace.agent`) ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).
- **Batches.** When the publisher sends a batch of messages, the publish RPC span is in a separate trace ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).
- **Missing traces.** Check three common causes. The service account does not have the Cloud Trace Agent role. The Cloud Trace span quota is used up. The application stops before it calls the flush function ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).
- **Not for automation.** Span names and attributes can change without notice. Use these traces interactively ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).

## Write the trace ID into log entries

| `LogEntry` field | JSON field in a structured log line | Value |
|---|---|---|
| `trace` | `logging.googleapis.com/trace` | Preferred: `TRACE_ID`. Legacy, still accepted: `projects/PROJECT_ID/traces/TRACE_ID` |
| `spanId` | `logging.googleapis.com/spanId` | 16 hexadecimal characters. For example, span ID 74 is `000000000000004a` |
| `traceSampled` | `logging.googleapis.com/trace_sampled` | `true` or `false`: the sampling decision when the log entry was written |

Sources: [Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration), [Configure the Logging agent](https://docs.cloud.google.com/logging/docs/agent/logging/configuration), [LogEntry](https://docs.cloud.google.com/logging/docs/reference/v2/rest/v2/LogEntry).

A log entry can have a trace ID although its trace was not sampled. That trace ID is still useful to correlate the log entries of one request ([LogEntry](https://docs.cloud.google.com/logging/docs/reference/v2/rest/v2/LogEntry), [Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration)).

### Choose how to fill the fields

| Your code uses | The trace fields come from | What you do |
|---|---|---|
| OpenTelemetry and JSON logs to standard output | The active OpenTelemetry span | Add the trace ID and span ID to each JSON line, as in the sample that follows |
| The Cloud Logging client library | The active OpenTelemetry span. If there is none, the `traceparent` or `X-Cloud-Trace-Context` header of a supported web framework | Nothing. Values that you set manually take precedence |
| Plain JSON lines, no library | The incoming trace header | Read the header and write `logging.googleapis.com/trace` yourself |

Sources: [Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration), [Automatic Trace/Span ID Extraction](https://docs.cloud.google.com/python/docs/reference/logging/latest/auto-trace-span-extraction), [Logging and viewing logs in Cloud Run](https://docs.cloud.google.com/run/docs/logging), [Python instrumentation sample](https://docs.cloud.google.com/stackdriver/docs/instrumentation/setup/python).

The Python instrumentation sample uses the `opentelemetry-instrumentation-logging` package to add the trace data of the active span, and `python-json-logger` to write each line as JSON:

```python
def setup_structured_logging() -> None:
    LoggingInstrumentor().instrument()

    log_handler = logging.StreamHandler()
    formatter = JsonFormatter(
        "%(asctime)s %(levelname)s %(message)s %(otelTraceID)s %(otelSpanID)s %(otelTraceSampled)s",
        rename_fields={
            "levelname": "severity",
            "asctime": "timestamp",
            "otelTraceID": "logging.googleapis.com/trace",
            "otelSpanID": "logging.googleapis.com/spanId",
            "otelTraceSampled": "logging.googleapis.com/trace_sampled",
        },
    )
    log_handler.setFormatter(formatter)
    logging.basicConfig(
        level=logging.INFO,
        handlers=[log_handler],
    )
```

Source: [Python instrumentation sample](https://docs.cloud.google.com/stackdriver/docs/instrumentation/setup/python).

The Cloud Run sample uses no library. It reads the legacy header and writes the legacy `trace` format:

```python
global_log_fields = {}
trace_header = request.headers.get("X-Cloud-Trace-Context")
if trace_header and PROJECT:
    trace = trace_header.split("/")
    global_log_fields[
        "logging.googleapis.com/trace"
    ] = f"projects/{PROJECT}/traces/{trace[0]}"
entry = dict(
    severity="NOTICE",
    message="This is the default display field.",
    **global_log_fields,
)
print(json.dumps(entry))
```

Source: [Logging and viewing logs in Cloud Run](https://docs.cloud.google.com/run/docs/logging).

On Cloud Run, the Logs Explorer shows container logs nested under their request log when both have the same `trace`. Container logs are not correlated with request logs automatically, unless you use a Cloud Logging client library or write the `logging.googleapis.com/trace` field ([Logging and viewing logs in Cloud Run](https://docs.cloud.google.com/run/docs/logging)).

## Find the logs of a trace, and the trace of a log

- **Trace Explorer.** Click **Search for trace** and enter the trace ID. If a valid trace ID returns no result, the trace can be in a project that the **Scope** setting does not search ([Find and explore traces](https://docs.cloud.google.com/trace/docs/finding-traces)).
- **Logs of one span.** In the trace details, the **Logs & Events** tab lists the log entries whose trace ID and span ID match the selected span. **View logs** opens the Logs Explorer filtered to that trace, span, and time range ([Find and explore traces](https://docs.cloud.google.com/trace/docs/finding-traces)).
- **From a log entry.** In the Logs Explorer, click the trace icon of an entry ([View and analyze log entries](https://docs.cloud.google.com/logging/docs/view/logs-explorer-interface)):
  - **View trace details** opens the trace. It is available only when `traceSampled` is `true`.
  - **Show all logs for this trace** adds a `trace` filter to the query.
  - **Show only traced requests** adds a filter for `traceSampled` set to `True`.
- **Permissions.** To see the logs of a trace, you need `logging.logEntries.list`, from the Logs Viewer or Project Viewer role ([Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration)).
- **SQL.** Observability Analytics (formerly Log Analytics) can join trace data and log data in one query ([Cloud Trace overview](https://docs.cloud.google.com/trace/docs/overview), [Google Cloud Observability release notes](https://docs.cloud.google.com/stackdriver/docs/release-notes)).

This sample joins two log views on the trace and the span ID:

```sql
SELECT
  -- Do an inner join on two tables by using the span ID and trace ID.
  -- Don't join only by span ID, as this field isn't globally unique.
  a.timestamp, a.severity, a.json_payload, b.json_payload, a.span_id, a.trace
FROM  `PROJECT_ID.LOCATION.BUCKET_ID.LOG_VIEW_1` a
JOIN  `PROJECT_ID.LOCATION.BUCKET_ID.LOG_VIEW_2` b
ON
  a.span_id = b.span_id AND
  a.trace = b.trace
LIMIT 100
```

Source: [Sample SQL queries](https://docs.cloud.google.com/logging/docs/analyze/examples).

Spans in the `_Trace` bucket are kept for 30 days ([Cloud Trace overview](https://docs.cloud.google.com/trace/docs/overview)). How to use these tools in an incident is in [Finding and fixing issues](note:4.3-troubleshooting).

## AWS mapping

| AWS | Google Cloud | Difference that matters |
|---|---|---|
| AWS Application Signals | Cloud Trace | Cloud Run creates request traces automatically. Cloud Trace itself does not propagate context. Your code and the services do it, with W3C `traceparent` |
| Amazon CloudWatch Logs | Cloud Logging | A log entry links to a trace through the `trace`, `spanId`, and `traceSampled` fields |

Sources: [Compare AWS and Azure services to Google Cloud](https://docs.cloud.google.com/docs/get-started/aws-azure-gcp-service-comparison), [Using distributed tracing](https://docs.cloud.google.com/run/docs/trace), [Trace context](https://docs.cloud.google.com/trace/docs/trace-context), [Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration).

## Exam traps

- **"The load balancer exports a span."** Application Load Balancers export no traces or spans. The regional external Application Load Balancer does not even add a trace header ([External Application Load Balancer overview](https://docs.cloud.google.com/load-balancing/docs/https)).
- **"Trace an internal Application Load Balancer."** Internal Application Load Balancers do not support Cloud Trace ([Internal Application Load Balancer overview](https://docs.cloud.google.com/load-balancing/docs/l7-internal)).
- **"Increase the Cloud Run sample rate."** You cannot configure it. Add your own instrumentation for more detail ([Using distributed tracing](https://docs.cloud.google.com/run/docs/trace)).
- **"Cloud Trace links the services."** Cloud Trace does not propagate context. Each service must pass the context on, so that Cloud Trace shows the flow across services as one request ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context), [Using distributed tracing](https://docs.cloud.google.com/run/docs/trace)).
- **The span ID from `X-Cloud-Trace-Context` copied into `spanId`.** The header has a decimal span ID. `spanId` needs 16 hexadecimal characters ([Trace context](https://docs.cloud.google.com/trace/docs/trace-context), [Link log entries with traces](https://docs.cloud.google.com/trace/docs/trace-log-integration)).
- **A join on the span ID only.** The span ID is not globally unique. Join on the trace and the span ID ([Sample SQL queries](https://docs.cloud.google.com/logging/docs/analyze/examples)).
- **Tail sampling in Cloud Trace.** Cloud Trace does not support it. Use the Tail Sampling Processor in an OpenTelemetry Collector ([Trace sampling](https://docs.cloud.google.com/trace/docs/trace-sampling)).
- **A valid trace ID that Trace Explorer cannot find.** Check the **Scope** setting and your IAM role in the project that stores the trace ([Find and explore traces](https://docs.cloud.google.com/trace/docs/finding-traces)).
- **No View trace details on a log entry.** The option needs `traceSampled` set to `true` ([View and analyze log entries](https://docs.cloud.google.com/logging/docs/view/logs-explorer-interface)).
- **Pub/Sub tracing turned on for the publisher only.** The subscriber client must also enable OpenTelemetry tracing ([Pub/Sub OpenTelemetry tracing](https://docs.cloud.google.com/pubsub/docs/open-telemetry-tracing)).
