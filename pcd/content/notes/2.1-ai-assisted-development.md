## Why it matters

An AI coding assistant writes, explains, and changes code from your prompts. The quality of its output depends on the context that it gets, and its risk depends on the tools and permissions that it gets. The exam tests the features and editions of Gemini Code Assist (formerly Duet AI for Developers), and how you control context and exclude files ([Gemini Code Assist release notes](https://docs.cloud.google.com/gemini/docs/codeassist/release-notes)). It also tests how agents use Model Context Protocol (MCP) servers and how you keep identity, data, and generated code safe.

## Key points

- Gemini Code Assist has two editions for organizations: Standard and Enterprise. Enterprise adds code customization from your private repositories ([Gemini Code Assist Standard and Enterprise overview](https://docs.cloud.google.com/gemini/docs/codeassist/overview)).
- Since June 18, 2026, the Gemini Code Assist IDE extensions and Gemini CLI no longer serve consumer tiers. These tiers are Gemini Code Assist for individuals, Google AI Pro, and Google AI Ultra. Users of these tiers can migrate to the Antigravity family of products. Standard and Enterprise are not affected ([Gemini Code Assist consumer accounts](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals)).
- A user needs a license and the Gemini for Google Cloud User role (`roles/cloudaicompanion.user`) on a project where `cloudaicompanion.googleapis.com` is enabled ([Set up Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/set-up-gemini)).
- By default, chat uses the current open file as context. Add files and folders with `@`. A folder adds at most its first 100 files ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini)).
- Files in `.aiexclude` or `.gitignore` are excluded from local context by default. Code customization uses only `.aiexclude` ([Exclude files from Gemini Code Assist use](https://docs.cloud.google.com/gemini/docs/codeassist/create-aiexclude-file)).
- Rules are added to every chat prompt. A `GEMINI.md` context file gives agent mode your conventions ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer)).
- Agent mode (Preview) completes multi-step tasks with built-in tools and MCP servers. It asks before it changes files or resources, unless you allow the tool always ([Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode)).
- MCP is an open source protocol that standardizes how AI applications connect to data sources. A local MCP server uses stdio. A remote MCP server has an HTTP endpoint ([Google Cloud MCP servers overview](https://docs.cloud.google.com/mcp/overview)).
- A call to a Google Cloud remote MCP server needs the `mcp.tools.call` permission and the permissions for the underlying resource ([Control MCP use with Identity and Access Management](https://docs.cloud.google.com/mcp/control-mcp-use-iam)).
- For production agents, Google recommends a separate agent or workload identity with minimum permissions, not your own user identity ([Authenticate to Google and Google Cloud MCP servers](https://docs.cloud.google.com/mcp/authenticate-mcp)).
- Gemini does not use your prompts or its responses to train its models. You are responsible for the security, testing, and effectiveness of the code ([How Gemini products in Google Cloud use your data](https://docs.cloud.google.com/gemini/docs/discover/data-governance)).

## Gemini Code Assist editions and setup

Gemini Code Assist works in VS Code, JetBrains IDEs such as IntelliJ and PyCharm, Android Studio, the Cloud Shell Editor, and Cloud Workstations. Both editions give code completion, code generation, chat, smart actions, agentic chat, and a Gemini CLI quota.

| Need | Standard | Enterprise |
|---|---|---|
| Completion, generation, chat, and agent mode | Yes | Yes |
| Local codebase awareness in the IDE | Yes | Yes |
| Source citations, IP indemnification, VPC Service Controls, and Private Google Access | Yes | Yes |
| Code customization from GitHub, GitLab, and Bitbucket repositories | No | Yes |
| Gemini in Apigee and Application Integration | No | Yes |

Source: [Gemini Code Assist Standard and Enterprise overview](https://docs.cloud.google.com/gemini/docs/codeassist/overview).

To set up Gemini Code Assist for a team:

1. Get a Standard or Enterprise subscription. To buy a new subscription, contact Google Cloud sales. Manage and renew an existing subscription in the Google Cloud console.
2. Assign licenses. New subscriptions assign a license automatically when a user with `cloudaicompanion.licenses.selfAssign` first uses Gemini Code Assist. A license that is inactive for 30 days goes to another user.
3. Enable the Gemini for Google Cloud API: `gcloud services enable cloudaicompanion.googleapis.com`.
4. Grant `roles/cloudaicompanion.user` and `roles/serviceusage.serviceUsageConsumer`. Google recommends that you grant them to a group, not to individual users.
5. Install the IDE extension and select the project.

Sources: [Set up Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/set-up-gemini), [Security, privacy, and compliance for Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/security-privacy-compliance).

Since September 4, 2026, you cannot use the Google Cloud console to buy a subscription for a billing account without an active subscription. Billing accounts with an active subscription are not affected. For other AI developer tools, the release notes name Antigravity. Antigravity is available through eligible Gemini Enterprise subscriptions and through Gemini Enterprise Agent Platform ([Gemini Code Assist release notes](https://docs.cloud.google.com/gemini/docs/codeassist/release-notes)).

## Ways to work with the assistant

Each feature fits a different size of task. Small edits stay in the editor. Large tasks go to chat or agent mode.

| Feature | How you start it | Use it for |
|---|---|---|
| Code completion | Type code. Press Tab to accept the suggestion | The next lines of code |
| Generation from a comment | Write a comment that describes the code | A new function or block |
| Code transformation | Quick Pick (Ctrl+I or Cmd+I) with `/generate`, `/fix`, `/doc`, or `/simplify` | A change that you review in a diff view |
| Smart actions | Select code, then the lightbulb or right-click, for example **Generate unit tests** | Common tasks on selected code |
| Chat | The Gemini Code Assist pane, with `@` for files and folders | Questions and larger answers |
| Next Edit Predictions (Preview) | Turn on the setting, then pause while you type | Edits in other places in the same file |
| Agent mode (Preview) | The agent toggle in chat, in VS Code and IntelliJ | Multi-step tasks that need tools |
| Gemini CLI | The `gemini` command in a terminal or Cloud Shell | Agent tasks from the terminal |

Sources: [Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini), [Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode), [Gemini CLI](https://docs.cloud.google.com/gemini/docs/codeassist/gemini-cli).

## Context: what the assistant sees

Context is the information that goes to the model with your prompt. Better context gives more relevant answers. Context also decides which of your data leaves your machine.

| Context source | Scope | How you control it |
|---|---|---|
| Current open file and selected code | The default for chat | Select code, or add it to the Context Drawer |
| `@` files and folders | Up to the first 100 files of a folder | Add or remove items in the Context Drawer |
| Chat history | The current chat | Clear the history. Then add files again with `@` |
| Local codebase awareness | The current folder and open tabs | Exclusion files |
| Code customization (Enterprise) | All indexed repositories. The index refreshes every 24 hours | `@REPOSITORY_NAME` in a prompt, branch patterns, and `.aiexclude` |
| Rules | Every chat prompt | IDE settings. In IntelliJ, rules are not used in agent mode |
| `GEMINI.md` context files | Agent mode | `~/.gemini/GEMINI.md` for all projects, and files in the project for one project or one module |

Sources: [Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Code customization overview](https://docs.cloud.google.com/gemini/docs/codeassist/code-customization-overview), [Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer), [Exclude files from Gemini Code Assist use](https://docs.cloud.google.com/gemini/docs/codeassist/create-aiexclude-file).

A more specific `GEMINI.md` file, for example one in a module folder, overrides or adds to a more general one. Code customization stores the index in a single-tenant environment, and the model does not train on your private code ([Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer), [Code customization overview](https://docs.cloud.google.com/gemini/docs/codeassist/code-customization-overview)).

### Exclude files

An `.aiexclude` file uses the `.gitignore` syntax. When `.aiexclude` and `.gitignore` conflict, `.aiexclude` wins. Gemini Code Assist reads only the `.gitignore` file in the root working folder. The Gemini CLI uses a `.geminiignore` file instead:

```text
apikeys.txt
*.key
my/sensitive/dir/
```

Source: [Exclude files from Gemini Code Assist use](https://docs.cloud.google.com/gemini/docs/codeassist/create-aiexclude-file).

### Context engineering

Google's Architecture Center defines context engineering as the process of managing the information flow that an agent needs. It includes strategies such as isolating context for an agent, persisting information across steps, and compressing large data ([Choose a design pattern for your agentic AI system](https://docs.cloud.google.com/architecture/choose-design-pattern-agentic-ai-system)). A Google Cloud explainer separates prompt engineering from context engineering. Prompt engineering is about the instructions. Context engineering designs all the data and memory that the AI uses. It describes three levels of context ([What Is AI context engineering?](https://cloud.google.com/discover/ai-context-engineering)):

| Level | Meaning | Gemini Code Assist example |
|---|---|---|
| Persistent | Rules that apply to every interaction | Rules and `GEMINI.md` files |
| Semi-persistent | Conversation history and preferences | Chat history |
| Transient | Data for the current task | `@` files, selected code, tool output, and MCP results |

Sources: [What Is AI context engineering?](https://cloud.google.com/discover/ai-context-engineering), [Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode).

Too much context also has a cost. The MCP docs say that agents can become slow, confused, and expensive when you load too many tools into context ([Google Cloud MCP servers overview](https://docs.cloud.google.com/mcp/overview)).

The Gemini prompt guidance gives these rules ([Write better prompts for Gemini in Google Cloud](https://docs.cloud.google.com/gemini/docs/discover/write-prompts)):

- Write full questions with detail, and keep a prompt to 4,000 characters or fewer.
- Say why you need the result, and name the products, languages, and your level of expertise.
- Ask for all the parameters, for example "make sure all methods use their required arguments".
- Break a complex problem into several prompts.

## Agent mode and the Gemini CLI

Agent mode (Preview) sends your prompt and a list of tools to the Gemini API. The model answers, or it asks to use a tool. The agent runs the tool, sends the result back, and repeats until the task is complete. For a complex task, Gemini can show a plan for your approval first ([Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode)).

| Control | What it does |
|---|---|
| Permission prompts | Tools that change files or resources ask first. Read-only tools might not ask |
| Plan approval | You comment on, edit, and approve the plan before work starts |
| `coreTools` and `excludeTools` in `~/.gemini/settings.json` | Allow or block tools and commands. A tool in both lists is excluded |
| Yolo mode (`geminicodeassist.agentYoloMode`) | Allows all actions without prompts. It works only in a trusted workspace |
| `/tools` and `/mcp` | List the tools and the MCP servers that the agent can use |

Sources: [Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer).

This setting allows only `ls -l` from the shell tool and blocks `rm -rf`:

```json
{
  "coreTools": ["ShellTool(ls -l)"],
  "excludeTools": ["ShellTool(rm -rf)"]
}
```

Source: [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer).

The agent can use your file system and your terminal. You cannot undo changes that the agent makes to resources outside the IDE. Recitation is not available in agent mode, so the agent does not cite sources ([Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer), [Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode)).

The Gemini CLI is an open source AI agent for your terminal. It uses a reason and act (ReAct) loop with built-in tools and MCP servers, for example to fix bugs and improve test coverage. In VS Code, agent mode is powered by the Gemini CLI, and the two share one quota. The Gemini CLI is ready to use in Cloud Shell ([Gemini CLI](https://docs.cloud.google.com/gemini/docs/codeassist/gemini-cli)).

## MCP servers

An MCP host is the AI application, for example VS Code or the Gemini CLI. Its MCP client talks to MCP servers. A server exposes tools (actions such as API calls), prompts, and resources (data such as files or schemas) ([Google Cloud MCP servers overview](https://docs.cloud.google.com/mcp/overview)).

| Type | Transport | Where it runs | Example |
|---|---|---|---|
| Local MCP server | stdio | Your machine | A server that the settings file starts with an `npx` command |
| Google Cloud remote MCP server | HTTP | Google infrastructure | `https://bigquery.googleapis.com/mcp`, `https://run.googleapis.com/mcp` |
| Your own remote MCP server | HTTP (streamable HTTP on Cloud Run) | Cloud Run, or Apigee for an existing API | A service that you deploy |

Sources: [Google Cloud MCP servers overview](https://docs.cloud.google.com/mcp/overview), [Supported products](https://docs.cloud.google.com/mcp/supported-products), [Host MCP servers on Cloud Run](https://docs.cloud.google.com/run/docs/host-mcp-servers).

### Configure an MCP server in the IDE

For agent mode in VS Code, add servers to `mcpServers` in `~/.gemini/settings.json`. In IntelliJ, use an `mcp.json` file in the IDE configuration folder. Local servers usually take a token in an environment variable, and remote servers take it in the HTTP `Authorization` header ([Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer)).

For the Gemini CLI, run `gcloud auth application-default login`. Then add a Google Cloud remote MCP server as an extension in `~/.gemini/extensions/EXT_NAME/gemini-extension.json`:

```json
{
  "name": "EXT_NAME",
  "version": "1.0.0",
  "mcpServers": {
    "MCP_SERVER_NAME": {
      "httpUrl": "https://bigquery.googleapis.com/mcp",
      "authProviderType": "google_credentials",
      "oauth": { "scopes": ["SCOPE"] },
      "timeout": 30000,
      "headers": { "x-goog-user-project": "PROJECT_ID" }
    }
  }
}
```

Source: [Configure MCP in an AI application](https://docs.cloud.google.com/mcp/configure-mcp-ai-application).

### Google Cloud remote MCP servers

A Google Cloud remote MCP server is available when you enable the API of its product. Its tools act on real resources, so IAM controls them ([Manage MCP servers](https://docs.cloud.google.com/mcp/manage-mcp-servers)).

| Control | What it does |
|---|---|
| MCP Tool User role (`roles/mcp.toolUser`) | Gives the permission to call MCP tools in the project (`mcp.tools.call`) |
| Resource permissions | The caller also needs normal permissions, for example `bigquery.datasets.get` |
| IAM deny policy with `tool.isReadOnly` | Blocks tools that create, change, or delete resources |
| Toolsets | Smaller groups of tools, each with its own endpoint |
| Model Armor | Scans MCP requests and responses for prompt injection, sensitive data disclosure, and tool poisoning |

Sources: [Configure MCP in an AI application](https://docs.cloud.google.com/mcp/configure-mcp-ai-application), [Control MCP use with Identity and Access Management](https://docs.cloud.google.com/mcp/control-mcp-use-iam), [Google Cloud MCP servers overview](https://docs.cloud.google.com/mcp/overview).

Only a deny policy can use `tool.isReadOnly`. An allow policy condition supports only `resource.service` and `tool.name`. A deny policy does not hide tools: `tools/list` still returns all tools. You cannot use IAM to control MCP servers that are not Google Cloud servers ([Control MCP use with Identity and Access Management](https://docs.cloud.google.com/mcp/control-mcp-use-iam), [Google Cloud MCP servers overview](https://docs.cloud.google.com/mcp/overview)).

### Identity for MCP clients

| Identity | Use it when | Effect |
|---|---|---|
| Your user account (ADC) | Local development | The client has all your permissions, and logs show your identity |
| Service account impersonation | You want to test with a service account in development | The client has only that service account's permissions |
| Agent identity or workload identity | Production agents | You limit permissions and see agent actions in logs |
| Workload Identity Federation | The agent runs outside Google Cloud | The preferred method outside Google Cloud |

Source: [Authenticate to Google and Google Cloud MCP servers](https://docs.cloud.google.com/mcp/authenticate-mcp).

An MCP server can run any code with the permissions of your user account. The docs tell you to trust the source of every MCP server that you add ([Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer)).

To publish your own MCP server, host it on Cloud Run with streamable HTTP. Cloud Run does not support stdio MCP servers. A local client can reach a private server through `gcloud run services proxy`, which needs the Cloud Run Invoker role ([Host MCP servers on Cloud Run](https://docs.cloud.google.com/run/docs/host-mcp-servers)).

## Data governance and responsible use

| Question | What the docs say |
|---|---|
| Does Google train on my prompts? | No. Gemini does not use your prompts or its responses to train its models |
| Are prompts stored? | Gemini Code Assist Standard and Enterprise are stateless and do not store prompts and responses, unless you turn on logging to Cloud Logging |
| Where is data processed? | On the global Google network. Regionality is not guaranteed |
| What counts as Customer Data? | Prompts, responses, and context such as open file snippets, adjacent files, and the cursor location |
| Can generated code match open source code? | Yes. Gemini cites sources that it quotes at length. You can block suggestions that match cited sources |
| Is the generated code correct? | Not always. Models can hallucinate, including links that do not exist, and can fail on edge cases. Test the code and check for vulnerabilities |

Sources: [How Gemini products in Google Cloud use your data](https://docs.cloud.google.com/gemini/docs/discover/data-governance), [Security, privacy, and compliance for Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/security-privacy-compliance), [Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini), [Google Cloud with Gemini and responsible AI](https://docs.cloud.google.com/gemini/docs/discover/responsible-ai).

To block code that matches cited sources in VS Code, set **Recitation: Max Cited Length** to `0`. In IntelliJ, select **Block selections that match external cited sources** ([Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini)).

## Exam traps

- **A large folder with `@`.** Only the first 100 files become context. For more, use code customization ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini)).
- **A `.gitignore` in a subfolder to hide secrets.** Only the root `.gitignore` counts, and code customization ignores `.gitignore`. Use `.aiexclude` ([Exclude files from Gemini Code Assist use](https://docs.cloud.google.com/gemini/docs/codeassist/create-aiexclude-file)).
- **Only `roles/mcp.toolUser` for an agent.** The tool call also needs the permissions for the resource ([Control MCP use with Identity and Access Management](https://docs.cloud.google.com/mcp/control-mcp-use-iam)).
- **A stdio MCP server on Cloud Run.** Cloud Run does not host MCP servers with stdio transport. Use streamable HTTP ([Host MCP servers on Cloud Run](https://docs.cloud.google.com/run/docs/host-mcp-servers)).
- **Your own identity for a production agent.** Use a separate agent or workload identity with minimum permissions ([Authenticate to Google and Google Cloud MCP servers](https://docs.cloud.google.com/mcp/authenticate-mcp)).
- **"Agent mode shows citations."** Recitation is not available in agent mode ([Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode)).
- **Yolo mode to save time in any folder.** It works only in a trusted workspace, and the agent can run terminal commands ([Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer)).
- **A consumer Gemini Code Assist account for a team.** The consumer tiers stopped on June 18, 2026. Use Standard or Enterprise ([Gemini Code Assist consumer accounts](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals)).
- **Generated code without review.** You are responsible for its security and tests ([How Gemini products in Google Cloud use your data](https://docs.cloud.google.com/gemini/docs/discover/data-governance)).
