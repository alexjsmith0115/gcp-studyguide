## Why it matters

An AI coding assistant can write unit tests quickly, but a test has value only if it checks the correct behavior. You stay responsible for the tests that you accept. The exam tests how you ask Gemini Code Assist for tests and how you review them. It also tests mocks and emulators, shared test conventions, test runs in Cloud Build, and AI reviews of pull requests.

## Key points

- Select code and use the smart action **Generate unit tests** to ask Gemini Code Assist for tests ([Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini)).
- In chat, select a function and write a prompt such as "Write a unit test for this function". Gemini uses the selected code as context ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini)).
- Rules go with every chat prompt. The docs give the rule "Always generate unit tests when creating a new function" as an example ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini)).
- Agent mode (Preview) and the Gemini CLI can work on tasks such as better test coverage, with file and terminal tools ([Gemini CLI](https://docs.cloud.google.com/gemini/docs/codeassist/gemini-cli), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer)).
- Generated output can look correct and still be wrong. Validate all output before you use it ([Gemini Code Assist Standard and Enterprise overview](https://docs.cloud.google.com/gemini/docs/codeassist/overview)).
- You are responsible for the security, testing, and effectiveness of the code. Test it and check it for vulnerabilities ([How Gemini products in Google Cloud use your data](https://docs.cloud.google.com/gemini/docs/discover/data-governance)).
- The Cloud Run functions samples test a function directly. They build the event in the test, or they use `unittest.mock` for the context ([Cloud Storage (2nd Gen) Unit Test](https://docs.cloud.google.com/functions/docs/samples/functions-cloudevent-storage-unit-test), [Pub/Sub unit tests](https://docs.cloud.google.com/functions/docs/samples/functions-pubsub-unit-test)).
- For code that calls Pub/Sub, Firestore, Bigtable, or Spanner, point the client library at a local emulator with an environment variable ([Testing apps locally with the emulator](https://docs.cloud.google.com/pubsub/docs/emulator), [Use Firestore emulator locally](https://docs.cloud.google.com/firestore/native/docs/emulator)).
- Cloud Build runs `pytest` in a build step and can save the JUnit XML report to Cloud Storage ([Build and test Python applications](https://docs.cloud.google.com/build/docs/building/build-python)).
- Gemini Code Assist on GitHub reviews pull requests and gives each comment a severity: Critical, High, Medium, or Low ([Use Gemini Code Assist on GitHub](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github)).

## Ways to ask for tests

Choose the method by the size of the task and by how much you want to control the output.

| Method | How you start it | Use it when |
|---|---|---|
| Smart action | Select code. Click the lightbulb (VS Code) or right-click (IntelliJ), then **Generate unit tests** | You want tests for one function quickly |
| Chat with selected code | Select the function and prompt "Write a unit test for this function", plus your requirements | You want to name the framework, the cases, or the style |
| Chat with an example file | `@` a test file: "Generate unit tests for module-x based on the examples in the selected file" | New tests must follow your existing tests |
| Code transformation | Quick Pick with `/generate`. The result shows in a diff view | You want to see each change before you accept it |
| Agent mode (Preview) or the Gemini CLI | A goal, such as better test coverage for a module | The task spans several files or needs commands |

Sources: [Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini), [Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Gemini CLI](https://docs.cloud.google.com/gemini/docs/codeassist/gemini-cli), [Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode).

The prompt guidance applies to test prompts too. Give detail and say why. Name the language and the framework, and ask for all the parameters. Break a large request into several prompts, for example one prompt for each module ([Write better prompts for Gemini in Google Cloud](https://docs.cloud.google.com/gemini/docs/discover/write-prompts)).

## A workflow for AI-generated unit tests

1. Set the conventions first: rules in the IDE, and a `GEMINI.md` file for agent mode. See the section about conventions below.
2. Select the function, and ask for tests with a smart action or a chat prompt. Name the edge cases and the error cases that you need.
3. Read the result before you accept it. Code transformation and quick fixes show a diff view.
4. Run the tests locally. Set the emulator variables first if the code calls a Google Cloud service.
5. If a test fails, add the terminal output to the Context Drawer and ask Gemini about the failure.
6. Commit the tests. Cloud Build runs them, and Gemini Code Assist on GitHub reviews the pull request.

Sources: [Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Code with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/write-code-gemini), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer), [Build and test Python applications](https://docs.cloud.google.com/build/docs/building/build-python), [Use Gemini Code Assist on GitHub](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github).

## Review the generated tests

The docs list the limitations of generated output. Each limitation gives you one thing to check in a generated test.

| Check | The limitation that it addresses |
|---|---|
| Each test asserts a specific expected result, and the result is correct | Output can seem plausible but be factually incorrect |
| The tests cover edge cases and error paths | Models can fail on unusual or rare cases that are not well represented in training data |
| Every class, method, and import exists in the library version that you use | Models can hallucinate, including links and references that do not exist |
| Long blocks that match open source code have an acceptable license | Gemini cites a source when it quotes at length, so that you can follow license requirements |
| The tests contain no secrets, and secret files stay out of context | Files in `.aiexclude` are not sent as context |
| The tests do not call production services | A client library uses the emulator only when the emulator variable is set |
| The tested code has no security vulnerabilities | You are responsible for the security of the code |

Sources: [Gemini Code Assist Standard and Enterprise overview](https://docs.cloud.google.com/gemini/docs/codeassist/overview), [Google Cloud with Gemini and responsible AI](https://docs.cloud.google.com/gemini/docs/discover/responsible-ai), [How Gemini products in Google Cloud use your data](https://docs.cloud.google.com/gemini/docs/discover/data-governance), [Exclude files from Gemini Code Assist use](https://docs.cloud.google.com/gemini/docs/codeassist/create-aiexclude-file), [Testing apps locally with the emulator](https://docs.cloud.google.com/pubsub/docs/emulator).

Agent mode does not cite sources, and you cannot block suggestions that match cited sources in agent mode. Check agent output for copied code with extra care ([Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode)).

## Mocks, events, and emulators for Google Cloud code

A unit test must not depend on a real cloud resource. The Google samples and emulator docs show which test double to use for each kind of code.

| Code under test | Test double | How |
|---|---|---|
| A CloudEvent function | An event object that the test builds | `CloudEvent(attributes, data)`, then call the function |
| A function with a context argument | A mock context | `unittest.mock.Mock()` with the fields that the function reads |
| Code that uses the Pub/Sub, Firestore, Bigtable, or Spanner client library | An emulator | Start the emulator, then set `PUBSUB_EMULATOR_HOST`, `FIRESTORE_EMULATOR_HOST`, `BIGTABLE_EMULATOR_HOST`, or `SPANNER_EMULATOR_HOST` |
| A function that runs as an HTTP server | The Functions Framework in a subprocess | Start `functions-framework`, then send HTTP requests |
| Code that depends on IAM, indexes, or limits | No double. Use a test project | An integration test |

Sources: [Cloud Storage (2nd Gen) Unit Test](https://docs.cloud.google.com/functions/docs/samples/functions-cloudevent-storage-unit-test), [Pub/Sub unit tests](https://docs.cloud.google.com/functions/docs/samples/functions-pubsub-unit-test), [Pub/Sub integration tests](https://docs.cloud.google.com/functions/docs/samples/functions-pubsub-integration-test), [Testing apps locally with the emulator](https://docs.cloud.google.com/pubsub/docs/emulator), [Use Firestore emulator locally](https://docs.cloud.google.com/firestore/native/docs/emulator).

The docs sample for a Pub/Sub function uses a mock context and checks the printed output:

```python
import base64
from unittest import mock

import main

mock_context = mock.Mock()
mock_context.event_id = "617187464135194"
mock_context.timestamp = "2019-07-15T22:09:03.761Z"
mock_context.resource = {
    "name": "projects/my-project/topics/my-topic",
    "service": "pubsub.googleapis.com",
    "type": "type.googleapis.com/google.pubsub.v1.PubsubMessage",
}

def test_print_name(capsys):
    name = "test"
    data = {"data": base64.b64encode(name.encode())}
    main.hello_pubsub(data, mock_context)
    out, err = capsys.readouterr()
    assert f"Hello {name}!\n" in out
```

Source: [Pub/Sub unit tests](https://docs.cloud.google.com/functions/docs/samples/functions-pubsub-unit-test).

For code that reads or writes Firestore, run the tests against the emulator and clear its data between runs:

```bash
gcloud emulators firestore start --host-port=localhost:8080
# In a second terminal
export FIRESTORE_EMULATOR_HOST="localhost:8080"
python -m pytest
curl -v -X DELETE "http://localhost:8080/emulator/v1/projects/PROJECT_ID/databases/(default)/documents"
```

Sources: [Use Firestore emulator locally](https://docs.cloud.google.com/firestore/native/docs/emulator), [Build and test Python applications](https://docs.cloud.google.com/build/docs/building/build-python).

An emulator does not check IAM, and the Firestore emulator does not check manual (composite) indexes ([Emulate Spanner locally](https://docs.cloud.google.com/spanner/docs/emulator), [Use Firestore emulator locally](https://docs.cloud.google.com/firestore/native/docs/emulator)). Tests for those behaviors belong in [Automated integration tests in Cloud Build](note:2.3-integration-tests-cloud-build). [Emulating Google Cloud services](note:2.1-emulators) lists each emulator and its gaps.

## Set test conventions once

Put the test conventions in files and settings, not in each prompt. Then every developer and every agent uses the same conventions.

| Where | Scope | Example use |
|---|---|---|
| Rules (VS Code setting `Geminicodeassist: Rules`) | Every chat prompt | "Always generate unit tests when creating a new function" |
| Rules in IntelliJ (IDE or Project scope) | Chat. Not used in agent mode | Project rules are shared when the `.idea` folder is in version control |
| Custom commands | A saved prompt that you run from Quick Pick or the Prompt Library | A test prompt that you repeat often |
| `GEMINI.md` | Agent mode, for all projects, one project, or one module | The test framework, folder layout, and emulator use |
| `.gemini/styleguide.md` in the repository | Gemini Code Assist on GitHub reviews | Team rules that reviews check |

Sources: [Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer), [Code review style guide](https://docs.cloud.google.com/gemini/docs/code-review/style-guide).

## Code review on GitHub

Gemini Code Assist on GitHub reviews a pull request when it opens. It adds `gemini-code-assist[bot]` as a reviewer and posts comments with a severity, feedback, and a code suggestion that you can commit. In a pull request comment, `/gemini review` asks for a review, `/gemini summary` asks for a summary, and `/gemini help` lists the commands ([Use Gemini Code Assist on GitHub](https://docs.cloud.google.com/gemini/docs/code-review/use-code-assist-github)).

The enterprise version of Gemini Code Assist on GitHub is in Preview. It is a separate product from Gemini Code Assist Enterprise. Gemini Code Assist on GitHub does not generate summaries or suggestions for files in `.github/workflows` ([Review GitHub code using Gemini Code Assist](https://docs.cloud.google.com/gemini/docs/code-review/review-repo-code)).

A `.gemini/config.yaml` file in the repository root changes the review behavior. The default severity threshold is `MEDIUM`, and a review posts by default when a pull request opens:

```yaml
code_review:
  comment_severity_threshold: HIGH
  max_review_comments: -1
  pull_request_opened:
    summary: true
    code_review: true
ignore_patterns:
  - "docs/**"
```

Source: [Customize Gemini Code Assist behavior in GitHub](https://docs.cloud.google.com/gemini/docs/code-review/customize-repo-review).

## Run the tests in Cloud Build

A Cloud Build config can install the dependencies, run `pytest`, and continue to the build steps only after the tests pass. This sample from the docs also saves the test report to Cloud Storage:

```yaml
steps:
  - name: 'python'
    entrypoint: 'python'
    args: ['-m', 'pip', 'install', '--upgrade', 'pip']
  - name: python
    entrypoint: python
    args: ['-m', 'pip', 'install', 'build', 'pytest', 'Flask', '--user']
  - name: 'python'
    entrypoint: 'python'
    args: ['-m', 'pytest', '--junitxml=${SHORT_SHA}_test_log.xml']
  - name: 'python'
    entrypoint: 'python'
    args: ['-m', 'build']
artifacts:
  objects:
    location: 'gs://${_BUCKET_NAME}/'
    paths:
      - '${SHORT_SHA}_test_log.xml'
```

Source: [Build and test Python applications](https://docs.cloud.google.com/build/docs/building/build-python).

The `--user` flag lets later steps use the modules that an earlier step installed. To write the report to the bucket, the build service account needs the Storage Object Creator role (`roles/storage.objectCreator`) ([Build and test Python applications](https://docs.cloud.google.com/build/docs/building/build-python)). [Building containers with Cloud Build](note:2.2-cloud-build-artifact-registry) explains build steps and triggers.

## Exam traps

- **Accepting generated tests without running them.** Validate all output, and test the code ([Gemini Code Assist Standard and Enterprise overview](https://docs.cloud.google.com/gemini/docs/codeassist/overview), [How Gemini products in Google Cloud use your data](https://docs.cloud.google.com/gemini/docs/discover/data-governance)).
- **A unit test that writes to production.** Without the emulator variable, the client library calls the production service ([Testing apps locally with the emulator](https://docs.cloud.google.com/pubsub/docs/emulator)).
- **"The emulator tests pass, so the IAM roles are correct."** Emulators do not check IAM ([Emulate Spanner locally](https://docs.cloud.google.com/spanner/docs/emulator)).
- **The test framework in every prompt.** Put it in a rule or a `GEMINI.md` file ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini), [Use the Gemini Code Assist agent mode](https://docs.cloud.google.com/gemini/docs/codeassist/use-agentic-chat-pair-programmer)).
- **IntelliJ rules for agent mode.** IntelliJ does not use rules in agent mode. Use a context file ([Chat with Gemini Code Assist Standard and Enterprise](https://docs.cloud.google.com/gemini/docs/codeassist/chat-gemini)).
- **"Agent mode tells me when it copies code."** Recitation is not available in agent mode ([Agent mode overview](https://docs.cloud.google.com/gemini/docs/codeassist/agent-mode)).
- **Low-severity review comments by default.** The default threshold is `MEDIUM`, so `LOW` issues get no comment ([Customize Gemini Code Assist behavior in GitHub](https://docs.cloud.google.com/gemini/docs/code-review/customize-repo-review)).
- **A test report that disappears.** List the report file under `artifacts.objects` to keep it in Cloud Storage ([Build and test Python applications](https://docs.cloud.google.com/build/docs/building/build-python)).
