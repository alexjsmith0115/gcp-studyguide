## Why it matters

An API needs rate limits, authentication, and monitoring in front of the backend code. Google Cloud has three products for this: Apigee, API Gateway (the exam guide says Cloud API Gateway), and Cloud Endpoints. The exam tests which product fits a scenario. It also tests the configuration that does the job: an OpenAPI extension in API Gateway, or a policy in an Apigee API proxy.

## Key points

- Apigee is Google Cloud's native API management platform. It puts an API proxy layer with policies between clients and backends, and it supports REST, gRPC, SOAP, and GraphQL ([What is Apigee?](https://docs.cloud.google.com/apigee/docs/api-platform/get-started/what-apigee)).
- API Gateway is a fully managed, pay-per-use gateway that Google designed for serverless backends. You configure it with an OpenAPI document, or with a gRPC service configuration for gRPC services on Cloud Run ([API Gateway architecture](https://docs.cloud.google.com/api-gateway/docs/architecture-overview), [Choosing between Apigee, API Gateway, and Cloud Endpoints](https://cloud.google.com/blog/products/application-modernization/choosing-between-apigee-api-gateway-and-cloud-endpoints), [API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model)).
- An API Gateway API config cannot change after you create it. A gateway is regional and hosts exactly one API config ([API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model)).
- API Gateway calls a backend with an ID token for its service account. Give that service account the Cloud Run Invoker role on a private Cloud Run backend ([Securing backend services](https://docs.cloud.google.com/api-gateway/docs/securing-backend-services)).
- An API key identifies a Google Cloud project for quota, billing, and monitoring. A JWT identifies a user or a service ([Choosing an authentication method](https://docs.cloud.google.com/api-gateway/docs/authentication-method), [Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt)).
- API Gateway quotas (Beta) count requests per minute per consumer project. A client over the limit gets HTTP `429` ([OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions), [About quotas (Endpoints)](https://docs.cloud.google.com/endpoints/docs/openapi/quotas-overview)).
- In Apigee, SpikeArrest protects the backend from traffic spikes from all clients. Quota limits each app or developer over longer periods and counts accurately ([Comparing rate-limiting policies](https://docs.cloud.google.com/apigee/docs/api-platform/develop/comparing-quota-and-spike-arrest-policies)).
- Apigee provisions API keys for API products, not for API proxies. A developer app gets a key when you register it with at least one API product ([Introduction to API products](https://docs.cloud.google.com/apigee/docs/api-platform/publish/what-api-product)).
- Apigee does not check keys automatically. Without a VerifyAPIKey or OAuthV2 VerifyAccessToken policy in the proxy, any caller can call your API ([Introduction to API products](https://docs.cloud.google.com/apigee/docs/api-platform/publish/what-api-product)).
- API Gateway sends latency, traffic, and error metrics to Cloud Monitoring and request logs to Cloud Logging ([Monitoring your API](https://docs.cloud.google.com/api-gateway/docs/monitoring)).

## Choose a product

Google suggests Apigee first for complex or high-scale APIs, and API Gateway for serverless backends that do not need a developer portal. Cloud Endpoints fits when you run the gateway on your own runtime ([Choosing between Apigee, API Gateway, and Cloud Endpoints](https://cloud.google.com/blog/products/application-modernization/choosing-between-apigee-api-gateway-and-cloud-endpoints)).

| The scenario says | Choose | Why |
|---|---|---|
| Partners or third parties use the API. You need a developer portal, API products, or monetization | Apigee | Apigee has developer portals, API products, and monetization. API Gateway fits when consumers need no developer portal |
| Very high API volume, enterprise security, or backends on premises and in other clouds | Apigee | Apigee runs in Google Cloud, on premises, or in a hybrid deployment |
| Cloud Run or Cloud Run functions backends, key or JWT checks, simple per-minute quotas (Beta), consumption pricing | API Gateway | A lightweight, fully managed gateway at the project level. You can move to Apigee later |
| The gateway must run next to your app, in your private network, or on your own machine for tests | Cloud Endpoints (ESPv2) | You deploy and operate the proxy yourself, with more control and more operational work |

Sources: [Choosing between Apigee, API Gateway, and Cloud Endpoints](https://cloud.google.com/blog/products/application-modernization/choosing-between-apigee-api-gateway-and-cloud-endpoints), [Compare AWS and Azure services to Google Cloud](https://docs.cloud.google.com/docs/get-started/aws-azure-gcp-service-comparison).

| Feature | Apigee | API Gateway | Cloud Endpoints |
|---|---|---|---|
| Proxy | Apigee API proxies | Google-managed Envoy proxy, regional | ESPv2 (Envoy) that you deploy |
| API definition | API proxy with XML policies | OpenAPI 2.0 or 3.x, or gRPC service configuration | OpenAPI 2.0, or gRPC service configuration |
| Rate limiting | SpikeArrest and Quota policies, quotas in API products | Per-minute quota per consumer project (Beta) | Per-minute quota per consumer project (Beta) |
| Authentication | API keys, OAuth 2.0 access tokens, JWTs, IAM | API keys, JWTs | API keys, JWTs |
| Observability | Apigee API Analytics, API monitoring | Cloud Monitoring metrics and Cloud Logging | Cloud Monitoring metrics and Cloud Logging |

Sources: [What is Apigee?](https://docs.cloud.google.com/apigee/docs/api-platform/get-started/what-apigee), [API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model), [OpenAPI overview](https://docs.cloud.google.com/api-gateway/docs/openapi-overview), [About API Gateway](https://docs.cloud.google.com/api-gateway/docs/about-api-gateway), [About Cloud Endpoints](https://docs.cloud.google.com/endpoints/docs/openapi/about-cloud-endpoints), [About quotas (Endpoints)](https://docs.cloud.google.com/endpoints/docs/openapi/quotas-overview), [OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions), [Choosing between Apigee, API Gateway, and Cloud Endpoints](https://cloud.google.com/blog/products/application-modernization/choosing-between-apigee-api-gateway-and-cloud-endpoints).

## API Gateway

### Resources and deployment

| Resource | What it is | Rule to remember |
|---|---|---|
| API | The container for API configs. Each API gets a managed service, for example `my-api-123abc456def1.apigateway.my-project.cloud.goog` | Consumers enable this managed service to call the API with an API key |
| API config | Your OpenAPI document (or gRPC definition) after upload | It cannot change. A new upload creates a new API config |
| Gateway | A regional, Envoy-based proxy with a URL like `https://GATEWAY_ID-HASH.REGION_CODE.gateway.dev` | It hosts exactly one API config. You can switch it to another API config |

Sources: [API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model), [Monitoring your API](https://docs.cloud.google.com/api-gateway/docs/monitoring), [Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys).

A gateway scales to zero when there is no traffic. Google manages the TLS certificate for the `gateway.dev` domain. To use dev, stage, and prod configs, deploy each API config to its own gateway ([API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model)).

```bash
gcloud services enable apigateway.googleapis.com
gcloud services enable servicemanagement.googleapis.com
gcloud services enable servicecontrol.googleapis.com
gcloud api-gateway api-configs create CONFIG_ID \
  --api=API_ID --openapi-spec=openapi2-run.yaml \
  --project=PROJECT_ID --backend-auth-service-account=SERVICE_ACCOUNT_EMAIL
gcloud api-gateway gateways create GATEWAY_ID \
  --api=API_ID --api-config=CONFIG_ID \
  --location=GCP_REGION --project=PROJECT_ID
```

Source: [Getting started with API Gateway and Cloud Run](https://docs.cloud.google.com/api-gateway/docs/get-started-cloud-run).

The first `api-configs create` command also creates the API. A complex API config can take up to ten minutes to create ([Getting started with API Gateway and Cloud Run](https://docs.cloud.google.com/api-gateway/docs/get-started-cloud-run)). An update has no downtime, but for a short time some requests can still go to the previous API config ([API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model)).

### The OpenAPI document

The document sets the backend, the authentication, and the quotas with `x-google-*` extensions. The quota extensions, `x-google-management` and `x-google-quota`, are Beta. This OpenAPI 2.0 example requires an API key and counts each call to `/hello` against a per-minute quota:

```yaml
swagger: '2.0'
info:
  title: API_ID optional-string
  version: 1.0.0
x-google-backend:
  address: APP_URL
x-google-management:
  metrics:
    - name: "read-requests"
      valueType: INT64
      metricKind: DELTA
  quota:
    limits:
      - name: "read-requests-limit"
        metric: "read-requests"
        unit: "1/min/{project}"
        values:
          STANDARD: 5000
paths:
  /hello:
    get:
      operationId: hello
      x-google-quota:
        metricCosts:
          read-requests: 1
      security:
      - api_key: []
      responses:
        '200':
          description: A successful response
securityDefinitions:
  api_key:
    type: "apiKey"
    name: "key"
    in: "query"
```

Sources: [Getting started with API Gateway and Cloud Run](https://docs.cloud.google.com/api-gateway/docs/get-started-cloud-run), [OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions), [Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys).

The `x-google-backend` extension has these fields:

| Field | What it does |
|---|---|
| `address` | The backend URL, for example the Cloud Run service URL |
| `jwt_audience` | The audience of the ID token that the gateway sends. The default is the `address` value |
| `disable_auth` | Stops the gateway from adding an ID token |
| `path_translation` | `APPEND_PATH_TO_ADDRESS` (default at the top level) or `CONSTANT_ADDRESS` (default at the operation level) |
| `deadline` | Seconds to wait for the full response. The default is `15.0` |
| `protocol` | `http/1.1` (default) or `h2`. `h2` is recommended for serverless backends and required for gRPC |

Source: [OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions).

OpenAPI 3.x documents use the same ideas with different syntax, for example `x-google-api-management` for backends and `x-google-auth` for JWTs ([Getting started with API Gateway and Cloud Run](https://docs.cloud.google.com/api-gateway/docs/get-started-cloud-run), [Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt)).

### Authenticate clients

| | API key | JWT |
|---|---|---|
| What it identifies | The client's Google Cloud project | A user or a service (issuer and subject claims) |
| API config | `securityDefinitions` of type `apiKey` | `securityDefinitions` with `x-google-issuer`, `x-google-jwks_uri`, and optional `x-google-audiences` |
| Extra setup | Enable the API's managed service with `gcloud services enable MANAGED_SERVICE_NAME` | None. The gateway gets the public keys from the JWKS URI |
| Client sends | `?key=API_KEY` (or a header, if the API config says so) | `Authorization: Bearer TOKEN`, or the `access_token` query parameter |
| Use it for | Quotas and project identification | User access and service-to-service calls |

Sources: [Choosing an authentication method](https://docs.cloud.google.com/api-gateway/docs/authentication-method), [Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys), [Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt).

Know these API key rules:

- The gateway rejects a key unless it comes from your project or from a project that enabled your API ([Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys)).
- An API key travels with each request, so it is less secure than a short-lived token. Do not use only API keys when calls carry sensitive data ([Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys)).
- Keys are unrestricted by default. Add API restrictions and application restrictions. An HTTP referrer restriction needs a scheme, for example `https://example.com/*` ([Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys)).
- A standard API key does not identify a principal, so no IAM check happens ([Manage API keys](https://docs.cloud.google.com/docs/authentication/api-keys)).

Know these JWT rules:

- The gateway caches the issuer's JSON Web Key Set (JWKS) for five minutes ([Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt)).
- Without `x-google-audiences`, the gateway accepts JWTs with `https://SERVICE_NAME` in the `aud` claim ([Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt)).
- Security settings on a method override the settings at the API level ([Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt)).
- The backend gets the verified JWT payload in a header. Use it instead of the `Authorization` header. The docs give two names for this header. The JWT page says `X-Apigateway-Api-Userinfo`, and the extensions page says `X-Endpoint-API-UserInfo` ([Using JWT to authenticate users](https://docs.cloud.google.com/api-gateway/docs/authenticating-users-jwt), [OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions)).

[Authenticating end users](note:1.2-user-authentication) explains Identity Platform and OAuth 2.0 tokens.

### Authenticate to the backend

API Gateway replaces the `Authorization` header with an instance ID token for the gateway's service account. It copies the client's original header to `X-Forwarded-Authorization` ([OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions)).

1. Keep the Cloud Run service private. Cloud Run services are private by default.
2. Give the gateway's service account `roles/run.invoker` on the service. For Cloud Run functions, give `roles/cloudfunctions.invoker`.
3. Pass that service account with `--backend-auth-service-account` when you create the API config. The service account also needs the `iam.serviceAccounts.actAs` permission (in the Service Account User role).

Sources: [Securing backend services](https://docs.cloud.google.com/api-gateway/docs/securing-backend-services), [API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model), [Getting started with API Gateway and Cloud Run](https://docs.cloud.google.com/api-gateway/docs/get-started-cloud-run).

For an App Engine backend or a backend behind Identity-Aware Proxy (IAP), set `jwt_audience` to the OAuth client ID ([OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions)). API Gateway cannot call `*.googleapis.com` backends. Those calls fail with `401`, because Google APIs need an access token, not an ID token ([Securing backend services](https://docs.cloud.google.com/api-gateway/docs/securing-backend-services)).

### Rate limits

API Gateway quotas protect the backend from too many requests and keep one client from affecting the others ([About quotas](https://docs.cloud.google.com/api-gateway/docs/quotas-overview)). This feature is Beta. The API Gateway quota page refers to the Cloud Endpoints quota page, and that page and the `x-google-management` extension are labeled Beta ([About quotas](https://docs.cloud.google.com/api-gateway/docs/quotas-overview), [About quotas (Endpoints)](https://docs.cloud.google.com/endpoints/docs/openapi/quotas-overview), [OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions)).

- The only limit unit is `1/min/{project}`: per consumer project, reset every minute ([OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions)).
- `metricCosts` lets an expensive method use more of the same quota. A method without `x-google-quota` has no limit ([OpenAPI 2.0 extensions in API Gateway](https://docs.cloud.google.com/api-gateway/docs/oasv2-extensions)).
- Each client sends an API key, so that the gateway can find the consumer project. A client over the limit gets `429` and must decrease its call rate, for example with exponential backoff ([About quotas (Endpoints)](https://docs.cloud.google.com/endpoints/docs/openapi/quotas-overview)).
- Enforcement is approximate, with a 30% margin of error. You can override the limit for one consumer project ([About quotas (Endpoints)](https://docs.cloud.google.com/endpoints/docs/openapi/quotas-overview)).
- Quotas apply to the whole API. The newest API config sets them for every gateway. If you rename or remove a metric, gateways with an older API config return `500` with `Failed to call Service Control Quota.` ([About quotas](https://docs.cloud.google.com/api-gateway/docs/quotas-overview)).

### Monitoring and logs

API Gateway tracks three of the four golden signals: latency, traffic, and errors. In Metrics Explorer, the metric is **API Gateway > Proxy > Request Count**. You can group it by `response_code_class`, `gateway_id`, and `api_config`, and filter it by consumer project. Logs Explorer shows a log entry for each request ([Monitoring your API](https://docs.cloud.google.com/api-gateway/docs/monitoring)). The docs disagree about tracing. The tracing page says that the current release does not support tracing ([Tracing your API](https://docs.cloud.google.com/api-gateway/docs/tracing)). The deployment model page lists trace information for each gateway ([API Gateway deployment model](https://docs.cloud.google.com/api-gateway/docs/deployment-model)).

A load balancer in front of the gateways lets you use a custom domain, Cloud Armor, Cloud CDN, and gateways in several regions. The load balancer is a global external or classic Application Load Balancer (formerly HTTP(S) Load Balancing) with a serverless NEG. This integration is in Preview ([Load balancing for API Gateway](https://docs.cloud.google.com/api-gateway/docs/gateway-load-balancing), [Use a custom domain with API Gateway](https://docs.cloud.google.com/api-gateway/docs/using-custom-domains)).

## Apigee

### API proxies and policies

An API proxy has two parts. The ProxyEndpoint is the URL that clients call, and it usually holds the security and rate-limit policies. The TargetEndpoint calls the backend ([Understanding APIs and API proxies](https://docs.cloud.google.com/apigee/docs/api-platform/fundamentals/understanding-apis-and-api-proxies)). A standard proxy has only Standard policies and cannot be in an API product. An extensible proxy has at least one Extensible policy ([Understanding APIs and API proxies](https://docs.cloud.google.com/apigee/docs/api-platform/fundamentals/understanding-apis-and-api-proxies)).

| Policy | What it does | Where to attach it | Policy type |
|---|---|---|---|
| SpikeArrest | Limits the request rate to the backend for all clients, per second (`ps`) or per minute (`pm`) | ProxyEndpoint Request PreFlow, at the start, before Quota | Standard |
| Quota | Counts requests per app or developer over minutes to months. It can read the limits from the API product | ProxyEndpoint Request PreFlow, after authentication | Extensible |
| VerifyAPIKey | Checks that the key belongs to an approved app for the API product | Before Quota | Extensible |
| OAuthV2 (`VerifyAccessToken`) | Checks an OAuth 2.0 bearer access token. Other operations issue tokens | Before Quota | Extensible |
| VerifyJWT | Checks the JWT signature, expiry, and optional claims, and extracts the claims | Request flow | Standard |
| VerifyIAM | Checks access with IAM, as an alternative to VerifyAPIKey and OAuthV2. Not in Apigee hybrid | Request flow | Standard |

Sources: [Comparing rate-limiting policies](https://docs.cloud.google.com/apigee/docs/api-platform/develop/comparing-quota-and-spike-arrest-policies), [SpikeArrest policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/spike-arrest-policy), [Quota policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/quota-policy), [VerifyAPIKey policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/verify-api-key-policy), [OAuthV2 policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/oauthv2-policy), [VerifyJWT policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/verify-jwt-policy), [VerifyIAM policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/verify-iam-policy).

```xml
<VerifyAPIKey name="verify-api-key">
    <APIKey ref="request.header.x-apikey" />
</VerifyAPIKey>

<SpikeArrest name="SA-Static-5ps">
  <Rate>5ps</Rate>
  <UseEffectiveCount>false</UseEffectiveCount>
</SpikeArrest>

<!-- Reads the limits that the API product sets, through VerifyAPIKey flow variables -->
<Quota name="CheckQuota">
  <Interval ref="verifyapikey.verify-api-key.apiproduct.developer.quota.interval">1</Interval>
  <TimeUnit ref="verifyapikey.verify-api-key.apiproduct.developer.quota.timeunit">hour</TimeUnit>
  <Allow count="200" countRef="verifyapikey.verify-api-key.apiproduct.developer.quota.limit"/>
</Quota>
```

Sources: [VerifyAPIKey policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/verify-api-key-policy), [SpikeArrest policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/spike-arrest-policy), [Quota policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/quota-policy).

Know these rate-limit rules:

- SpikeArrest keeps its counts in a best-effort cache, so counts can be lost. Do not use it when you need accurate counts. Use Quota ([Comparing rate-limiting policies](https://docs.cloud.google.com/apigee/docs/api-platform/develop/comparing-quota-and-spike-arrest-policies)).
- Use Quota for business contracts and SLAs with developers and partners. Use SpikeArrest for sudden traffic spikes ([SpikeArrest policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/spike-arrest-policy)).
- Both policies return `429 Too Many Requests` ([Comparing rate-limiting policies](https://docs.cloud.google.com/apigee/docs/api-platform/develop/comparing-quota-and-spike-arrest-policies)).
- By default, Apigee keeps a separate quota counter for each operation in an API product. Three proxies in one product do not share one quota. To count at the proxy or product level, set the product's `quotaCounterScope` attribute to `PROXY` or `PRODUCT` ([Quota policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/quota-policy)).
- For LLM traffic, LLMTokenQuota and PromptTokenLimit limit tokens instead of requests ([Comparing rate-limiting policies](https://docs.cloud.google.com/apigee/docs/api-platform/develop/comparing-quota-and-spike-arrest-policies)).
- Send the API key in a header, not in a query parameter. Query parameters can appear in browser history and network logs ([VerifyAPIKey policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/verify-api-key-policy)).

### API products and developer apps

An API product bundles operations. An operation names one API proxy, its resource paths, and optionally HTTP methods and a quota. You can create products for service tiers, for example Free, Basic, and Premium ([Introduction to API products](https://docs.cloud.google.com/apigee/docs/api-platform/publish/what-api-product)).

1. Create an API product with the operations and the quota.
2. A developer registers an app with at least one API product.
3. Apigee gives the app a consumer key (the API key).
4. The proxy checks the key with VerifyAPIKey, then applies the product quota with Quota.

Source: [Introduction to API products](https://docs.cloud.google.com/apigee/docs/api-platform/publish/what-api-product).

Apigee recommends one OpenAPI document, one API proxy, and one API product for each API ([Introduction to API products](https://docs.cloud.google.com/apigee/docs/api-platform/publish/what-api-product)). [Versioning, exposing, and securing APIs on Cloud Run](note:3.1-api-versioning-and-exposure) covers base paths, environments, and versions.

### Analytics

Apigee API Analytics answers questions such as: how traffic changes over time, which methods are most popular, who the top developers are, and where traffic comes from. It collects response time, target errors, API product, developer, and app ([Apigee API Analytics overview](https://docs.cloud.google.com/apigee/docs/api-platform/analytics/analytics-services-overview)). A Subscription organization includes analytics. A Pay-as-you-go organization must enable it as a paid add-on ([Apigee API Analytics overview](https://docs.cloud.google.com/apigee/docs/api-platform/analytics/analytics-services-overview)).

### Calling Cloud Run from Apigee

Add an `<Authentication>` element to the TargetEndpoint. Use `<GoogleIDToken>` for a Cloud Run service and `<GoogleAccessToken>` for a Google API. The service account must be in the project of the Apigee organization, and the deployer needs `iam.serviceAccounts.actAs` on it ([Using Google authentication](https://docs.cloud.google.com/apigee/docs/api-platform/security/google-auth/overview)).

## Cloud Endpoints

Cloud Endpoints uses the Extensible Service Proxy V2 (ESPv2), an Envoy-based proxy for OpenAPI and gRPC backends. The older ESP (based on NGINX) is maintained for existing users ([About Cloud Endpoints](https://docs.cloud.google.com/endpoints/docs/openapi/about-cloud-endpoints)). On GKE and Compute Engine, ESPv2 runs as a container in front of the app or as a sidecar. For serverless platforms, ESPv2 runs as a Cloud Run service that acts as a remote proxy ([Choosing an Endpoints option](https://docs.cloud.google.com/endpoints/docs/choose-endpoints-option)). Endpoints for gRPC does not work on App Engine or Cloud Run functions, because they do not support HTTP/2 ([Choosing an Endpoints option](https://docs.cloud.google.com/endpoints/docs/choose-endpoints-option)).

## AWS mapping

| AWS | Google Cloud | Difference that matters |
|---|---|---|
| Amazon API Gateway | API Gateway | An API config cannot change. A gateway is regional and serves one API config. Quotas (Beta) are per minute per consumer project |
| Amazon API Gateway | Apigee | Policies in the API proxy do key checks and rate limits. Keys belong to API products |
| Amazon API Gateway | Apigee integrated portals | Developers find APIs and register apps in a portal. API Gateway has no portal |

## Exam traps

- **API keys as the only protection for sensitive data.** Keys are less secure than tokens. Add JWT or OAuth authentication ([Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys)).
- **An API key from a project that did not enable the API.** API Gateway rejects it. The consumer project must enable the API's managed service ([Use API keys](https://docs.cloud.google.com/api-gateway/docs/authenticate-api-keys)).
- **SpikeArrest to enforce a contract limit per partner.** SpikeArrest counts are best-effort and cover all clients. Use Quota ([Comparing rate-limiting policies](https://docs.cloud.google.com/apigee/docs/api-platform/develop/comparing-quota-and-spike-arrest-policies)).
- **Quota before VerifyAPIKey.** The Quota policy needs VerifyAPIKey or VerifyAccessToken first to find the API product ([Quota policy](https://docs.cloud.google.com/apigee/docs/api-platform/reference/policies/quota-policy)).
- **An API product that "protects" a proxy with no credential policy.** Without VerifyAPIKey or VerifyAccessToken in the proxy, any caller gets through ([Introduction to API products](https://docs.cloud.google.com/apigee/docs/api-platform/publish/what-api-product)).
- **A public Cloud Run backend behind API Gateway.** Keep it private and give the gateway's service account the Cloud Run Invoker role ([Securing backend services](https://docs.cloud.google.com/api-gateway/docs/securing-backend-services)).
- **API Gateway in front of a Google API such as BigQuery.** Calls fail with `401` ([Securing backend services](https://docs.cloud.google.com/api-gateway/docs/securing-backend-services)).
- **A renamed quota metric while older gateways still run.** Those gateways return `500` for quota-enforced methods ([About quotas](https://docs.cloud.google.com/api-gateway/docs/quotas-overview)).
- **Exact per-minute quota enforcement.** Enforcement has a 30% margin of error ([About quotas (Endpoints)](https://docs.cloud.google.com/endpoints/docs/openapi/quotas-overview)).
